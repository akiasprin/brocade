# 模型、修订与发布

模型如何编译成每台机器的产物、改动如何发布，以及 Agent 如何收敛。

## 确定性编译

系统以一份完整的模型快照作为编译输入。编译过程不访问数据库、文件系统或外部服务；在版本与输入相同的条件下，输出产物按字节保持一致。核心数据流如下：

```text
ModelSnapshot → 中间表示（IR）→ 节点产物 → 期望状态 → Agent 收敛
```

基准产物作为测试夹具纳入版本控制。编译器发生修改时，测试会直接呈现产物差异，从而区分预期的语义变化与非预期回归。相同机制也用于发布前预览和历史修订的重新编译。

## 模型与拓扑

一个快照包含节点、用户、外部出口和应用。节点记录地址、密钥及运行参数；应用包含链、入口、转发步骤、规则与授权。每个中转监听由 `(chain, node)` 唯一拥有自己的端口、安全参数和有序规则表；其它规则可以引用这个身份并进入整棵规则子树，但不会复制端口或规则。链路路径不作为独立状态重复存储，而是由入口位置、逐跳转发规则和显式监听引用推导得到。由此，拓扑成为规则的确定性结果，避免两套表示之间产生一致性偏差。

## 草稿、修订与发布

会改变机器产物的编辑首先写入草稿，提交后形成不可变修订；名称、展示顺序、用户以及只影响未来对象或下一轮任务的设置则保存即提交。一次界面操作可以原子地修改多张关系表，而不必暴露中间状态。发布以特定修订为输入，并按影响范围划分为若干波次。设置页的「无人值守发布」默认开启，上一波满足既有成功判据后继续下一波；关闭后，包含破坏性操作的波次须由操作者确认。执行错误仍会暂停发布，切换设置不会恢复已经暂停的发布。

配置发布与授权发布相互独立。Xray 配置优先原进程热更新；无法热更新时，由「设置 → 发布 → Beta 功能 → Xray 进程交接」决定：默认关闭，采用重启并断开现有连接；开启后采用双进程交接，旧 TCP 最多保留 120 秒，到期终止剩余旧连接，UDP 会话需重建。Agent v40 起，缺少交接能力或运行态时，在候选校验与最终计量成功后降级为直接重启，并记录原因；旧 Agent 保持原来的拒绝行为。配置错误、授权检查点损坏或计量无法落盘不属于可忽略的能力不足。策略在创建发布单时冻结，切换设置不改变既有发布、重试、隔离补偿或正在进行的交接；旧工单未记录策略时保留原交接语义。授权发布只更新运行中的访问主体，因此仍具有不同的风险和执行代价。回滚不会修改既有修订，而是以历史修订为目标创建一次新的发布，以保留完整的因果记录。

Beta 开关仅系统管理员可修改，不产生模型修订或自动发布。新配置策略需要协议 37 或更新的 Agent；旧 Agent 继续运行与升级，不领取携带新策略的 Xray 配置工单，以免忽略策略后误用交接，但授权、历史工单和证书续期不因此阻塞。已有数据库部署前需审查 [Beta 设置兼容 SQL](../scripts/compat-xray-handoff-beta.sql) 及其他待部署 schema 变化，再核对构建所含迁移的 SHA-384。

发布预览的机器产物按“节点确认过的实际产物 → 本次计划”比较，旧内容通过已应用的摘要读取归档，不把历史修订用当前编译器重新编译后当作运行基线。因此，编译器升级或证书更新即使没有模型修订变化，也能显示真实文件差异。新纳管机器没有既有受管产物时以空集为基线，完整显示新增文件和内容；已有机器缺失旧内容时保留已知摘要，明确提示原文缺失，不伪装成空文件。文件原文仅系统管理员可读，其他有权限账号只获取状态和摘要。

产物差异面板固定展示，不提供折叠入口。执行计划的全量发布阶段默认合计展示 4 台机器，可通过“查看更多”展开其余目标；这只影响展示，不改变发布范围、依赖、波次或确认要求。

路由规则热更新采用整表原子切换：先完整构建、校验新配置，再一次替换运行快照；单次路由查询始终使用同一代规则，包括 DNS 二次匹配，校验失败时保留旧表。Agent 沿用上游 `AddRule(shouldAppend=false)`，提交包含规则与均衡器的完整 `routing` 配置；均衡器按上游语义重建，继续读取原有 Observatory 判活数据。普通 VLESS 出站仅调整目标地址或端口时，通过临时出站和两次完整路由配置切换完成 API 热更新，最终恢复原标签，保留进程与已有 TCP 连接。此能力要求配套 Agent 和声明 `atomic-routing-reload-v1` 的运行中 Xray；Agent 检查实际运行的可执行文件，旧内核按工单冻结策略继续交接或重启。默认出站、反向隧道、监听地址及其它未支持热更新的结构变化同样按冻结策略处理。公网中继沿用原来的地址族规则：存在 IPv6 直连时监听 `::`，仅 IPv4 直连时监听 `0.0.0.0`。

新建 TLS/REALITY 的默认客户端指纹为 `safari`，覆盖全局 REALITY 默认、新建外部出站及缺省指纹的导入；已保存或导入时显式指定的 Chrome、Firefox 等值不被覆盖。已有库可用 [默认指纹兼容 SQL](../scripts/compat-tls-fingerprint-default.sql) 调整列默认值，该脚本不修改已有配置行。

## 授权变更

授权变更与自动发布任务在同一事务中入库。提交时从前后两个已保存快照复用编译缓存，通过授权专用投影比较账户，不生成完整节点配置或计算发布波次；入口迁移、协议、Flow、撤权及节点退役仍参与比较，不可发布模型仍保守排入待收敛任务。只要有任务到期，后台就把全部待处理权限任务（包括退避中的旧任务）合并到最新修订；已有授权单未落地时继续等待，不提前判定“无需下发”，也不修改已经下发的名单。等待不计为失败重试；暂停的授权单需要先由操作者处理。用户页的每张授权卡独立等待写入后的快照修订确认，刷新失败时保持禁用并提供重试；拨测面板在当前用户修改授权后的 60 秒内每 3 秒重读 Serving 计划，之后停止自动刷新。授权卡上的已保存状态不代表节点已执行完成。

## 节点收敛

协议 v39 起，Console 对未完成目标重发同一份已冻结工单，不因首次 HTTP 响应丢失而等待 15 分钟；Agent 在下一轮常规轮询（通常 15 秒）恢复领取。重发保留原派发时间、授权名单、领取身份和计量代次，仍遵循波次、人工确认、暂停与生命周期边界。Agent 同一状态目录只允许一个收敛执行者；已有配置执行日志优先恢复，未确认收敛回执先从 spool 补发，确认前不再领取，因此响应重发不会重复启动交接。独立计量与运行上报继续执行。

先更新 Console，再更新 Agent；旧 Agent 连接新 Console 仍使用 15 分钟租约，新 Agent 连接旧 Console 也遵循旧服务端租约。无需数据库迁移、修改 Xray 或改变已冻结的平滑交接策略。HTTP 读取失败日志包含读取阶段、已知状态码、接收字节数、声明长度及耗时，不记录响应头内容、正文或凭据；这些信息用于区分未收到响应与正文中途停顿，并不延长网络超时或自动重放 POST。

agent 接收期望状态，而非待执行的命令序列。它将期望状态与本机实际状态比较，仅在存在偏差时执行操作，并将收敛结果回报控制面。最近一次期望状态会保存在节点本地，因此控制面暂时不可达时，节点仍能发现并修正本机漂移。

## 机器初始化与隔离

新纳管机器默认关闭 WireGuard。纳管前没有历史配置积压、上线前也没有新增业务配置冲突时，Console 在首次兼容的 Agent 轮询后自动创建仅针对这台机器的初始化配置单；安装页会显示等待、执行、完成或人工处理原因，关闭页面不影响后台推进。入门向导等待初始化完成后才提示创建线路，异常时保留安装步骤并展示处理原因。连续纳管的独立初始化任务逐台排队。初始化单保留修订、操作者与执行回执，但不推进全局业务配置或订阅的发布基线。显式开启 WireGuard、历史积压、安装期间配置变更等情况仍需人工查看发布计划；初始化失败通过原发布单重试，不因重复心跳、重装或重签 token 反复创建发布单。已有机器和旧登记记录不会补建自动初始化任务。

system-admin 可直接从机器详情的更多操作中隔离 active 机器，无需等待某次发布出现目标行。隔离会立即把机器从服务视图和可接入节点中摘除；若机器同时处于一个或多个发布中，相关目标会在同一事务中转为隔离待补偿，已经下发或失败的现场状态会标记为不确定并重新生成完整期望。Agent 在隔离期间仍领取并收敛最新债务；只有债务清零、轮询与运行上报新鲜且各运行组件均已确认后，机器详情才允许人工恢复服务。

## Agent 与 Xray 发布单

Agent 和 Xray 可执行文件不属于模型修订。发布页共用二进制发布单结构，冻结组件、当前 Console 内嵌的双架构摘要、明确的机器名单与更新前摘要。建议先为灰度机器创建一单，观察完成后再为其余机器创建新单；不会因部署 Console 或后来加入机器而自动更新机队。每次重试保存独立证据，历史按需分页读取，只保存元数据而不保存历史二进制，也没有历史单内回滚入口。后续上传覆盖会接入当前产物目录，本版尚不提供上传入口；目前人工回退仍需部署携带所需字节的 Console，再创建新单。

交接结束且配置收敛日志已清除后，Agent 保留所有存活代和最近两份退役代，逐轮最多回收四份更旧的可执行文件、manifest 与对应日志（含轮转文件）；交接、重启恢复或配置收敛期间禁止回收，避免连续发布积累二进制占满节点磁盘。

交接期间若候选退出或控制通道失联，Agent 使用持久检查点在本地恢复，不等待 Console：候选仍健康时仅退役失联旧代；候选不可用时重启已批准的配置和二进制，恢复完整授权、转发和共享计量命名空间。控制 RPC 的连接、发送和接收均设超时，错误包含操作、阶段和进程身份。交接期间后台 gRPC 观察共用短预算，执行后的观察共用短预算，计量代次提交后即释放互斥锁；已退出的候选不会继续消耗 30 秒启动等待。重启恢复会断开现有连接，失败回执与恢复成功回执分别保留。

Xray 二进制升级始终默认「直接重启」。Beta 关闭时不能新建交接发布，后端同样拒绝绕过界面的交接请求；开启后才可手动选择「双跑交接 Beta」及排空期限。关闭 Beta 不撤销已有批准，进行中的交接和原发布单重试仍沿用批准时的策略。

Agent 替换前持久保存回执，重启后恢复轮询与运行上报且摘要匹配才确认成功；旧 Agent 首次升级缺少执行回执时明确标为“观测确认”。Xray 仍独立执行大小、摘要、版本和当前配置预检，在收敛安全边界替换，验证监听和运行摘要；失败时本地恢复原字节。仅正在运行受管 Xray 且摘要一致的节点可加入 Xray 单。交接发布对旧 Agent 还要求真实运行态 ready；v40 起可纳入具备重启降级能力的节点。任一执行失败会暂停未领取目标；领取后失联的目标在租约到期后可人工重试。停止不是回滚，迟到结果仍留存；节点离开 active 生命周期会停止相关发布，永久删除节点也不删除历史证据。安装器将确定的 Xray 路径写入 `BROCADE_XRAY_BIN`，兼容旧安装时优先识别 Agent 同目录的 `xray`。具体门槛见[发布手册](../.agents/runbooks/release-and-rollback.md)。
