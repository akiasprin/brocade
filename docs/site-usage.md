# 出流量统计

按固定站点分类、未分类域名和嗅探失败目标统计用户流量。新安装时三项均默认开启，只用于观测，不参与计费。既有库保存的开关不会自动覆盖；[默认值兼容 SQL](../scripts/compat-traffic-observation-defaults.sql) 只调整列默认值，保留已有关闭选择和容量设置。缺少 Console 策略头时仍关闭采集，不因升级 Agent 意外开启。

## 站点流量

「全局设置 → 出流量统计」统一控制机队，新安装默认开启，仅系统管理员可修改。策略随 Agent 的期望状态轮询同步，Xray 每秒检查私有控制文件，无需配置发布或重启；开启后为新连接分类，关闭后停止已有连接的站点计数，计费用量与历史站点数据不受影响。关闭／重新开启会更新采集边界，首次上报重新建立基线。缺少新版 Console 的策略头时 Agent 默认关闭；升级旧 Agent/Xray 后才具备采集能力。

MTProxy 不经过通用 Dispatcher，依据已认证的 Telegram 专用协议直接归入 Telegram，不依赖嗅探。

用户详情的「站点流量」统计用户 × 固定站点集合的上下行字节与占比，已登录操作者可读所属租户范围；普通用户与访客不能获取。集合版本与域名后缀定义共用 [catalog.json](../components/xray-core/common/siteusage/catalog.json)，只上报固定分类标识，不保存逐条域名、URL 或访问日志。优先使用嗅探取得的域名，其次使用代理请求自带的域名；是否允许覆盖路由目标不影响分类。未命中集合归「其他站点」，启用嗅探但未取得域名归「嗅探失败」，未启用嗅探且无域名归「未识别」。无法识别的加密流量、纯 IP 协议及共享 CDN 无法凭此准确还原网站，分类只用于观测，不作为计费或访问审计依据。

报表嵌在当前用户的详情内，不是机队站点汇总；全局设置将「站点分类」「未分类域名」「嗅探失败目标」整合到一个「出流量统计」面板，侧栏只保留一个入口；三类策略独立，站点分类开关即时保存，域名和目标参数分别保存。「站点流量」合并时间分布、分类排行、其他站点域名明细和嗅探失败目标明细。正文合计行提供当天／当周／当月筛选，按 UTC+8 自然日、周一起的自然周、自然月查询。当天和当周按小时、当月按天绘制堆叠柱，前五类站点单独着色，其余合并；未来时段留空，未观测区域与当前时刻有标记。窄屏上下排列图表和排行，切换周期保持卡片与展开状态。站点名称前显示本地内嵌、随主题适配的品牌图标，兜底分类复用通用界面图标，不请求第三方 favicon；素材来源见 [图标说明](../frontend/src/ui/site-brand-icons.LICENSE.md)。本地视觉夹具标明示例用户，不能当作真实报表。

端口转发在机器「流出统计」和用户「站点流量」中作为独立类型置顶，计入上下行、合计、占比和时间图，不按目标猜测站点分类。用户视图合并该用户各台机器及规则的历史转发账本，规则撤销、删除或移机不清除已记流量。当天、当周的转发总量来自日账本，小时图仅使用尚存的窗口明细；当月按日汇总。小时明细清理后保留总量并提示无法分配到图中的部分。站点采集开关、上报覆盖和观测起点仅描述代理入口，关闭站点采集仍展示转发账本。

三条用户观测接口 `site-usage`、`other-domains`、`sniffing-failed-targets` 使用 `period=day|week|month`（默认 `day`，非法值返回 400）；旧 `hours` 参数不再控制范围。站点响应包含周期结束时间、桶宽和各类上下行时间序列，分类合计与时间序列取自同一数据库快照。前端与 Console 需作为同一产物更新；此次查询与展示调整不改变 Agent/Xray 上报协议，也不需要数据库迁移。

## 采集与上报

Agent v31 与带 `user-site-usage-v1` 能力的受管 Xray 使用独立、有界的 `xray-site-accounting.bin`（约 8 MiB）保存累计站点计数；中继身份、探测身份与独立端口转发不参与站点分类采集，报表中的端口转发另由转发账本合并。该维度随原用量报告离线补报，在同一幂等事务内按冻结授权归属落库，不加入计费总量。首次上报或 journal 更换建立基线，不把未知历史归入当前时段；按 UTC 小时聚合，跨小时区间按时间比例分配，保留 31 天，查询当天／当周／当月内截至当前的桶。未支持、上报过期、覆盖不足和计数受限会明确提示，范围切换保留现有面板。

分类索引全进程复用，不缓存逐条域名。相同用户与站点复用一对计数器；首次注册交给单个后台工作线程，队列最多 256 项、缓存最多 8192 对，并限制键长度。转发路径不等待站点注册的磁盘同步，持续传输只做原子累加，不复制载荷、不逐包投递异步任务；统计快照遇到注册繁忙会跳过本轮站点标签刷新，不等待它。队列满、容量耗尽或注册失败只影响观测并标记受限，失败后由后续连接触发至少间隔 5 秒的重试，不阻断计费和转发。

尚未注册完成的站点字节暂存内存：进程突然退出可能丢失这部分观测，持久化的 `site>>>pending` 标记使新版 Agent 将其报告为不完整，而不是伪装为完整用量；注册完成后直接累加到 mmap。正常退出最多等待 2 秒排空，超时明确标记受限。必需的计费计数不经过这个异步队列。Agent 与 Xray 应使用配套版本，以识别新增的待注册标记。优化对照方法和边界见 [性能测试说明](../scripts/tests/site-usage/README.md)。

## 升级

现有数据库先核对生产 schema 与 migration checksum，再评估执行 [兼容 SQL](../scripts/compat-user-site-usage.sql)；以数据库管理员执行时必须传入 `-v app_role=brocade`，保证新增对象归应用角色所有。脚本只覆盖三张站点观测表与全局开关字段，不包含工作区其他 schema 改动。推荐先 Console，再按发布单更新 Agent 与 Xray；只部署 Console 不会自动升级机队，也不会补出升级前的网站数据。新字段可选，旧计量报告和旧回执仍可重放。本地视觉夹具见 `frontend/tests/fixtures/site-usage-preview.html`，通过 Vite 的 `/@fs/` 路径访问，明确标记为示例数据。

## 其他站点 Top N（用户 × 域名）

固定站点分类采用「固定版本 geosite 精选集合 + 手工补全/精细覆盖」：目前覆盖 44 个平台/公司，另有其他站点、嗅探失败与未识别三种兜底。包括 X/Twitter、Facebook、Instagram，以及字节跳动、百度、腾讯、阿里巴巴等国内公司；具体产品优先于母公司，共享 Meta CDN 单列，不把整个共享 CDN 根域归给某网站。构建时生成、全进程复用，运行时不联网拉取、不做 DNS 反查。规则来源、匹配语义、优先级与更新方式见 [分类资源说明](../components/xray-core/common/siteusage/README.md)。分类扩充需先升级 Console 再发布 Xray；既有连接与历史数据不回溯重分类。

「全局设置 → 未分类域名」是独立、新安装默认开启的策略，不依赖固定站点开关。仅系统管理员可修改；用户详情中的结果只允许系统管理员与作用域内租户管理员读取，普通用户（含本人）、访客和其他操作角色均不可读，接口禁止缓存。

默认展示每用户 Top 128；每个节点的当前采集窗口同时维护每用户最多 1,024 个未分类域名候选。节点总容量默认 4,096，同时约束当前候选索引与入口身份 × 域名计数对，不按用户预分配；多用户或多入口共享该预算。新版 Agent/Xray 在容量满时淘汰已可靠保存、最久没有新增流量的条目，给新域名腾位；同一用户的多个入口共同占用候选预算。容量限制同时驻留条目，不再禁止用户在一天内访问超过 1,024 个网站。上述数值与上报间隔（默认 30 秒）可配置：Top N 为 1–512，每用户容量不小于 Top N、节点容量不小于每用户容量，两种容量均不超过 4,096；间隔为 15–300 秒。容量调整会重建采集窗口，展示数量／间隔调整不清空采集；关闭停止数据面计数，重新开启建立新窗口，只有开启时新建的连接具备域名观测包装。

只记录已获认证的用户入口、未命中固定预设分类的规范化 ASCII/Punycode DNS 主机名及上下行字节，不保存 URL、路径、内容、IP 或逐次访问记录，不做 DNS／外部 favicon 请求。每节点最多保存当前与上一 UTC 小时的内存计数，热路径仅原子累加，冷准入使用 TryLock；快照格式化／排序不持有准入锁。单独的 Agent 后台线程通过专用查询采样并批量上报；新版计数段通过 `otherdomain>>>v2` 读取，保留 `otherdomain>>>` 的旧版只读接口。转发路径不进行磁盘或网络操作，计费线程不等待明细采样、持久化或上报。

Console 按冻结用量代际确定用户归属，累计头幂等计算增量，跨节点合并后排序；小时明细默认保留 24 小时，可在「全局设置 → 数据保留 → 其他域名小时明细」按小时或天调整。上报时清理、定时清理与查询共用这项设置，查询起点向上取整到尚在保留期内的小时桶。明细跟随当天／当周／当月筛选，查询起点取自然周期起点与保留起点的较晚者；例如保留 7 天时，周五查当周可以看到周一至今，界面不新增「近 7 天」筛选。调长保留期不会恢复已清理或采集前的数据，周／月不会补出已过期的明细。前端用随构建内嵌的公共后缀表（含私有后缀）将主机名按可注册域归并，避免将 `github.io` 等平台的不同租户合成一个站点；不联网解析域名。每节默认展示六项，可展开全部、折叠预览或从排行跳转；说明行写明保留范围、采集起点、覆盖量和限制。固定分类无数据或读取失败时，独立明细仍可查看。仅对实际采集的域名排名，**不是无界、全量域名排名保证**。容量满时仅允许淘汰已经由 Agent 可靠保存、之后未新增流量的冷条目；尚未保存的条目保留，无法腾位时明确标为受限。缺报、采集前时段、受限和重建窗口会明确提示，不将辅助观测冒充完整计费。

需要协议 v34 Agent 与声明 `other-domain-usage-v1` 的 Xray；推荐 Console → Agent → Xray，均就绪后再开启。旧 Agent 忽略策略头，新 Agent 遇旧 Console 默认关闭、遇旧 Xray 显示无可用观测，不影响主计费。新 Agent 的常规启动及热交接均传递私有 `other-domain-policy.json` 路径。已有库先审查 [域名观测兼容 SQL](../scripts/compat-other-domain-usage.sql) 和所有待部署 schema 差异，再使用构建所含 `0001_init.sql` 的 SHA-384 更新 checksum；该脚本不包含其他功能的 schema 变更。此功能与固定站点历史互不回填。

## 嗅探失败目标 Top N（用户 × IP／端口／协议）

「全局设置 → 嗅探失败目标」提供独立、新安装默认开启的全局策略。默认每用户展示 Top 128，每节点持续维护每用户 1,024 个目标，节点总容量 4,096、每 30 秒异步上报；可配置范围与容量关系沿用其他域名维度，两个维度预算互不挤占。目标小时明细默认保留 24 小时，可在「全局设置 → 数据保留 → 识别失败目标小时明细」独立调整。只有系统管理员能修改；系统管理员及作用域内租户管理员可查看用户详情，普通用户、访客及其他操作角色均不可读，接口禁止缓存。

仅对新建、已认证、启用嗅探却未识别出域名的连接，统计原始 TCP/UDP 目标 IP 与端口的上下行字节。IPv4/IPv6 均支持并规范化，TCP/UDP、不同端口分别统计；原始地址可能是 FakeIP，不等于最终出口地址或代理下一跳。不保存载荷、URL、逐连接日志，也不以 IP 猜网站。未启用嗅探、域名目标和已识别域名不计入。明细合并在站点流量卡片底部，按协议、IP 与端口列出；跟随自然周期筛选，并遵循对应的数据保留设置，切换范围不移除面板。

数据面复用有界冷准入及原子计数器，关闭不创建目标索引；专用 `sniffingfailed>>>` / `sniffingfailed>>>v2` 查询不会混入计费或其他域名查询。Agent 独立采样及上报，计费不等待可选观测；冷条目淘汰、独立离线 spool 与未采样数据的丢失边界与域名维度相同，并非全量 Top N 保证。需要协议 v35 Agent 和 `sniffing-failed-targets-v1` Xray，推荐 Console → Agent → Xray 后再启用；缺少策略头默认关闭，旧 Xray 无观测而不影响计费。正常启动及热交接均传递私有 `sniffing-failed-policy.json` 路径。

现有数据库先核对生产 schema、checksum 及所有工作区差异，再评估 [目标观测兼容 SQL](../scripts/compat-sniffing-failed-usage.sql)，通过 `-v app_role=brocade` 指定对象属主；脚本只包含本功能，既不启用采集，也不修改 migration checksum。它不能替代对其他待部署 schema 的审查。


## 容量轮换与离线补报

Agent 协议 v38 与声明 `detail-checkpoints-v2` 的 Xray 配套启用计数段和可靠淘汰。先更新 Console，再更新 Agent，最后更新 Xray；新版 Agent 遇旧 Xray 保持 v1 上报，新 Xray 的普通查询也保留 v1 形状。旧版查询不会触发可靠淘汰。相同 Xray epoch 从 v1 切换到 v2 时，Console 一次性转移已记录的基线，避免重复累计；进入 v2 后不再接受该 epoch 的 v1 上报，回退旧 Agent 需同时重启／回退 Xray 建立新 epoch。Store 使用现有计数头命名空间保存「Xray epoch + 计数段 ID」，无需修改业务表或迁移既有历史。

每次条目登记都分配新的计数段 ID。同一网站被淘汰后重新进入，也不会与上次的累计基线混淆。Agent 只把发生变化的累计值追加到对应的 `other-domain.spool.jsonl` 或 `sniffing-failed.spool.jsonl`；原子写入及 fsync 完成后，才向 Xray 确认这些值可以用于安全淘汰。确认丢失时可重试，不再重复入队相同累计值。同一小时、同一采集 epoch 和授权代际的待发送尾部报告可合并，保留每个计数段的最新累计值，避免持续流量反复占用离线空间。上报线程按 FIFO 发送，成功后移除；响应丢失或 Agent 重启重放，由 Console 计数头计算差值，不重复累计。无变化时只发送少量覆盖状态心跳，不重复上传计数条目。

两类 spool 各自最多 720 条报告、32 MiB，先达到任一上限就停止接纳新检查点，保留已有数据并暂不确认对应淘汰。它们不占计费 spool、不阻塞计费或转发。Console 接受仍在最近 24 个小时桶内的旧计数段，去重基线至少保留 24 小时，旧的两小时保留配置自动按安全下限执行。补报接受窗口与历史明细保留期独立；调长明细保留期不会延长离线补报期限，超过补报窗口的报告会被确认后移除，不会永远堵住本地队列。本次保留设置贯通仅需更新 Console 及其内嵌前端，无需修改 Agent／Xray 或数据库结构。

Console 的历史存储保护独立于驻留容量：每节点、每维度、每小时最多 65,536 个历史目标及计数段，异常高基数超过保护上限时标记受限。Xray 仍只保留当前和上一小时的内存快照；已经采样并落入 spool 的数据可跨进程重启补报，但 Xray 退出或重建窗口前尚未采样的数据、Agent 长时间停止后消失的旧内存桶、冷准入竞争及缓冲耗尽期间无法接纳的新条目仍可能缺失；首次登记失败的长连接会在后续传输中按至少五秒间隔重试，避免整条连接永久缺席。回退 Console/Agent 前先排空 v2 明细 spool，旧 Console 不接受 v2 报告。
