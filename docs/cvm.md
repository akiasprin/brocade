# CVM（CubeVM）

裸机可作为没有容器隔离的整机实例纳管，启用方式、支持能力与解除流程见[裸机实例](baremetal.md)。

CVM 将系统、计算容量、系统盘和网络连接放在一个实例中管理。创建时选择承载宿主，访问入口与出网可由其他机器提供。“编排”包含“线路”“容器”两个子页（见[控制台导航](concepts.md#控制台导航)）。“容器”默认打开按宿主分组的清单，按权限提供“宿主”和“网络”页签；后者管理全局访问入口地址和出口网络。单个实例的入口、网卡和路由在其实例详情的“网络”页签配置。同一宿主可同时承载 Cube 容器与一个无隔离物理宿主实例，Agent 按实例目标动态分派。用户端口转发仍在用户详情中单独配置。

机器运行状态的“扩展应用”只显示一个 **CUBE** 扩展，与 OPENVPN 并列；宿主系统管理属于同一组合执行栈，不另列标签。CUBE 是可选扩展；只有已确认过 Cube 运行栈或仍有保留实例的机器，才判定其运行健康。未纳管的普通机器显示灰色“未启用”，缺少可选配置不会显示配置不一致或异常；已纳管机器则按实际上报区分已启用、能力异常、报告过期和未上报。Cube 或宿主系统任一部分异常都汇总到这个标签，具体原因保留在提示中。此处只展示运行栈状态，不以安装选项或 Agent 协议版本推断已经安装。

节点已上报运行模式时，标签显示 **CUBE[KVM]** 或 **CUBE[PVM]**；其他 Cube 后端保留实际上报的名称。未启用或未明确上报模式时只显示 **CUBE**，不根据宿主内核或实例期望猜测模式。

## 当前实现范围

| 能力           | 当前行为                                                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| WebShell       | CubeShim 管理持久 Guest PTY，支持重连、会话切换、窗口调整和粘贴；在“宿主”表的 WebShell 列按机器开关访问                                      |
| 实例管理       | 创建分配、不可变规格、开机、关机、重启、重装、关机改配、删除和失败重试                                                                       |
| 系统与容量     | 镜像与资源独立；CPU、内存和系统盘容量分别选择，磁盘按精确字节分配                                                                            |
| 网卡挂载       | 创建时生成管理主网卡，可预选已授权的业务网卡并在实例网络页核对后保存；热挂卸和槽位由宿主实测能力控制                                         |
| Cube 运行栈    | Agent 内置 Rust 执行库对接 Cubelet；一张原生主网卡加最多两张真实副网卡，支持运行中热挂卸；XFS/reflink 与 ext4/plain 均支持受保护的持久系统盘 |
| 原盘开机／关机 | 安装 protected-root-v1 扩展后，关机保留原盘和地址分配，开机按原物理对象恢复                                                                  |
| 访问入口       | 任意机器的 IPv4 地址按 TCP、UDP、ICMP 和其他 IP 协议投递到容器主网卡，不占网卡槽位；可在同一用户的容器间改派                                 |
| 出口网络       | 只承担出网的 IP 层网卡，支持 Xray／WireGuard、共享 NAT、独立路由地址和一对一 NAT，双栈                                                       |
| 路由表         | 匹配 IP／网段（L3），或协议加目的端口（L4）；网段越具体越优先，同网段端口规则优先，再按每地址族网卡优先级选择；故障不换卡                    |

Cube 的原生主网卡由 Cube 管理，保留管理联络，并默认通过宿主机 NAT 访问公网，优先级最低。业务网卡的 ID、MAC、地址和资源归属由 Store 统一分配；Cubelet 接收分配结果，创建真实 TAP 和 virtio-net 设备并核查 Guest 状态。当前 Cube 实测上限为三张，包含管理主网卡；同一网络可反复挂载，每次得到独立设备与分配，不按来源数量限制槽位。通用模型最多表达 16 张，具体机器仍按实际上报容量准入。

L3 整 IP 转发可以使用入口机器自身的 IPv4 地址，IP 继续保留在入口机器，不会配置到目标网卡。
新入站流量（包括 SSH 等宿主服务端口）转发到指定实例；入口机器主动连接的回包以及实际传输通道端口保留。
共享 NAT 出口可以继续使用该地址，其出站连接的回包不进入 L3 转发。机器的组网地址仍不可发布为整 IP 入口。
入口机器必须上报 `entry_host_l3` 能力；裸机目标接收跨机器 L3／UDP 转发也须具备此能力，以保证 UDP 回包使用主网卡地址。缺少该实际执行能力时拒绝创建入口。
跨机器可选择 Xray，或 WireGuard 的 UDP 直连／Phantun FakeTCP 传输。Xray 复用原始 IP 包封装和认证；Phantun 在 WireGuard 外层承载 UDP，L3／L4 的转发语义不变。通道实际使用的 TCP／UDP 端口不参与整 IP 转发；同机目标不建立通道，可关闭“允许转发到其他机器”。Agent 分别上报 `entry_xray`、`entry_phantun`，两端均支持后才允许建立相应通道；Phantun 能力要求已安装客户端与服务端运行包。缺失对应能力时拒绝建立通道。已有机器对通道固定其承载与凭据，更换前须撤销相关跨机器入口并等待两端清理；不能通过修改发布静默切换。

网卡不再提供入站：访问入口取代了网卡入站方向、入站来源与共享地址端口映射。首发数据库与扩展切换见[产品变体与数据库](#产品变体与数据库)。数据库历史严格校验，不能修改 SQLx 回执绕过检查。

## 网络配置日志

系统管理员可在“宿主”表的对应行打开“宿主网络配置日志”，也可在实例详情的“网络”页通过“网卡”栏的“配置日志”或单条访问入口的日志按钮查看。跨机器入口和出口可切换查看两端机器，按 Agent 执行、Xray 进程或 Phantun 进程筛选，并复制当前显示的记录。

入口与出口的 WireGuard 命令共用安全错误分类，保留失败环节及权限拒绝、超时、端口占用、路径或设备缺失、密钥格式错误等原因。工具可能在失败时回显密钥，因此回报和日志不直接透传其原始输出；未知错误也不会回显命令参数或密钥。

Ubuntu 26.04 等系统会对 `/usr/bin/wg` 强制执行 AppArmor 规则。入口配置和出口私钥经匿名标准输入管道交给 `wg`，不要求它直接读取 Agent 的状态目录，也不修改或关闭系统安全规则。状态目录中的配置副本仍以私有权限保存，支持自定义状态路径；私钥不进入命令参数、环境变量或日志。其他权限或安全策略拒绝仍按实际失败回报。

Agent 采集网络配置版本、应用结果、主网卡／路由确认、出口网卡状态、通道连接、失败与重试，以及受管 Xray／Phantun 子进程的标准输出和错误。入口握手等待超过 120 秒后显示明确失败原因并继续重试；恢复后记录新的连接确认。当前版本的整体应用错误在“尚未应用”时同样显示，旧版本回报不覆盖新版本的状态。

每台机器保留最近 256 条网络记录及最多 1024 个资源状态；超长行省略，凭据隐藏，历史按容量轮换。记录位于 Agent 状态目录的 `cvm-network-diagnostics.json`，权限为 0600，并随现有入口／网卡回报上传。页面显示采集时间、配置期望／回报版本、等待时长、轮换数量和过期状态；没有回报时明确提示。日志采集故障不停止转发进程。启用采集之前被丢弃的进程输出无法补回。

机器日志可能包含共享承载的其他网络记录，因此 `GET /cvm/network-logs?nodes=<机器 ID 列表>` 仅限系统管理员，一次最多读取 8 台机器；普通用户及只读账号不能访问。日志不包含期望状态里的通道凭据，也不采集用户包内容。

## 页面与读数

容器清单在桌面使用表格，在手机使用按宿主分组的卡片。可以按状态、宿主及可见的使用者筛选，也可搜索名称、地址或端口。每行显示实例规格、读数、访问入口、出口和本月计量，并提供当前权限与宿主能力允许的快捷操作。支持选中多项批量开机、关机或重启；管理员还可批量删除符合条件的容器。确认时列出涉及的容器，逐项显示结果，不把跳过或失败视为成功。

实例详情是独立页面，分为“概览”“网络”“监控与诊断”“产物”，按权限展示。标题图标角上的状态灯区分正常运行和停止；失败、待核查等状态另有提示。概览显示 CPU、内存、系统盘、网卡速率、运行时长和本月流量，可展开近一小时历史；下方提供连接与凭证、网络概况、最近事件、规格、使用授权、发布与存储。“网络”页将访问入口、网卡、“路由与命中测试”直接展开：就地添加或撤销入口、挂卸网卡及编辑路由；业务网卡行另提供“更换连接方式”和“应用新规格”。“监控与诊断”提供时间范围、网卡筛选、连接健康和详细诊断。手机使用同一组操作；返回清单使用顶栏“编排”的返回入口。

“宿主”页可搜索机器，列出能力状态、分配量／宿主容量、工作负载数、运行模式及 WebShell 策略。展开行可查看 Cube 容器与物理宿主实例，并在权限及能力允许时执行创建、动态纳管或移除宿主。物理宿主实例没有容器隔离；它的存在不关闭同机 Cube 创建能力。容器创建后不能更换承载宿主。

容器清单通过 `GET /cvm/readings` 批量读取当前可见实例的最近观测。作用域与 `/cvm` 一致，最多 512 个实例，每实例最多 60 个近一小时的分钟历史点；不逐卡请求详情监控。最新采样与运行健康均在 120 秒以内才展示实时读数。过期、停机、缺失或请求失败显示 `—`；历史采样间断时曲线断开，不能将缺失解释为零。

“当前”表示全部已挂载网卡的 Guest 视角收发速率合计；“本月”表示当前业务网卡按 UTC 自然月记录的消费侧上传与下载计量，管理主网卡 NAT 不在该月度计量中。尚未收到完整计量时显示 `—`，有计量缺口时明确标记；清单可查看计量口径及时间。混合有限额与不限额网卡时不显示汇总额度上限。

清单的“创建容器”打开独立创建页；实例菜单的“复制为新容器”也会进入同一页。复制只预填同租户源实例的镜像、规格及仍可用的业务网卡选项，不复制系统盘数据、登录凭证、使用授权、入口或路由。

## 镜像与规格

系统镜像描述运行什么系统，资源数值描述分配多少容量。系统盘容量属于实例资源；镜像与系统模板不设置硬盘大小，也不按内存划分。Cube 的内存快照属于实例恢复点，不能作为绑定某个硬件规格的通用系统镜像。Rust 执行库拒绝包含容量或内存快照参数的系统启动清单。

## 使用

管理员先配置宿主执行服务，再创建容器并配置规格和网络。系统管理员和作用域内的租户管理员可创建、改配、重装、删除、维护实例网络并管理使用授权；创建还须拥有目标宿主的管理权限。添加／移除宿主、纳管裸机、管理全局入口地址与出口网络及查看机器网络配置日志仅限系统管理员。普通用户只看获授权的容器，可在能力与状态允许时开机、关机、重启、打开终端、复制 SSH 命令和查看登录密码，不能管理容器或网络配置。其他管理角色不能改动 CVM 实例；统一发布另有权限检查。

容器不设置用户实例数、CPU、内存、系统盘、网卡总额，也不要求先给用户授权宿主。一个容器最多授权给一个使用用户，可以保持未授权。收回授权立即撤销该用户的控制台读取、操作和 WebShell 访问，同时保存关机、网络撤下和密码更新变更，待统一发布后执行；不会删除系统盘。更换使用者前必须先发布收回变更，并等待关机和网络清理确认。使用授权变更不能通过“撤回待发布配置”恢复，需要显式重新授权。授权记录保存操作者、前后使用者和执行代。

只读账号及启用访客模式后的匿名访问者可查看作用域内的容器清单、脱敏详情及监控与诊断；不显示运行时和系统盘标识、接入地址、网卡地址及敏感网络详情，不提供原始产物、登录密码、终端、生命周期或发布操作。关闭访客模式后，后续匿名请求立即被拒绝。手机主导航包含“编排”（其中的“容器”子页）和“用量”。

独立创建页依次填写“名称与归属、宿主、系统、规格、网络与访问”。可选择同租户使用者，也可保持未授权；选择宿主、系统镜像与版本，再分别填写 CPU、内存和系统盘容量。右侧显示创建后的分配量／宿主容量，不代表物理用量；范围、步长和设备容量由服务端校验。无需填写 SSH 公钥或密码，系统自动生成独立登录密码。

在“网络与访问”可预选已授权的入口和业务网卡，也可只创建容器。点击“保存创建变更”先将实例及管理主网卡保存为待发布；若有预选项，进入新实例的“网络”页，并把这些选项带入本次会话的未保存网络草稿，不分配入口端口或业务网卡地址。可继续编辑，核对后点击“保存网络变更”；若不需要预选项，可丢弃当前草稿，已保存的创建仍保留。要让首次发布包含这些网络改动，请先保存网络草稿，再从统一发布计划发布。

## 出口网络、挂载与路由

网络目录的 `provider_names` 只包含当前可见发布和本人／作用域内实例仍占用的网卡所引用的机器名称。出口列表与实例详情共用这些名称；普通用户不会因此获得管理员的提供机器能力清单。撤销发布授权后，仍占用的本人网卡可以继续识别提供机器，直到资源清理；其他用户的占用不会扩大名称可见范围。

以 A 表示容器、H 表示运行 A 的机器、B 表示提供网络的机器。B 创建网络 P，A 挂载后得到自己的网卡 N，再由 A 的路由表 R 选择哪些目标走 N。B 与 H 可以是同一台机器；B 只需具备网络执行能力，不要求具备 KVM 计算容量。

系统管理员在“容器 → 网络”分别查看“访问入口地址”和“出口网络”两张表。点击“出口网络”表的名称或“修改规格”，进入独立编辑页；也可添加新出口网络。选择提供机器 B，填写地址池、地址族、可达的 IP／网段、初始路由、可选 DNS 建议和限速／流量额度，并授权使用者。编辑页同时列出派生网卡和版本状态，可核查授权变更的影响和删除依赖。地址池可以复用，同一资源域统一检查地址占用；不同隔离资源域可以使用重叠私网，但同一容器内地址不能重复。三种地址模式分别为：

- **共享 NAT**：多个 N 共享出口地址；没有固定共享地址时，由 B 按实际路由选择 NAT 地址。
- **独立路由地址**：地址直接配置在 Guest；B 必须实际具备对应上游路由或邻居代理条件。
- **独立一对一 NAT**：Guest 地址和独立对外地址分别展示，不把 NAT 公网地址当作 Guest 已配置地址。

N 只承担出网：容器主动建立的连接及其回包经 N 和 B 往返，新的入站连接一律不经 N；需要入站时为容器添加[访问入口](#访问入口)。路由表不能扩大 P 的授权，不提供 NAT64 或透明二层延伸。

出入对称：容器在 B 上同时拥有整 IP 入口时，经 B 的 NAT 出口网卡出网的 IPv4 源地址改用该入口地址；路由独立地址模式下 Guest 本身就使用公网地址，不受影响。

容器在详情“网络”页签中挂载已授权的 P，选择双方实际支持的 Xray／WireGuard 承载交集。创建独立网卡不会创建另一份计算实例。可手动更换承载，N 的 ID、MAC、地址分配和 R 引用保留；切换可能中断连接。新承载未启用时失败仍使用原承载，启用后失败尝试恢复原承载；原承载也不可用时保持不可达。

Xray 当前使用独立的 VLESS Reverse／TLS 进程封装和认证原始 IP 包，WireGuard 使用原生内核 IP-over-UDP。两者使用每个 N 的隔离上下文、独立凭据和有界缓冲，不改主 Xray 配置或代理授权。默认由 H 连接 B；发布规格也可选择由 B 连接 H，监听方必须提供实际可达的端点和端口。两族业务可共用一个外层地址族。

R 独立保存目标 IP／网段、可选的协议与目的端口段（L4，例如 `tcp/22`、`udp/1000-2000`）、各地址族出口优先级和 DNS。全路由分别用 `0.0.0.0/0`、`::/0` 表达。先选最长前缀；同一前缀上带协议端口的规则优先于不带的规则；再按较小的网卡优先级选择，最后选更窄的端口段。相同前缀和优先级、端口段重叠却指向不同 N 时拒绝保存。L4 规则需要宿主 Agent 上报 `route_service`、Cubelet 上报 `route_services`：Guest 内按协议端口写策略路由，宿主按同一顺序放行或丢弃，选给另一张网卡的流量不会从这张网卡出网。未匹配业务路由时，流量使用优先级最低的主网卡，经宿主机 NAT 出网；选中的 N 故障时保持不可达，不回落到其他网卡或主网卡。宿主同时约束实际 IP 流量，Guest 绑定源地址不能绕开 R。

在实例详情的“网络”页签中，可直接查看路由和默认出口。管理员可在表中编辑路由与 DNS，分别拖动 IPv4／IPv6 出口或用方向键调序，也可直接填写优先级；数值越小越优先。改动先进入顶部网络草稿，与入口和网卡改动一并检查并保存；保存后仍需发布。

命中测试仅对作用域内管理员开放。输入 IPv4／IPv6 地址及协议；TCP／UDP 还须输入目的端口。测试按期望路由选择出口并高亮命中的规则，能使用未保存的网络草稿；它不解析域名、不发包，不表示已发布状态或实际可达性，也不模拟主网卡管理联络等运行时例外。无显式规则时显示默认路径。Cube 容器若命中线路的整段规则但协议不是 TCP／UDP，流量被阻断而不是回落；裸机本机选路不会为此类流量选择线路。

`POST /cvm/{id}/routes/match` 接受 `{destination, protocol, port?, routes?, network_edit?}`，`protocol` 为 `tcp`、`udp` 或 `other`。可提交暂存路由 `routes`，或提交完整网络草稿 `network_edit`（与网络编辑预览请求同形，支持尚未挂载的网卡引用）；两者都省略时使用已保存的期望路由表。草稿以回滚式编译检查，不保存配置、不占用地址。返回 `kind: "route"` 时包含命中的规则 `route`、从零起算的 `route_index` 及该地址族的 `priority`；显式提交路由表时索引按提交顺序，否则按编译后的路由表顺序。规则引用待挂载网卡时返回其草稿标识；Cube 线路阻断时还返回 `blocked: "chain_requires_tcp_udp"`。无显式规则时返回 `kind: "default"`。

P 的初始路由仅用于挂载初始化，之后由容器管理；P 新版本不覆盖 R。DNS 建议只有明确勾选后才应用，容器 DNS 仍可单独配置，解析流量遵循 R。

P 的修改创建不可变新版本。新挂载使用最新版本，已有 N 固定原版本，须由管理员显式应用新规格。在出口网络编辑页可批量应用保留地址与当前承载的兼容规格。同一容器内的多卡更新一次性保存，任一校验失败会全部拒绝。原地址满足新规格时保留；需要换地址时必须先关机、处理路由／入站依赖并明确允许重新分配。新旧分配分别保留清理证据，不静默改变入口。停止新挂载不影响已有 N 的通信、重连和恢复；撤销授权则阻断已有 N，保留身份、分配与 R，离线端显示待执行。

卸载前先在同一个网络草稿中移除该网卡的路由和优先级引用，然后暂存卸载，一次保存。正常删除 P 要先处理派生 N 并等待清理。B 退役是明确例外：直接删除其发布和网卡引用、删除相应 R 引用，剩余路由可以重新匹配；逻辑删除不等待 B 上线，未知物理资源仍保留占用证据。

上下行限速和 UTC 月流量额度可选。业务 IP 字节在 H 的 N 边界计量一次，包括 IP 头和业务重传，不重复累加两端或外层隧道重传；外层承载开销单独观测。计数器重置或跨月采样缺口明确标记。超额阻断 N，不触发换卡；管理联络保留。额度和用量不复用代理转发授权。

## 计算与磁盘容量

CPU、内存和系统盘使用实例自己的逻辑规格，不设置用户总额准入。创建、关机改配和编译预览校验管理员作用域与宿主执行能力，不因宿主全部实例的逻辑分配超过 CPU、内存或磁盘基准而拒绝。单实例仍须满足节点明确声明的执行范围、最小值和步长。

资源用量继续使用持久记录，保留待清理系统盘和网卡的归属；CPU 和内存的展示预约保留当前规格与已发布规格的较大值。删除用户配额不会提前释放系统盘、地址、端口或待清理网络资源。

宿主表和创建页展示“分配量 / 宿主容量”；分配量不是实际使用率或创建禁用条件。实际使用由运行监控报告。网络状态表、地址与端口仍使用各自的独立容量和归属约束，逻辑 Guest 内存不抵扣网络状态表预算。

## 线路作为出口

容器路由的“经由”可选业务网卡或已授权的线路。“出口优先级”分别设置 IPv4 和 IPv6；L3 最长前缀、同前缀 L4 优先、出口优先级与端口段宽度使用同一套排序，网卡与线路一起比较。线路规则不创建业务网卡、不消耗网卡槽位或地址池分配。

线路流量经管理主网卡交给宿主的受管 Xray 客户端，以**容器使用者**已有的接入凭据连接线路入口，再按线路内部的域名、IP、协议和端口分流。只支持 TCP／UDP；ICMP 不经线路，不能以 ping 判断线路是否正常。未匹配任何规则的流量仍走主网卡 NAT；已经匹配线路的流量在客户端退出、入口不可达、授权撤销或额度耗尽时保持阻断，不回落到宿主 NAT、其他线路或业务网卡。主网卡管理联络与访问入口回包保留。

接入授权、用量、常态限速、超额行为和计费周期沿用该使用者在该应用下的线路策略，不创建第二份容器线路账本。业务网卡的 UTC 自然月额度与线路用量使用不同口径。“路由与命中测试”的“经由”选择器区分业务网卡和线路；未获授权或宿主无法执行的线路不能选用。撤销授权后仍可看到已有规则，方便撤下。

宿主须上报 `chain_egress`，Console／Agent 协议至少为 76。Cube 容器要求运行栈支持主网卡分类器；物理宿主实例通过本机 OUTPUT 分类、连接标记和输出防回落规则执行，不经过 Cube 数据面。物理宿主保留管理联络、入站回包与 Agent 受管连接，线路客户端上游连接独立保护；相关前提见 [物理宿主能力边界](baremetal.md#能力与隔离边界)。IPv6 规则还要求线路每个已知出网分支具备 IPv6；不能确认的代理出口不允许保存 `::/0`。带前置代理或独立下载链路的入口当前会明确标为不支持，不绕过它们的配置。

线路出口不可用时，界面分别说明宿主状态不可读、状态上报过期、容器服务异常或宿主组件不支持，并给出处理方式。此时已授权线路显示“宿主未就绪”，避免将授权等同于可用；能力恢复并重新上报后可继续选择。

线路客户端、原生防回落 nft 规则、路由标记与策略表随同全局修订冻结，管理员可在混合发布单查看脱敏内容和差异。只有冻结客户端与防回落规则的摘要均匹配，且运行栈确认路由后，才确认执行。Xray 输出进入实例网络配置日志；私有凭据不进入普通实例产物或用户日志。

## 网络草稿与待发布

容器清单、实例详情、创建页和资源页共用顶部变更条。展开“未保存”可核对当前实例的草稿及“路由与 DNS 差异”，也可通过其他草稿的链接进入对应实例的“网络”页。草稿保留在本次页面会话中。打开对应实例后，可用“丢弃当前草稿”清除。

实例“网络”中的新增或撤销入口、挂载或卸载网卡、路由、优先级和 DNS 可以放在同一草稿里编辑。“查看配置差异”在事务中检查整组改动，随后回滚临时的地址、端口和修订分配。“保存网络变更”会复用当前输入的审核结果，草稿变动后重新检查，并携带审核摘要在一个事务中保存全部改动。任一项校验失败都会拒绝整组保存。明确拒绝后可修改并重新检查。保存结果不明时，使用“重试原保存”沿用锁定的原请求与审核摘要，避免重复分配。收到草稿版本冲突时，先核对当前配置，再丢弃旧草稿并重新编辑。

保存后的配置进入顶部“待发布”列表，发布批准后才下发，实际状态以节点回执为准。展开列表可跳到对应实例或其“网络”页。可管理该实例的管理员还能打开“变更详情”，查看保存时间、操作者和改动摘要，并对符合条件的实例选择“撤回”。关联发布单锁定时，列表显示锁定原因。使用授权变更须按授权流程处理。有发布权限的操作者可查看同修订发布检查，并通过“查看发布计划”进入统一发布页。既无实例编辑权限也无发布权限的账号会看到“变更已保存，等待管理员发布”。相关限制见[实例编译产物](#实例编译产物)。

## 访问入口

管理员在“网络”页签的“访问入口地址”按机器发布地址并授权使用者：

- **共享地址**按协议端口分给多个容器，必须是机器网卡上的实际地址；宿主正在监听的端口、代理与组网保留端口、用户端口转发和网卡承载端口都不会分配。
- **独占地址**由一个容器持有地址租约，可选择需要转发的协议和端口。可以使用入口机器自身或共享出网使用的 IPv4 地址，地址继续保留在入口机器；组网通道地址不可使用。保留端口不会开放给另一个容器分配。
- 云厂商一对一 NAT 时填写“对外地址”：机器上匹配内网地址，界面与 SSH 命令展示公网地址。
- 同一机器的地址只能出现在一份发布中。授权实时生效：撤销后已有入口保留地址与端口但停止转发。

入口按协议配置，不要求选择 L3／L4 分类。TCP 和 UDP 各自选择“全部端口”或端口列表／范围，例如 `22,443,8000-8100`；未填写映射的部分保持原端口。独占地址还可选择 ICMP 和其他 IP 协议。共享地址只允许 TCP／UDP，全部可分配端口限定在发布的端口段内，且仍须通过占用检查。

每个地址可由管理员设置 TCP／UDP **保留端口**，语法相同。它们继续按入口机器现有服务和防火墙处理，不参与入口转发，也不会自动新增防火墙放行。新增配置不会自动保留 22；若 Agent 观测到 sshd 的真实监听端口，编辑器提供显式添加按钮。保留 TCP 端口不会同时保留同号 UDP 端口。通道正在使用的端口仍由系统保护。

端口映射显式填写，例如 `30022 → 22`、`30000-30099 → 40000-40099`，多个映射可分行填写。两端范围必须等长，入口范围互不重叠，且位于所选转发范围内。保留按**入口端口**扣除：入口机保留 TCP 22 时，仍可用 TCP 30022 访问实例 22。若保留 30050，30051 仍映射到 40051，后续偏移不改变。

每份输入最多 256 段；每个协议的改端口映射最多 4096 个端口。共享入口的有效租约最多 8192 个协议端口，每台机器参与的共享租约合计上限为 16384，撤销中仍计入占用。独占地址保持一个地址租约；不改端口的全范围使用区间匹配，不展开为数万条规则。共享地址已分配的端口不能直接改为保留，须先撤销相关入口并等待清理。

保留变更随全局配置修订发布，保存不会改变正在执行的冻结配置。减少或删除保留时，分配器同时保护当前配置、已发布配置和节点最后确认的保留集合，节点确认替换后才解除旧保护。入口机器和计算宿主一起发布。更新或撤销入口时，沿用 Agent 的持久清理流程关闭受影响入口的旧连接；未变更入口的连接保留，保留端口不被临时阻断规则扩大覆盖。

当前 API 新规则为 `kind: "protocols"`，包含 `tcp`、`udp`、`icmp`、`other_ip`。TCP／UDP 为 `{kind:"disabled"}` 或 `{kind:"forward", ports:{kind:"all"}, mappings:[]}`；指定范围使用 `ports:{kind:"ranges",ranges:[{start:80,end:80}]}`；映射为 `{listen:{start:30022,end:30022},target:{start:22,end:22}}`。发布地址的 `reserved_ports` 为 `{tcp:[{start:22,end:22}],udp:[]}`。

旧 `l3`／`l4_range` 记录、冻结发布和 Agent 私有检查点继续读取，缺失保留列表等价于空列表，不重写历史或自动补保留端口。已经停止支持的旧 `kind:"l4"` 形态仍拒绝。协议入口规则需要两端上报 `entry_protocol_rules`；缺失表示不支持。Agent 协议为 79，先升级能读历史数据的 Console，再升级相关 Agent，最后发布新配置。契约不匹配返回 409，不进入凭据撤销清理分支。使用新格式后，回滚程序也必须能够读取它。

在实例详情的“网络”页签打开“访问入口”，可添加入口或在已有入口行选择“撤销”。这两种操作先进入网络草稿，由顶部“保存网络变更”统一保存。删除容器时也会撤销所属入口。撤销后的地址与端口保留到入口机器回报清理完成，每份发布、每个容器（64 条）、每台机器（4096 条）都有入口上限。

改派已有入口前，先保存或丢弃当前实例的网络草稿。点击该入口行的“改派”，在就地表单选择同一使用者名下仍可用的其他容器，再点“保存改派”。该操作单独保存，沿用原地址和端口，只更改投递目标，保存后进入顶部“待发布”列表。若保存结果不明，使用“重试原改派”核对同一次请求。

数据面：入口机器把目的地址换成容器的宿主内地址。容器在别的宿主时，按每对机器共用一条的受管 IP 通道送达：默认入口机器监听发布中的通道端口，宿主主动连接，可以位于 NAT 后；也可选择由计算宿主监听。WireGuard 使用内核设备；Xray 使用独立的 VLESS Reverse／TLS 进程和有界 IP 帧通道。Phantun 的进程、TUN 和规则独立于原组网管理，重载原组网不会停止入口通道。通道在第一条入口时建立、最后一条撤销时收回，端口与槽位在两端确认清理后释放。宿主把来源换成 Cube 网关地址，经 CubeVS `primary_delivery` 交给容器主网卡，回包沿原路返回。

Guest 看到的来源是宿主网关，不保留访问者原始 IP。Cube 主网卡只有 IPv4，访问入口目前只支持 IPv4 地址。通道使用槽位派生的 E 类地址 240.0.0.0/15（只在两端之间，不会离开通道），入口机器另用包标记与路由表 `0xb60000` 加槽位、规则优先级 31700，不修改宿主默认路由。容器未运行、授权撤销或通道未就绪时，入口机器仍占住地址与端口并丢弃新连接，不会落到宿主服务。

前提：入口机器和容器宿主的 Agent 上报 `entries`（需要 nftables、iproute2，并开启 IPv4 转发；WireGuard 另需 `wg` 与内核模块，Xray 另需匹配的 Xray 和 TUN）；容器宿主的运行栈上报 `primary_ip_delivery`。宿主若有其他防火墙丢弃转发流量或通道 UDP 端口，需要放行。实例详情的访问入口列表按节点回报区分部署中、已生效、执行失败、机器离线、授权撤销、目标未运行和撤销中等状态。

## 状态与恢复

HTTP 请求受理只表示分配和操作已保存，界面显示“待执行”。设备地址是 Guest 内的地址，实例接入地址是承载机器投递到该实例的地址；映射后端中二者可能不同，不能互相冒充。

“运行中”需要对应实例、操作、规格版本、运行时、系统盘和 Guest 网卡的实际回执。副网卡还需要主网卡路由、默认业务出口、无匹配路由时的主网卡 NAT 路径以及已选中业务路由故障时禁止回落的观测证据。

通信中断或原运行时丢失时先核查原对象。支持原盘恢复的后端会重新使用同一个物理系统盘；原盘缺失或身份不符时显示“待核查”，不以新空盘替代。重试沿用原操作身份。过期回执不能覆盖新规格；机器能力报告超过 150 秒或包含错误时，暂停创建、启动和网卡变更，保留已有分配。仍可提交删除或核查原任务；能力观测失败时保留上次有效的删除与保盘能力，Agent 继续尝试清理已归属的实例。

关机保留数据。实例详情“更多操作”中的“删除”先说明对象和系统盘、网卡、入口后果，确认后保存删除变更。删除会销毁系统盘数据、清除实例路由、撤销访问入口并卸载网卡，无法恢复。保存后，顶部变更条列出待发布的删除，实例清单继续显示该实例。运行时、网络和系统盘清理确认后才释放分配。整实例删除可覆盖尚未确认的网卡卸载，以完整网络清理回执确认全部网卡释放。

卸载副网卡先停止该地址的业务路由，再请求真实设备移除；Guest MAC、Hypervisor 设备、宿主 TAP 及对应 CubeVS 端点策略均清理确认后，才释放网卡分配。网卡挂卸只改变网络规格，不改变最初的运行时、系统镜像、CPU、内存或系统盘身份。已确认删除实例的地址分配可重用；结果不明的对象继续占用原地址。

普通退役要求先释放承载机器上的实例和系统盘。系统管理员使用机器详情中的“强制退役”时，Console 会先取消冲突发布，把该机所有 Cube 实例记为删除、裸机实例记为解除纳管，并一次撤销入口和网卡关系；退役机器不再作为清理回执方。未隔离的关联机器进入新的清理发布，隔离中的关联机器不阻塞本次退役，恢复服务时再按 Console 已清理的基线收敛。无法从失联机器确认的系统盘、地址或端口继续保留为未确认的审计／占用证据，但不会让机器或容器继续显示为待发布，也不会阻止强制退役完成。

已清理实例的不可变执行历史保留原机器 ID 文本，但不再以外键保留机器记录。系统管理员永久移除已退役机器时，Console 会清理该机的活动快照、发布目标、用量明细和关联线路，再删除机器记录；历史文本不会阻止删除。

移除容器宿主前，先删除该宿主上的全部实例，等待系统盘、网卡和访问入口清理完成。若宿主承载裸机实例，须先解除纳管并等待资源清理。系统管理员在“宿主”表展开对应机器，点击“移除宿主…”并确认。此操作停止该机器承载新实例。机器的代理、组网和出口网络继续运行；Cube 运行栈有独立的安装和卸载流程。需要恢复时，在“宿主”页顶部的“添加宿主”选择该机器。

## 节点执行与配置

Console 和 Agent 通过 `brocade-deployment::cvm` 的共享契约交换期望状态。Agent 内的 `brocade-cube` Rust 库直接通过 Unix socket 调用 Cubelet 的 gRPC／Tasks 接口，执行和核查实例、原盘与网卡，并提供 Guest 观测和 PTY。用户、认证、配额、不可变规格及操作仍由 Console／Store 管理；Cubelet、Shim 与 CubeVS 保存实际执行状态。

Rust 对接库随 Agent 一起编译和分发，Cube 运行栈是独立的可选安装与发布域。所有 CVM 功能采用统一版本门槛；关机卸载由 Console 下发稳定清理 ID，Cubelet 证明设备和租约已清理后，Agent 才完成回执。缺少实际证明时保留分配和待确认状态。先升级 Console，准备匹配的 Agent 二进制，激活对应 Cubelet／Shim 后再重启 Agent。普通 Agent 更新不会隐式替换 Cube 运行栈。

访问入口变更或撤销时，Agent 先阻断受影响入口，按原始目标地址、入口端口和 DNAT 目标清理旧连接，再发布新规则并解除临时阻断。清理进度保存在持久状态目录；中断后继续重试，未完成时不报告入口配置成功。未变更入口的连接保留，承载通道端口不受临时阻断影响。

在 **Agent 服务环境**设置：

- `BROCADE_CVM_CONFIG`：私有 Cube 配置的绝对路径，默认 `/etc/brocade/cvm-cube.json`。
- `BROCADE_CVM_STATE_DIR`：持久执行记录的绝对目录，默认 `/var/lib/brocade/cvm-cube`。

这些变量不属于 Console 环境。配置结构见 [配置示例](../crates/brocade-cube/examples/cvm-cube.example.json)。托管安装使用 `/opt/brocade/cvm/current/generated/cube.json`，由 Rust 客户端直接读取。更改配置后重启 Agent。

私有配置的 `capabilities` 只描述管理员选择的执行策略、容量、资源范围、系统镜像与网络来源目录。`backend`、`guest_terminal`、`configure_network` 和 `primary_ip_delivery` 由执行器及 Cubelet 实际能力生成，不属于配置输入；WebShell 访问开关由 Console 管理。持久系统盘的能力核查要求 Cubelet 明确上报与配置一致的存储后端。

配置必须由 Agent 的有效 UID 持有、权限为 `0600`。镜像清单同样由该 UID 持有且禁止组或其他用户写入，`image.sha256` 固定其原始字节。清单只描述系统制品、组件版本和启动方式；CPU、内存与系统盘大小来自实例的不可变规格。包含容量或内存快照绑定的系统清单会被拒绝。

`cubelet_socket` 必须是本机绝对路径；客户端核对 socket、所在目录及 Unix peer 的身份。接受 Cubelet 的 `0660` socket，禁止其他用户写入，目录不能被组或其他用户替换。`network_inspection_url` 仅接受字面 loopback IP 的 `/v1/network/taps`，不跟随重定向。RPC 和检查响应均有期限与长度上限。

可在不读取 Console 凭据、不认领执行记录或执行实例操作的情况下检查能力：

```sh
brocade-agent cvm-check --config /etc/brocade/cvm-cube.json
```

计算与网络能力目录、构建和节点前提见 [Cube 节点运行栈](cube-runtime.md)。Cubelet 私有网络配置示例见 [cube-networks.example.json](../crates/brocade-cube/examples/cube-networks.example.json)。地址池及网卡授权在 Console 发布，实际设备容量由 Cubelet 上报；B 的地址归属与上游路由由管理员保证。

执行任务串行收敛，待执行队列最多 256 个实例；同一实例的新规格合并到原排队位置，重复轮询不追加任务。每机最多保存 8192 条、每条最多 32 KiB 的私有执行记录。意图和回执通过 `fsync`、原子替换和 `0600` 保存。创建结果不明时按冻结归属核查，不能再次分配空盘。观测使用独立的有界调度与缓存，失败不完成生命周期操作。

## 网络执行前提

网卡与访问入口只使用当前契约：网卡节点契约为 1，本机交付为 `cubevs-attachments-v2`，运行栈须具备实际 `managed_networks` 能力。B／H 需要 Linux 网络管理权限、iproute2（含 tc／ss）、nftables、conntrack 和可用的 IP forwarding；WireGuard 另需内核支持与 `wg`，Xray 另需匹配的 Brocade Xray 和 `/dev/net/tun`。缺失能力明确拒绝挂载，不进行旧网卡记录转换或本地业务网桥接管。

Agent 自动收敛自己拥有的命名空间、bridge、路由、nftables 与邻居代理，保留宿主默认路由和其他服务；发生归属冲突时报错，不接管未知设备。使用 journald 日志命名空间等私有挂载视图时，网卡命名空间在宿主持有独立句柄；Agent 重启后沿同一身份接管，普通卸载在归属核查后释放两侧句柄。旧进程退出留下的空占位文件，只有归属记录匹配且旧设备已消失时才回收。B 的公网地址、实际端点连通性和上游路由仍须真实可用。节点控制中断时已有数据面继续收敛本地保存的意图，已分配的月额度由 H 的持久计量边界继续执行；跨 UTC 月重置不依赖 Console 在线。新分配与配置变更等待 Store。

网络执行器每轮连续处理全部有界承载，每八条上报一次，完成整轮后才等待下一次轮询；实际执行耗时仍会影响观测新鲜度。离线恢复先恢复保留资源的隔离规则，再逐卡收敛；单张网卡失败不阻止其他网卡恢复。即使承载已清理，只要资源仍等待释放确认，其隔离规则也继续恢复。

## 产品变体与数据库

CVM 是默认不安装的扩展能力。先按[安装与升级](install.md#产品变体与扩展切换)切换为 `cvm` Console；已装机器的 Agent 不会因此更换，之后在发布页升级时跟随 Console 换为容器 Agent。仅提供入口或出口网络的机器安装 `--agent-flavor cvm` 即可，不要求 Cube 或 KVM；计算宿主使用 `--enable-cvm`，同时安装容器 Agent 和经过校验的运行栈。

Agent 重装省略变体时保留已安装身份。发布页的 Agent 类型跟随 Console，不再提供变体切换：容器版 Console 统一下发容器 Agent，名单中的基础 Agent 在同一次批准中换为容器 Agent，名单工具条写明台数；基础版 Console 只下发基础 Agent。退回基础 Agent 需要先排空全部 CVM 资源、等待实际清理回执、停止 Agent，再以 `--agent-flavor base` 运行安装器。在线自更新不承担 CVM 降级；其执行进程持有资源锁，不能替代停机检查。

两种 Console 共用首发统一 schema。全新安装执行正常迁移；切换产品变体不删表、不改写 SQLx checksum、不重建普通数据。基础版会拒绝仍在使用或待清理的实例、卷、网卡、入口、地址端口与网络状态，以及未发布的容器配置和未结束的混合发布。实验 schema、旧 CVM 执行记录和中间协议不属于首发接管范围，已移除实验转换开关。

## 独立配置 CPU 与内存

创建实例时分别填写 CPU（核）、内存（MiB）和系统盘（GiB），不选择命名套餐。API 使用 `resources: {vcpus, memory_bytes, root_disk_bytes}`。机器通过可选的 `resource_limits` 上报各维度的最小值、最大值与内存／系统盘步长；Console 和 Rust 执行库分别校验，不再依赖用户额度。

独立数值直接保存于不可变实例规格的 `resources`，不包含套餐 ID 或名称。机器开放创建时必须提供 `resource_limits`；单实例范围、步长和实际网卡容量仍须校验。Cube 实例必须带非零登录凭据版本，由当前 Agent 通过私有凭据接口取得密码。

## 开机、关机、重启、改配与重装

详情用标题图标角上的状态灯表示实际运行状态，异常另加角标。概览、网络、监控与诊断、产物页签带图标，与实例操作位于同一工具栏，窄窗口下分行显示。开机／关机和重启直接可见；“更多操作”提供修改配置、重装系统和删除。关机、开机、重启保留系统盘数据与网卡地址分配。CPU、内存及名称在确认关机后独立修改，额度按新配置原子校验，镜像不因此改变。当前不提供运行中热改 CPU／内存和系统盘缩容。

重装明确清空系统盘并重新初始化 SSH 身份；要求填写完整实例名称并确认数据清除。实例身份、CPU、内存、系统盘容量和网卡配置保留，可另选系统镜像，登录密码自动重新生成。重启和重装各有单调递增代次，重试或进程重启不会重复重启或再次清盘；回执必须包含对应完成代次。

关机后的重装同样先确认旧系统盘已物理删除，再启动新系统。执行记录单独保存已确认清盘的重装代次，启动回执丢失或恢复启动失败时继续使用本轮新盘，不重复清盘。

Cube 的默认 storage DB 位于临时状态目录，不能承担断电恢复登记。protected-root-v1 将受保护原盘的执行清单同步写入持久 DataPath 下的 `brocade-roots/`，文件及目录均 fsync。普通 GC、关机和失败清理不能删除受保护系统盘；只有明确删除数据或重装才允许删除。宿主重新启动后按清单与真实 CoW 对象恢复登记，沿原盘冷启动，并重新核对主网卡、副网卡、路由与隔离规则。缺失物理盘不会触发新盘分配。

持久清单损坏、物理对象缺失或归属不一致时保留分配并报错。Agent 重启后清除缓存的成功状态，重新核查实际运行结果。

## ext4 兼容边界

ext4/plain 使用同一份固定只读系统镜像，每个实例新建独立、按需占用物理空间的可写稀疏文件盘，Guest 沿用 OverlayFS；创建不复制镜像，也不使用 reflink。与 XFS 相同地支持当前已开放的独立 CPU／内存／磁盘创建、原盘关机／开机／重启、关机改 CPU／内存／名称、明确清盘的重装、删除及重试、服务／宿主重启后的原盘恢复。网络、转发、监控与终端不依赖宿主文件系统类型。

plain 不实现磁盘或内存快照、克隆、暂停快照恢复、跨节点迁移、磁盘扩缩容及保留盘管理；这些也不属于当前 CVM 的公开能力。卷核查 API 仍保留，用于确认原盘与物理删除，不代表开放快照功能。

plain 的卷文件与目录仅服务 UID 可访问，池采用独占进程锁。分配在私有暂存目录完成后原子发布；删除先持久记录删除意图，再回收文件。启动会恢复未发布分配与未完成删除，遇到未知对象则拒绝接管。格式化完成后持久保存磁盘名称、容量和 inode 回执；恢复只认原盘。回执缺失／损坏、逻辑容量或原盘身份不符、路径或权限异常时停止使用该盘并保留分配，不自动格式化或补建替代盘。初始化过程中断且无法证明完成的盘需要管理员核查后处理。

新安装按宿主 CPU、扣除运行时保留后的内存及当前可用磁盘空间生成资源基准；基准不限制逻辑分配，实例由管理员统一配置。受管 plain 卷使用稀疏文件薄置备，逻辑容量可以超过当前可用物理空间，实际写入仍需要真实空间。初始化回执只接受 `brocade-plain-initialized-v2`，记录已完成格式化及原盘身份。v1 回执被明确拒绝，不转换或重新格式化旧盘。plain 不具备 reflink 共享块或内存快照能力。安装器将实际文件系统 UUID 固定在私有 `generated/storage.json`，启动与升级时核对；数据盘未挂载或文件系统改变时拒绝初始化替代池。升级保留管理员配置与后端身份；其他宿主程序占满磁盘仍会导致分配或写入失败，应监控共享文件系统空间。

本地存储配置 `local_backend = "plain"` 与 Rust 客户端 `storage_backend = "plain"` 必须一致，安装器自动生成；`plain_reserve_bytes` 默认 0，安装器不自行设置预留比例或固定空间；管理员显式配置的值在升级时保留。已建卷禁止通过改配置切换 XFS/plain，也不隐式迁移卷。节点包必须通过 `storage_backends` 明确声明支持范围；ext4 主机在停服务前拒绝激活不支持 plain 的版本。

## 安装与运行包

Agent 安装器支持 `--enable-cvm`，从控制面提供的架构清单获取并校验运行包及安装器。先安装包含 Rust Cube 客户端的 Agent，再安装 Cubelet、Shim／Hypervisor、CoW 和固定系统制品。安装器配置 Cubelet 服务及 Agent 的 CVM drop-in，校验实际运行进程与能力；首次纳管在消费纳管凭据之前完成制品和宿主预检，需要换核时保存待重启状态并继续普通 Agent 纳管。

小内存宿主可显式调整 `generated/cubelet.toml` 的预建池：`io.cubelet.internal.v1.cgroup` 下的 `pool_size = 50` 使用小型 cgroup 池，网络插件默认 `tap_init_num = 1`，预建 1 张空闲 TAP，其余按需创建；可设为 `0` 完全按需创建。模板的 3,000 个 cgroup 预建量可能耗尽 1GB 宿主内存。这是管理员的运行时缓存配置，不扣减可分配容量；升级保留该配置。

### 原生 KVM 与 PVM

新运行包支持 `auto`、`kvm`、`pvm` 三种节点模式。首次安装默认 `auto`，先加载并实际检查 KVM（包括创建一个无 vCPU、无内存的临时 VM）；没有可用原生 KVM 时准备 PVM。正在正常使用 PVM 的节点在 auto 下继续使用 PVM。后续安装省略模式时保留已保存的选择；可用 `--enable-cvm --cvm-mode auto|kvm|pvm` 显式修改。权限、I/O、包校验或其他系统错误不会被当作缺少 KVM 而自动换核。

PVM 通过专用宿主内核提供 KVM 接口，不需要云服务商向 VPS 暴露 VMX/SVM。运行包必须同时提供经过 SHA-256 核验的宿主内核 `.deb`、匹配的 PVM Guest 内核与配对元数据。Cubelet 的实际内核源和系统镜像内核缓存按虚拟化模式隔离，避免复用另一模式的 Guest 内核。选择 PVM 前会核对完整配对制品；仅给安装命令添加环境变量不能补齐内核。

运行包统一使用 `brocade-cvm-stack-v2`，每个包均包含固定的宿主模式管理程序。换核和激活前还要求 Agent 支持 `cvm-check --maintenance-contract`（输出 `brocade-cvm-maintenance-v1`），确保待重启期间的暂停实际生效。升级顺序为先 Agent，再使用匹配的新安装器与运行包。

自动准备宿主内核目前支持 x86_64 Debian/Ubuntu、GRUB 与 dpkg。安装器从系统生成的 GRUB 条目复制实际 root、initrd 与原启动参数，增加独立的原内核/PVM 条目；不改网卡命名或 IPv6 设置。PVM 所需的 `nopti pti=off no5lvl rt_group_sched=0` 参数只作用于 PVM 条目；后者关闭该内核的实时任务分组，使 cgroup v2 CPU 控制器可与 `multipathd` 等实时线程共存，不停止其他宿主服务或修改全局实时带宽上限。当前上游内核不支持 KPTI，这会改变宿主的侧信道防护边界，应在发布该内核配对前评估。其他系统可手动准备匹配内核后使用 PVM，但不宣称自动换核支持。

准备完成后返回退出码 **75（等待重启）**，不自动重启。普通 Agent 纳管仍完成，CVM 暂不分配实例；用户手动重启后，固定版本的 systemd 恢复程序会继续安装。首次仅单次启动新内核，核对实际内核、模块、启动参数、Cubelet 与能力后才设置后续默认。新内核不能启动时，下一次启动仍有原内核入口；机器已回到原内核时恢复程序撤销失败切换、恢复原配置。内核卡死时仍需要服务商控制台或人工重启，无法由未启动的系统自行恢复。

已安装节点可以使用：

```sh
sudo python3 /usr/local/lib/brocade/cvm-stack.py mode auto
sudo python3 /usr/local/lib/brocade/cvm-stack.py mode kvm
sudo python3 /usr/local/lib/brocade/cvm-stack.py mode pvm
sudo python3 /usr/local/lib/brocade/cvm-stack.py status
```

每次只执行需要的一种选择。显式 `kvm` 不会回退到 PVM；切回原生 KVM 仍需要 CPU 暴露 VMX/SVM。切换前必须清空该节点的 CVM 实例并确认清理；关机实例也不能直接跨模式启动。安装器短暂停止 Agent，以执行目录排他锁和实际 Cube 列表共同确认空节点，再让 Agent 的其他收敛域继续工作。原盘、系统制品与审计记录不会因模式选择被删除。

取消尚未完成的切换用 `sudo python3 /usr/local/lib/brocade/cvm-stack.py cancel-mode`。如果已经进入新内核，该命令先选回原启动项，需手动重启后再次取消/恢复；状态和失败证据保持可查。待切换状态位于 `/opt/brocade/cvm/host.json`，不要手动删除它来绕过暂停或恢复。

运行包保留不可变版本和摘要。仅同一当前契约内恢复执行状态；旧格式不导入或转换。升级或回退保留仍被实例引用的系统制品；匹配的 Rust Agent 是前提。安装器启动 Cubelet 和 Agent，Agent 内的 Rust 库承担本机执行。未知安装来源或不兼容状态拒绝接管。手动构建、安装与恢复见 [Cube 节点运行栈](cube-runtime.md)。

## 连接入口

实例详情优先展示已生效的访问入口：指向 22 端口的 TCP 入口使用入口端口，未保留 TCP 22 且确实转发到实例 22 的全端口入口使用 22；显式映射优先使用映射后的入口端口，均以访问者使用的地址展示。生效中、撤权或容器未运行的入口不推荐为连接入口。没有可用入口时可使用实例终端；宿主内管理地址单独标注为“在宿主上执行”。Guest 使用 `cube` 用户和系统生成的登录密码；旧公钥初始化规格不再执行。

已保存的公钥规格保留原编码与摘要，不自动生成密码或重写历史；裸机的存量规格可继续用于列表、详情与已批准的节点期望。裸机不使用 Guest 密码。历史 Cube 规格须通过明确的密码重置或重装操作生成密码修订后，才能编译新的 Guest 产物；仅兼容读取不代表接管旧执行格式。

“地址已分配”“Guest 设备已配置”“承载已连接”和服务可达性分别展示，不能从配置受理推导实际服务正常。修改、关机、离线和切换保留地址；卸载后须同时获得 Guest 设备与两端网络清理证据才释放。网络回收包括旧 nftables 规则、路由、邻居代理及连接跟踪，未知结果不会按超时重新分配。

## 实例监控

实例详情提供轻量的监控概览，以及独立“监控与诊断”页签。四类卡片按需展开：CPU 使用率、采样峰值、时间分项、每核读数、负载及压力；内存分类、Swap、重大缺页及 OOM；根文件系统空间、inode，以及能够可靠归属到根设备的 I/O、IOPS、等待与队列；逐网卡收发 bit/s、包速率、丢包、错误与 carrier，以及整个 Guest 的 TCP／UDP 计数。内核未提供的指标显示未知；根文件系统没有独立块设备映射时明确显示 I/O 不可用，不取宿主磁盘总计代替。

Rust 执行库通过本机 Cubelet 任务 API 执行固定只读命令，不依赖 SSH 私钥，也不安装额外 Guest 服务。监控独立于配置收敛、能力目录和八实例生命周期轮转。每机器最多 256 个对象，采样池并发 2–32，目标周期 15 秒；慢 Guest 会延长实际周期，界面始终使用实际观测时间。Rust 执行库每实例仅缓存最近四份数据，Agent 每轮按八实例分页遍历全部分配对象，上传与生命周期分开。采样失败不完成任务、不重建系统盘，也不抹除最后有效样本。

速率从相同 Guest boot_id、接口身份及 ifindex 的相邻计数计算。CPU 来自 `/proc/stat`，内存使用 `MemTotal − MemAvailable`；容量均为 Guest 可见值，与配置的物理容量分开。第一份样本、重启、设备重挂、计数器回退、采集通道中断或超过两分钟的间隔断开速率，曲线不补零。网卡总计不包含 loopback，不作为计费用量。TCP／UDP 诊断为整个 Guest，选择网卡不会改变这些计数。

运行时、Guest 管理采样通道、SSH TCP 22 和已配置 TCP 服务端口分别表达健康。SSH 与服务探测从承载机器连接此实例已确认的地址；成功不代表公网路径可用，UDP 不用 TCP 成功替代。监控页另提供承载机器观测入口。配置失败与实例仍在运行、仍能采样可以同时成立。

Console 使用独立的监控状态、分钟历史和事件表，不修改实例规格或生命周期回执。提供 1／6／24 小时范围；每分钟的 CPU、网络及 I/O 速率按有效持续时间聚合，保留 CPU 采样峰值、最低可用内存和窗口计数。展示最多 2,000 点、100 条事件；重启、OOM、通道和服务连接变化与既有实例操作关联。独立清理任务每分钟分批删除超过 25 小时的记录，无活跃上报时仍会执行。日历史从启用后逐步累积，不虚构过去数据。接受的一分钟内时钟领先会保留真实上报时间并扩展相同长度的查询窗口；超过五秒时提示校准机器时钟，避免新样本被查询上界隐藏。有效窗口内的计数器缺失或回退会保持该分钟速率未知，不按零参与平均。

`GET /cvm/{id}/monitoring?window_secs=3600|21600|86400` 按实例租户／用户鉴权；Agent 使用独立 `/agent/v1/cvm/observation-targets` 和 `/agent/v1/cvm/observations`。生命周期回执不携带监控数据，查询只读取独立观测状态和分钟历史；尚未采样时显示未知。滚动升级先 Console，再 Agent 及其内置执行库。

## 实例终端（WebShell）

运行中的实例可从清单或详情打开“终端”。两个入口均检查宿主 WebShell 策略、实例运行状态和操作者权限。浏览器通过同源 WSS 连接 Console，宿主 Brocade Agent 转接到实例 CubeShim。Shim 持有经 vsock 创建的 Guest PTY 和 Shell。无需实例公网地址、SSH 端口或密码。Guest 业务网络异常时仍可维护；Guest 内核或 cube-agent 不可用时无法连接，本功能不提供启动救援串口。

终端以 Guest root 运行。本人、作用域内租户管理员和系统管理员可以使用，只读及其他管理角色不能连接。浏览器不能选择任意 runtime、进程参数或本机路径。会话按操作者和实例运行身份隔离；新页面连接同一会话后，旧页面不能继续输入或调整尺寸。

系统管理员和所属机器租户作用域内的租户管理员，在 **容器 → 宿主 → WebShell** 按机器开启或关闭，默认关闭。关闭立即拒绝新连接并关闭 Console 中的现有连接；Agent 每 20 秒同步策略，随后要求 Shim 结束被撤销版本的 Shell。Agent 离线时需等连接恢复后执行清理。先关闭再开启也会撤销旧版本会话，不影响重新开启后创建的会话。普通用户和只读账号不能管理开关。Console 保存策略版本和操作审计，节点能力上报不会覆盖设置。`PUT /cvm/hosts/{node}/terminal` 接收 `enabled` 与 `expected_revision`，版本冲突返回 409。

开启 WebShell 后，有权限管理该宿主开关的管理员可在同一行查看“会话 已占用数 / 上限”。这是 Agent 最近一次有效上报的宿主会话名额占用，包含仍在后台存活的 Shell。观测缺失或过期时显示“会话数未上报”。创建新会话时由 CubeShim 按节点实时校验名额。

使用前须升级 Console、宿主 Brocade Agent、Rust Cube 客户端和支持持久终端及实际 `ResizePty` 转发的 CubeShim。执行库同时上报 `guest_terminal` 和 `guest_terminal_persistent`；缺少任一能力时不开放入口。已有实例继续使用启动时绑定的 Shim，需按保盘流程切换运行栈；仅替换磁盘二进制不会更新正在运行的 Shim。创建 Shell 时会验证两组 Guest 实际窗口尺寸，拒绝窗口调整未生效的运行栈。

终端要求当前独立版本 `x-brocade-terminal-version: 2`，缺失或不匹配时拒绝连接。Agent 使用 `/agent/v1/cvm/terminal/policy` 读取本节点策略和撤销版本。Shim 的本机套接字及 FIFO 位于 `/run/brocade-cvm-terminals/`，目录权限 0700、套接字 0600，并校验对端 UID；不对网络开放。

每个节点最多保留 **3 个存活 Shell 会话**，不同实例的 Shim 通过节点级文件锁共同执行限额。**不设置操作者维度的数量限制**。每会话最多保存 **4 MiB 已滚出的格式化历史字节**，超过后按完整行淘汰最旧内容；收到 Guest 退出回执后，在最终输出交付、分离或最多 30 秒的尾部交付等待结束时清理历史并释放名额。仅收到终止信号的确认或本机缓存的退出码不足以释放名额。浏览器滚动回看最多 3,000 行。当前画面、备用屏幕和连接队列另有边界，4 MiB 不是整个进程的内存上限。输出按浏览器渲染完成后的字节 ACK 限速；持续输出不会重新开始尚未完成的历史回放，慢连接在回放完成后可只同步最新画面，不积压无限输出。调整普通终端窗口大小时会保留长行、颜色和光标，并重排软换行。Shell 内运行的程序仍占用实例自身的 CPU 和内存。

会话不因无人输入自动过期。关闭窗口、刷新、网络断开、Console 或宿主 Agent 重启只分离连接；实例及 Shim 仍存活时，重新打开默认恢复本人最近的会话，保留 Shell PID、变量、工作目录和终端画面。标签可切换会话，“新建”创建独立 Shell；操作菜单中的“结束会话”经确认后结束 Shell 并释放名额。停机、实例重启、重装、删除、Shim 退出或宿主重启会结束该运行身份的会话；历史仅存内存，不跨这些边界恢复。

连接票据绑定操作者、实例、节点和运行身份，30 秒内一次使用。Console 的临时连接最多每节点 6 条、每进程 128 条，允许旧连接与新连接短暂交接；这些传输保护不增加节点的 3 个 Shell 名额。若 Guest 清理未确认，Shim 保留名额并拒绝恢复该会话，需完成实例重启或销毁后重试。连接最长两小时，届时可重新连接原 Shell。登录失效或权限撤销会关闭页面连接；该连接关闭不等同于结束后台 Shell。运行连接每两秒复核权限与实例身份，不重放输入。Console 日志记录签发、连接结束及对象身份，默认不记录键盘输入、命令正文或终端输出。

点击“终端”打开普通的新浏览器页面，不请求带指定尺寸或位置的弹出窗口；浏览器可按用户设置把它显示为新标签页。同一实例重复点击会聚焦已有页面；新页面被浏览器拦截时显示手动打开入口。桌面终端铺满页面，会话标签以右上浮动胶囊显示，输入时变淡，悬停或键盘聚焦时恢复。手机使用可横向滚动的顶部标签和底部按键条。终端页面独立于控制台当前选中的实例；关闭页面不结束 Shell，仅有未发送的输入框草稿时提示离开。

支持中文输入、Ctrl-C、Tab、Escape 和终端尺寸调整。Escape 留给终端程序，Ctrl+Shift+Escape 或菜单中的“关闭页面，保留会话”分离连接。双击标签或菜单重命名会话，名称仅保存在当前浏览器并按操作者和实例隔离；标签上的 × 经就地确认后结束对应 Shell。已访问会话保留连接，后台实际收到新输出时显示蓝点；未连接会话不推测输出。连接丢失后按有界退避尝试恢复同一 Shell，保留画面且不重放输入；明确服务端拒绝时保留错误并提供手动重试。实例状态刷新临时失败时保留终端画面并提示错误；明确的身份或权限拒绝会分离终端。

“⋯”菜单集中显示连接信息、粘贴、命令输入框、查找、复制记录、全屏、终端设置、导出和结束会话。连接信息对缺失的观测显示“未上报”。查找支持大小写、全词和正则表达式。命令输入框浮在右下角，不改变终端行列数，Ctrl+Enter 发送；每次最多 32 KiB，按 UTF-8 字节计算。HTTP 或剪贴板权限被拒时，“粘贴”自动打开同一个输入框，允许使用系统键盘粘贴。

默认选中即复制，有选区时 Ctrl+C 复制、无选区时中断；可在设置中关闭这两项。Ctrl+Shift+C／V（Mac 可用 ⌘C／V）用于复制／粘贴，Ctrl+Shift+F 查找。复制去掉行尾空格、保留硬换行并拼接软换行；复制记录最多十项、每项最多 256 KiB，仅保存在当前窗口内存，不写浏览器存储；更大的复制正常完成，但提示未加入记录。右键菜单提供选区、全选、编辑、导出及仅清空本地画面的操作；程序接管鼠标时提示按 Shift 选择。已结束或断开的终端仍可选择、复制和导出。

多行粘贴使用终端原生 bracketed paste 行为，程序未启用括号粘贴时先确认，避免换行直接执行。单行、已启用括号粘贴的输入不弹确认；切换连接后不会把旧的剪贴板读取结果、粘贴确认或命令草稿误发到新会话。手机按键条包含 Ctrl／Alt 一次按键锁定和方向键，右侧固定选择、粘贴、输入框；选择模式提供普通可选文字和系统选择手柄。屏幕阅读器可在设置中开启“辅助阅读”。

反向代理需保留浏览器 Host，并支持管理面 `/cvm/{id}/terminal/{session}/stream`、Agent 面 `/agent/v1/cvm/terminal/control` 和 `/agent/v1/cvm/terminal/{session}/stream` 的 WebSocket 升级；生产入口使用 HTTPS／WSS。同源校验拒绝跨站借用登录 Cookie，票据只在首个 WebSocket 消息发送，不放入 URL。多 Console 进程仍需把同一节点的控制连接、管理请求和数据连接路由到同一进程；重新建立连接后才能恢复 Shim 中的 Shell。

支持 WebRTC 的节点可在终端菜单“尝试直连”，成功后终端数据直接在浏览器与宿主间传输，Console WSS 保留鉴权与续租；穿透失败使用原有 Console 转发。稳定会话不自动迁移，直连故障恢复原 Shell 时不重放输入。首次选择、5 秒续租截止、Cloudflare 公共 STUN 与节点 UDP 配置见 [WebRTC 直连部署](terminal-webrtc.md)。直连 WSS 入口暂未实现。

## 自动登录密码

创建和重装由 Store 使用系统随机源生成每实例独立的 32 字符密码，用户无需填写。失败重试复用同一请求和密码版本；正常启停与重启不更换密码。管理员可在“实例更多操作”中选择“重置登录密码”，保留系统盘并生成新密码，等待发布后生效。

密码使用 `BROCADE_SECRET_KEY` 加密保存，AEAD 上下文绑定实例和凭据版本；未配置密钥时明确拒绝创建，不降级为明文保存。实例规格和 `guest/init.json` 仅保存凭据版本，不包含明文密码。节点经独立鉴权接口取得已批准版本，在私有目录中缓存并幂等初始化 Guest，更新 `cube` 账号密码、启用 SSH 密码认证并移除原有 `cube` 用户公钥。SSH 主机密钥仍由系统独立生成。

管理员及获授权用户在详情“连接”中点击“查看登录密码”，可以复制并重新隐藏；密码不会随列表或普通详情返回。接口为 `GET /cvm/{id}/credential`，响应为 `no-store`；只有对应配置已发布且运行中的 Guest 已确认执行后才提供密码，停机时须先开机。只读角色、访客和其他用户不能读取。节点接口 `/agent/v1/cvm/{id}/credential?revision=N` 只允许所属节点获取已批准的运行实例版本。

数据库结构通过新增的 `0009_cvm_instance_access_and_passwords.sql` 升级，不修改已发布的 0001–0008 迁移或其校验值。`0009` 是容器数据模型的破坏性边界：升级会删除此前的实例、网络、入口、终端、观测、产物和发布映射，不转换旧规格、归属、资源账本或密码；机器、用户、普通配置和其它非容器数据不受影响。升级前必须保留数据库备份。裸机沿用原有系统账号，不通过此流程修改宿主密码。

## 宿主网络容量保护

宿主的全部容器共享自动管理的连接状态预算，管理主网卡与业务网卡一并纳入，不再按用户分配连接额度，也没有用户额度试算或编辑页面。Store 根据宿主上报的物理内存预算、固定开销和系统保留生成一个宿主分组；Agent 在创建 TAP 前下发对应实例归属，CubeVS 执行有界连接表及新建速率保护。

逻辑 Guest 内存不抵扣网络状态表预算。地址池、端口、网卡槽位、网络服务自身的限速和月流量策略继续独立生效；线路出口仍消费当前使用者已有的线路授权和流量策略。节点的已报告网络状态尚未清理时，基础版切换与节点删除保护仍会拒绝放弃资源。

## 实例编译产物

容器配置和普通机器配置共用全局修订号 `R`，在同一张配置发布单里按机器混合展示。
保存创建、改配、启停、重启、重装、删除、网卡、路由与入口变更时，在资源事务内冻结配置并生成全局修订；
实例 generation、operation_id 和网络执行代仅用于精确核对回执，不是另一套发布版本。
顶部变更条显示待发布的全局修订。有发布权限的操作者可通过“查看发布计划”进入统一发布页预览和批准。

发布沿用已有波次、确认、暂停、取消与重试。同一批机器执行容器发布期间，新的容器配置保存会明确要求先完成或取消当前发布单；相同请求的幂等重放和原操作重试继续可用。节点先领取可执行波次并回报普通机器配置，
控制面才开放该节点本次批准的容器、网卡承载和入口配置；预览和保存不会提前下发。
同一目标必须等机器配置、容器和关联网络回执全部成功，才能推进后续波次。
跨宿主承载或入口的两端在同一波执行；容器启停或重启影响入口目标时，入口机器也进入这张发布单。
较新的未批准规格不会覆盖当前已发布的期望；旧发布代仍可上报，但不能把新规格标为成功或释放其预约。
授权撤销与流量配额继续按运行时安全策略阻断；它们不会因此提前授予新访问。
待发布的删除或承载变更不会停止当前已发布网卡的流量计量；同一实例存在待发布变更时，月额度恢复仍更新正在运行的配置，并保留草稿的启停和网络意图。运行态执行代与草稿执行代分别保存，后续批准继续使用更新后的草稿，不回放旧执行代。删除成功的实例即使已退出期望集合，发布历史仍保留其终态回执。
实例物理删除成功后，网络清理期间到达的末笔累计流量只更新计量，不再创建实例执行代。承载切换发生回退后，后续额度或授权执行代继续保留原发布的失败判定；取消旧发布后，可通过新的补偿修订恢复发布。

网卡配置清空后，Agent 仍须上报新执行代的空回执，供发布单确认清理完成。Console 与容器版 Agent 必须使用当前执行契约。

首次配置修改采用升级前的现有运行意图作为基线，不因升级 Console 自动重启或清除旧实例。
容器期望状态统一下发编译产物，由当前 Console 与 Agent 配套执行；不保留原规格下发或执行分支。统一发布屏障由控制面执行。原文按展开的容器文件读取，历史发布保留冻结的目标与摘要。
隔离中的机器允许通过完整范围的容器发布同步修复配置，仍按原有波次、确认和真实资源回执推进；不会自动恢复服务。新修复单取代旧失败债务，但在机器、容器和关联网络均确认前保留恢复屏障。作用域外的关联机器仍须由具备完整权限的管理员一并发布，不能拆开关联两端。
顶部“待发布”列表的“撤回”按最新实例版本创建恢复修订。恢复范围限于该实例已发布的规格及待发布变更涉及的网卡和入口预约。撤回尚未发布的创建会释放本次预约。重复请求沿用原请求身份，过期版本会被拒绝。
路由、DNS 和出口网络的配置错误使用中文说明，格式错误也返回统一 JSON 错误，保留原 HTTP 状态码。
关联发布单活动期间先取消发布，再核对可撤回范围；任一关联机器已经收到本次配置时拒绝直接撤回。恢复修订保存后继续通过统一发布核对节点回执。容器删除、重装已经清盘时旧数据无法恢复。
涉及容器资源的发布计划提供容器变更管理入口，混合发布详情提供取消发布；历史回滚、整体丢弃或旧执行代重发仍受资源保护。取消后已收到配置的节点继续收敛，实际状态以回执为准。

`brocade-cvm-compile` 是只在 CVM 依赖闭包中使用的纯编译器：以冻结规格、原始镜像清单、
宿主能力快照和编译器版本为输入，确定性地产生四份原生产物。
管理主网卡按宿主接入来源目录校验；业务网卡按 Store 的发布分配、宿主管理网卡能力及总槽位上限校验。

| 文件                    | 应用方式                                     | Agent 本机绑定        |
| ----------------------- | -------------------------------------------- | --------------------- |
| `cube/sandbox.json`     | 关机改配后创建；产物自身摘要写入运行对象标签 | 原盘对象名、Shim 版本 |
| `cube/egress.json`      | 主网卡出网策略热更新                         | 无                    |
| `cube/attachments.json` | 网卡、路由和 DNS 热收敛                      | 运行时 ID             |
| `guest/init.json`       | 启动身份的一部分，由固定 Guest 执行器应用    | 无                    |

沙箱文件不包含出网策略或整份规格摘要；只改路由不会改变沙箱产物。代号、路由修订、
清理附件名单和规格标签由冻结期望的元数据填入原生请求，不成为文件内容的一部分。
本机绑定只允许上述固定字段，不能覆盖任意 JSON 路径。Guest 声明不能携带任意脚本、用户或路径。

Agent 先上报 `artifact_compiler` 和 `cube_storage_backend`。
Console 在 inventory 回应中列出缺失的镜像清单摘要；Agent 只上传 Console 缺少的清单。
服务端校验原始 UTF-8 字节的 SHA-256、2 MiB 大小上限、原生 protobuf 形状和节点的镜像目录归属，
按摘要不可变保存。每次冻结新规格时，在同一事务中保存输入快照和四份内容、摘要。
无法验证清单时，新操作整体回滚，不留下资源预约或半份产物。
已经冻结的历史代不会因为能力或编译器升级被改写；不支持当前编译产物的节点需要先升级 Agent，才能提交新的容器运行操作。

实例详情的「产物」页按需加载当前代和上一代的文件，可查看变化、全文、完整输入承诺、镜像清单、能力快照、编译摘要、本机绑定和已确认的生效摘要。
接口为 `GET /cvm/{id}/artifacts?generation=N`，继承实例的租户及用户权限；脱敏只读角色不能获取原始产物。
工作区列表不内嵌大块产物内容。产物回执必须对应该实例、该代实际保存的输入和文件摘要。

容器运行操作只消费 Console 下发的编译产物。Agent 使用冻结的镜像清单和本机执行器事实重编，
逐文件核对后再绑定执行；缺失产物、发现篡改、编译器不支持或本地事实不一致时，拒绝本轮运行操作，
在回执和产物页保留失败原因。没有模式开关或原规格执行入口。裸机实例不使用 Cube 产物。
绑定阶段在创建请求中安装该实例的初始出网策略；使用线路出口时先拒绝直连，路由防回落规则就绪后才放开。初始化失败时仍保留初始限制。
关机后修改资源、网卡和路由仍冻结产物并提供文件预览；停止、删除等清理操作不要求重新编译。

生效摘要覆盖实际交给执行器的绑定后 JSON，只有原生执行器确认后才返回。
沙箱保留实际创建时的生效摘要，热更新不会伪造一份新的创建回执；缺失匹配创建回执的运行时被明确拒绝接管。
停止和删除使用本机持久所有权记录及既有清理协议，不消费创建产物，也不会因旧清单损坏而阻止清理。
该摘要证明配置请求已被执行器确认，实际设备、Guest、系统盘和网络效果仍由原有观测与回执验证。

Guest 路由收敛会先等待主网卡地址完成 IPv6 重复地址检测，检测失败或超时会保留明确错误，
不会把暂定地址当作可用路由源。DNS 热更新使用 Guest 自有文件覆盖只读的 resolver 挂载，
重复应用不叠加挂载；清空 DNS 配置时恢复原内容。

宿主入口、隧道和网卡承载作为附属产物进入同一全局发布单：入口包含就绪与栅栏两份 nft 模板，隧道与承载包含已冻结的类型化配置，线路包含客户端配置、实际防回落 nft 和策略路由配置。密钥使用固定脱敏投影，原始内容摘要保持可核对；投递地址、实际监听端口与就绪状态等节点事实明确列为本机绑定。线路防回落规则按冻结字节执行并校验回执摘要；其他宿主执行域按冻结配置与这些显式绑定收敛。运行栈安装与 VMM 本机配置仍有各自的生命周期。

新协议的期望接口按游标分页，每页至多 8 个实例，序列化内容控制在 12 MiB 内，低于 Agent 的 16 MiB 接收上限。
回执按各自的实例和代校验；分页不是新的发布域。请求未带游标时也从第一页返回完整产物，不切换为无产物响应。
单份产物及产物包分别有大小上限，编译时即校验，避免保存后才发现无法下发。
