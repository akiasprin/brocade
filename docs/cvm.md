# CVM（CubeVM）

CVM 将系统、计算容量、系统盘和网络连接放在一个实例中管理，计算与网络分别组合：容器可以在任一宿主运行，访问入口与出网可以来自任意机器。导航使用“机器”“容器”“线路”。“容器”页分为“组合台”“宿主”“网络”，系统管理员还可进入“额度”页签。组合台按“访问入口 | 计算 | 出口”三栏展示，流量从左到右；宿主卡展示可见预留资源与节点可分配容量、能力状态和 WebShell 策略。界面中的“容器”是功能名称，执行后端仍为 Cube/KVM。入站由独立的访问入口承担，出网由可复用的出口网络、容器网卡和独立路由表管理；用户端口转发在用户详情中单独配置。

机器运行状态的“扩展应用”显示 **CUBE** 扩展，与 OPENVPN 并列。CUBE 是可选扩展；只有已确认过 Cube 运行栈或仍有保留实例的机器，才判定其运行健康。未纳管的普通机器显示灰色“未启用”，缺少可选配置不会显示配置不一致或异常；已纳管机器则按实际上报区分已启用、能力异常、报告过期和未上报。此处只展示运行栈状态，不以安装选项或 Agent 协议版本推断已经安装。

节点已上报运行模式时，标签显示 **CUBE[KVM]** 或 **CUBE[PVM]**；其他 Cube 后端保留实际上报的名称。未启用或未明确上报模式时只显示 **CUBE**，不根据宿主内核或实例期望猜测模式。

## 当前实现范围

| 能力 | 当前行为 |
| --- | --- |
| WebShell | CubeShim 管理持久 Guest PTY，支持重连、会话切换、窗口调整和粘贴；在“宿主”页签的每台宿主卡上开关访问 |
| 实例管理 | 创建分配、不可变规格、开机、关机、重启、重装、关机改配、删除和失败重试 |
| 系统与容量 | 镜像与资源独立；CPU、内存和系统盘容量分别选择，磁盘按精确字节分配 |
| 网卡挂载 | 创建时仅生成管理主网卡，创建后消费已授权的可复用网卡；热挂卸和槽位由宿主实测能力控制 |
| Cube 运行栈 | Agent 内置 Rust 执行库对接 Cubelet；一张原生主网卡加最多两张真实副网卡，支持运行中热挂卸；XFS/reflink 与 ext4/plain 均支持受保护的持久系统盘 |
| 原盘开机／关机 | 安装 protected-root-v1 扩展后，关机保留原盘和地址分配，开机按原物理对象恢复 |
| 访问入口 | 任意机器的 IPv4 地址按整 IP（L3）或协议端口（L4）投递到容器主网卡，不占网卡槽位；可在同一用户的容器间改派 |
| 出口网络 | 只承担出网的 IP 层网卡，支持 Xray／WireGuard、共享 NAT、独立路由地址和一对一 NAT，双栈 |
| 路由表 | 匹配 IP／网段（L3），或协议加目的端口（L4）；网段越具体越优先，同网段端口规则优先，再按每地址族网卡优先级选择；故障不换卡 |

Cube 的原生主网卡由 Cube 管理，保留管理联络，并默认通过宿主机 NAT 访问公网，优先级最低。业务网卡的 ID、MAC、地址和资源归属由 Store 统一分配；Cubelet 接收分配结果，创建真实 TAP 和 virtio-net 设备并核查 Guest 状态。当前 Cube 实测上限为三张，包含管理主网卡；同一网络可反复挂载，每次得到独立设备与分配，不按来源数量限制槽位。通用模型最多表达 16 张，具体机器仍按实际上报容量准入。

网卡不再提供入站：访问入口取代了网卡入站方向、入站来源与共享地址端口映射。首发数据库与扩展切换见[产品变体与数据库](#产品变体与数据库)。数据库历史严格校验，不能修改 SQLx 回执绕过检查。

## 页面与读数

组合台左列是各机器发布的入口地址：共享地址列出已占用的协议端口和“＋ 端口”，独立地址显示整 IP 空闲或已分配；中列是宿主及其容器；右列是出口网络。把入口行右侧的线头拖到容器上即可改派，拖空闲行即可新增；把容器右侧的端口拖到出口即可新增出口规则，选中容器后拖出口线上的把手即可更换出口。也可以在右侧检查器点“＋ 入口”“＋ 出口”，再点目标。改动先画成虚线，在检查器确认后提交；检查器同时显示选中容器的入口与出口状态、本机出口及 CPU／内存／系统盘读数。窄屏按宿主分组列出容器的入口与出口，点容器进入详情。首版不迁移计算，容器不能拖到别的宿主。

实例详情分为“概览”“网络”“监控与诊断”。概览显示运行、连接、网卡、规格及最近事件，存储与任务信息可从规格卡展开；网络页依次展示访问入口、出口网卡和路由表，提供撤销入口、更换承载和应用规格等操作。监控页显示时间范围、连接健康和四张曲线卡，详细诊断按卡展开。返回列表使用顶栏的“容器”导航。访客与只读账号保留脱敏信息浏览，不显示创建、生命周期、网络写操作或终端按钮。

组合台与检查器通过 `GET /cvm/readings` 批量读取当前可见实例的最近观测。作用域与 `/cvm` 一致，最多 512 个实例，每实例最多 60 个近一小时的分钟历史点；不逐卡请求详情监控。最新采样与运行健康均在 120 秒以内才展示实时读数。过期、停机、缺失或请求失败显示 `—`；历史采样间断时曲线断开，不能将缺失解释为零。

“当前”表示全部已挂载网卡的 Guest 视角收发速率合计；“本月”表示当前业务网卡按 UTC 自然月记录的消费侧上传与下载计量，管理主网卡 NAT 不在该月度计量中。尚未收到完整计量时显示 `—`，有计量缺口时标记 `*`；悬停可查看口径及最后计量时间。混合有限额与不限额网卡时不显示汇总额度上限。

创建配置器右侧实时显示新实例规格，以及创建后的用户额度占用；条纹表示本次新增量。额度读数来自服务端准入所用的持久记录，包含计算释放后仍未释放的系统盘及待清理网卡。宿主卡的占用仅表示当前可见的预留实例，不代表整机物理用量。额度与宿主容量仍由服务端在提交时再次校验。

## 镜像与规格

系统镜像描述运行什么系统，资源数值描述分配多少容量。系统盘容量属于实例资源；镜像与系统模板不设置硬盘大小，也不按内存划分。Cube 的内存快照属于实例恢复点，不能作为绑定某个硬件规格的通用系统镜像。Rust 执行库拒绝包含容量或内存快照参数的系统启动清单。

## 使用

管理员先在承载机器配置执行服务，再到 “容器 → 额度”授权用户使用相应机器，分配实例、vCPU、内存、系统盘和网卡总额。机器授权包含其公开的 CVM 接入来源，目录应只发布允许该使用范围访问的连接。普通用户只能查看和操作自己的实例；租户管理员只能管理其作用域内的实例；系统管理员分配额度；其他管理角色只读。

开启访客模式后，未登录的访问者也可从“容器”查看可见范围内的实例、宿主及监控与诊断。访客沿用只读响应脱敏，隐藏 SSH 公钥、运行时和系统盘标识、实例接入地址及网卡地址；不能创建或变更实例、发布服务、管理额度或连接 WebShell。访问仍受访客开关和可见范围约束，关闭访客模式后后续匿名请求立即被拒绝。手机主导航包含“容器”，“用量”可从账户与更多功能菜单进入。

创建时按下列顺序选择：

1. 名称、使用用户和承载机器。
2. 系统镜像及其版本。
3. 分别选择 CPU 核数、内存和系统盘容量；范围与步长由承载机器上报。
4. 核对独立管理主网卡，业务网卡在创建后挂载。
5. SSH 公钥。机器未提供的执行能力会明确显示为不可用。

## 出口网络、挂载与路由

以 A 表示容器、H 表示运行 A 的机器、B 表示提供网络的机器。B 创建网络 P，A 挂载后得到自己的网卡 N，再由 A 的路由表 R 选择哪些目标走 N。B 与 H 可以是同一台机器；B 只需具备网络执行能力，不要求具备 KVM 计算容量。

管理员在“网络”选择 B，填写地址池、地址族、可达的 IP／网段、初始路由、可选 DNS 建议和限速／流量额度，并授权使用者。地址池可以复用，同一资源域统一检查地址占用；不同隔离资源域可以使用重叠私网，但同一容器内地址不能重复。三种地址模式分别为：

- **共享 NAT**：多个 N 共享出口地址；没有固定共享地址时，由 B 按实际路由选择 NAT 地址。
- **独立路由地址**：地址直接配置在 Guest；B 必须实际具备对应上游路由或邻居代理条件。
- **独立一对一 NAT**：Guest 地址和独立对外地址分别展示，不把 NAT 公网地址当作 Guest 已配置地址。

N 只承担出网：容器主动建立的连接及其回包经 N 和 B 往返，新的入站连接一律不经 N；需要入站时为容器添加[访问入口](#访问入口)。路由表不能扩大 P 的授权，不提供 NAT64 或透明二层延伸。

出入对称：容器在 B 上同时拥有整 IP 入口时，经 B 的 NAT 出口网卡出网的 IPv4 源地址改用该入口地址；路由独立地址模式下 Guest 本身就使用公网地址，不受影响。

容器在“网卡与路由”中挂载已授权的 P，选择双方实际支持的 Xray／WireGuard 承载交集。创建独立网卡不会创建另一份计算实例。可手动更换承载，N 的 ID、MAC、地址分配和 R 引用保留；切换可能中断连接。新承载未启用时失败仍使用原承载，启用后失败尝试恢复原承载；原承载也不可用时保持不可达。

Xray 当前使用独立的 VLESS Reverse／TLS 进程封装和认证原始 IP 包，WireGuard 使用原生内核 IP-over-UDP。两者使用每个 N 的隔离上下文、独立凭据和有界缓冲，不改主 Xray 配置或代理授权。默认由 H 连接 B；发布规格也可选择由 B 连接 H，监听方必须提供实际可达的端点和端口。两族业务可共用一个外层地址族。

R 独立保存目标 IP／网段、可选的协议与目的端口段（L4，例如 `tcp/22`、`udp/1000-2000`）、各地址族网卡优先级和 DNS。全路由分别用 `0.0.0.0/0`、`::/0` 表达。先选最长前缀；同一前缀上带协议端口的规则优先于不带的规则；再按较小的网卡优先级选择，最后选更窄的端口段。相同前缀和优先级、端口段重叠却指向不同 N 时拒绝保存。L4 规则需要宿主 Agent 上报 `route_service`、Cubelet 上报 `route_services`：Guest 内按协议端口写策略路由，宿主按同一顺序放行或丢弃，选给另一张网卡的流量不会从这张网卡出网。未匹配业务路由时，流量使用优先级最低的主网卡，经宿主机 NAT 出网；选中的 N 故障时保持不可达，不回落到其他网卡或主网卡。宿主同时约束实际 IP 流量，Guest 绑定源地址不能绕开 R。

P 的初始路由仅用于挂载初始化，之后由容器管理；P 新版本不覆盖 R。DNS 建议只有明确勾选后才应用，容器 DNS 仍可单独配置，解析流量遵循 R。

P 的修改创建不可变新版本。新挂载使用最新版本，已有 N 固定原版本，使用者显式应用新规格；管理员可在发布页查看派生网卡及删除依赖，并批量应用保留地址与当前承载的兼容规格。同一容器内的多卡更新一次性保存，任一校验失败会全部拒绝。原地址满足新规格时保留；需要换地址时必须先关机、处理路由／入站依赖并明确允许重新分配。新旧分配分别保留清理证据，不静默改变入口。停止新挂载不影响已有 N 的通信、重连和恢复；撤销授权则阻断已有 N，保留身份、分配与 R，离线端显示待执行。

普通卸载必须先移除路由和优先级引用。正常删除 P 要先处理派生 N 并等待清理。B 退役是明确例外：直接删除其发布和网卡引用、删除相应 R 引用，剩余路由可以重新匹配；逻辑删除不等待 B 上线，未知物理资源仍保留占用证据。

上下行限速和 UTC 月流量额度可选。业务 IP 字节在 H 的 N 边界计量一次，包括 IP 头和业务重传，不重复累加两端或外层隧道重传；外层承载开销单独观测。计数器重置或跨月采样缺口明确标记。超额阻断 N，不触发换卡；管理联络保留。额度和用量不复用代理转发授权。

## 访问入口

管理员在“网络”页签的“访问入口地址”按机器发布地址并授权使用者：

- **共享地址**按协议端口分给多个容器，必须是机器网卡上的实际地址；宿主正在监听的端口、代理与组网保留端口、用户端口转发和网卡承载端口都不会分配。
- **独立地址**整 IP 交给一个容器，包含全部协议与 ICMP；不能是机器的管理地址或出口网络的共享出网地址，上游须把它路由到这台机器。
- 云厂商一对一 NAT 时填写“对外地址”：机器上匹配内网地址，界面与 SSH 命令展示公网地址。
- 同一机器的地址只能出现在一份发布中。授权实时生效：撤销后已有入口保留地址与端口但停止转发。

容器的入口在组合台新增、改派或撤销。入口属于容器：删除容器时随之撤销；改派只改投递目标，地址与端口不变，只能在同一用户的容器之间进行。撤销后地址与端口保留到入口机器回报不再包含它的版本，才供他人使用。每份发布、每个容器（64 条）、每台机器（4096 条）都有入口上限。

数据面：入口机器把目的地址换成容器的宿主内地址。容器在别的宿主时，按每对机器共用一条的 WireGuard 通道送达：入口机器监听发布中的通道端口，宿主主动连接，可以位于 NAT 后。通道在第一条入口时建立、最后一条撤销时收回，端口与槽位在两端确认清理后释放。宿主把来源换成 Cube 网关地址，经 CubeVS `primary_delivery` 交给容器主网卡，回包沿原路返回。

Guest 看到的来源是宿主网关，不保留访问者原始 IP。Cube 主网卡只有 IPv4，首版入口只支持 IPv4 地址。通道使用槽位派生的 E 类地址 240.0.0.0/15（只在两端之间，不会离开通道），入口机器另用包标记与路由表 `0xb60000` 加槽位、规则优先级 31700，不修改宿主默认路由。容器未运行、授权撤销或通道未就绪时，入口机器仍占住地址与端口并丢弃新连接，不会落到宿主服务。

前提：入口机器和容器宿主的 Agent 上报 `entries`（协议 67，需要 nftables、iproute2、`wg` 与 WireGuard 内核模块，并开启 IPv4 转发）；容器宿主的运行栈上报 `primary_ip_delivery`。宿主若有其他防火墙丢弃转发流量或通道 UDP 端口，需要放行。组合台与详情页按节点回报分别显示“生效中”“已生效”“执行失败”“机器离线”“授权已撤销”“容器未运行”“撤销中”，不能从配置受理推导连通。

## 状态与恢复

HTTP 请求受理只表示分配和操作已保存，界面显示“待执行”。设备地址是 Guest 内的地址，实例接入地址是承载机器投递到该实例的地址；映射后端中二者可能不同，不能互相冒充。

“运行中”需要对应实例、操作、规格版本、运行时、系统盘和 Guest 网卡的实际回执。副网卡还需要主网卡路由、默认业务出口、无匹配路由时的主网卡 NAT 路径以及已选中业务路由故障时禁止回落的观测证据。

通信中断或原运行时丢失时先核查原对象。支持原盘恢复的后端会重新使用同一个物理系统盘；原盘缺失或身份不符时显示“待核查”，不以新空盘替代。重试沿用原操作身份。过期回执不能覆盖新规格；机器能力报告超过 150 秒或包含错误时，暂停创建、启动和网卡变更，保留已有分配。仍可提交删除或核查原任务；能力观测失败时保留上次有效的删除与保盘能力，Agent 继续尝试清理已归属的实例。

关机保留数据。点击实例详情的“删除”直接提交完整删除，不要求输入实例名称，也不询问备份或保留系统盘。删除会销毁系统盘数据、清除实例路由、撤销访问入口并卸载网卡，无法恢复。请求受理后显示“待执行”，运行时、网络和系统盘清理确认前，分配仍被占用。整实例删除可覆盖尚未确认的网卡卸载，以完整网络清理回执确认全部网卡释放。

卸载副网卡先停止该地址的业务路由，再请求真实设备移除；Guest MAC、Hypervisor 设备、宿主 TAP 及对应 CubeVS 端点策略均清理确认后，才释放网卡分配。网卡挂卸只改变网络规格，不改变最初的运行时、系统镜像、CPU、内存或系统盘身份。已确认删除实例的地址分配可重用；结果不明的对象继续占用原地址。

承载机器仍有实例或系统盘占用时不能退役。已清理实例的执行历史仍引用机器身份，机器可以保留退役记录，不能直接移除审计所依赖的机器行。

只取消容器宿主身份时，系统管理员在“宿主”页点击对应卡片的“移除宿主”。先删除该宿主上的全部实例，等待系统盘、网卡和访问入口清理完成。移除后不再显示为容器宿主，也不能继续创建实例；机器及其代理、组网、出口网卡发布等其他功能保留，不卸载 Cube 运行栈。Console 独立保存这一决定，Agent 后续上报不会自动恢复宿主身份。需要恢复时，在宿主页顶部的“添加宿主”选择该机器；原有用户额度与授权保留。

## 节点执行与配置

Console 和 Agent 通过 `brocade-deployment::cvm` 的共享契约交换期望状态。Agent 内的 `brocade-cube` Rust 库直接通过 Unix socket 调用 Cubelet 的 gRPC／Tasks 接口，执行和核查实例、原盘与网卡，并提供 Guest 观测和 PTY。用户、认证、配额、不可变规格及操作仍由 Console／Store 管理；Cubelet、Shim 与 CubeVS 保存实际执行状态。

Rust 对接库随 Agent 一起编译和分发，Cube 运行栈是独立的可选安装与发布域。所有 CVM 功能采用统一版本门槛；关机卸载由 Console 下发稳定清理 ID，Cubelet 证明设备和租约已清理后，Agent 才完成回执。缺少实际证明时保留分配和待确认状态。先升级 Console，准备匹配的 Agent 二进制，激活对应 Cubelet／Shim 后再重启 Agent。普通 Agent 更新不会隐式替换 Cube 运行栈。

在 **Agent 服务环境**设置：

- `BROCADE_CVM_CONFIG`：私有 Cube 配置的绝对路径，默认 `/etc/brocade/cvm-cube.json`。
- `BROCADE_CVM_STATE_DIR`：持久执行记录的绝对目录，默认 `/var/lib/brocade/cvm-cube`。


这些变量不属于 Console 环境。配置结构见 [配置示例](../crates/brocade-cube/examples/cvm-cube.example.json)。托管安装使用 `/opt/brocade/cvm/current/generated/cube.json`，由 Rust 客户端直接读取。更改配置后重启 Agent。

私有配置的 `capabilities` 只描述管理员选择的执行策略、容量、资源范围、系统镜像与网络来源目录。`backend`、`guest_terminal`、`configure_network` 和 `primary_ip_delivery` 由执行器及 Cubelet 实际能力生成，不属于配置输入；WebShell 访问开关由 Console 管理。持久系统盘的能力核查要求 Cubelet 明确上报与配置一致的存储后端。

配置必须由 Agent 的有效 UID 持有、权限为 `0600`。镜像清单同样由该 UID 持有且禁止组或其他用户写入，`image.sha256` 固定其原始字节。清单只描述系统制品、组件版本和启动方式；CPU、内存与系统盘大小来自实例的不可变规格。包含容量或内存快照绑定的系统清单会被拒绝。

`cubelet_socket` 必须是本机绝对路径；客户端核对 socket、所在目录及 Unix peer 的身份。兼容 Cubelet 的 `0660` socket，禁止其他用户写入，目录不能被组或其他用户替换。`network_inspection_url` 仅接受字面 loopback IP 的 `/v1/network/taps`，不跟随重定向。RPC 和检查响应均有期限与长度上限。

可在不读取 Console 凭据、不认领执行记录或执行实例操作的情况下检查能力：

```sh
brocade-agent cvm-check --config /etc/brocade/cvm-cube.json
```

计算与网络能力目录、构建和节点前提见 [Cube 节点运行栈](cube-runtime.md)。Cubelet 私有网络配置示例见 [cube-networks.example.json](../crates/brocade-cube/examples/cube-networks.example.json)。地址池及网卡授权在 Console 发布，实际设备容量由 Cubelet 上报；B 的地址归属与上游路由由管理员保证。

执行任务串行收敛，待执行队列最多 256 个实例；同一实例的新规格合并到原排队位置，重复轮询不追加任务。每机最多保存 8192 条、每条最多 32 KiB 的私有执行记录。意图和回执通过 `fsync`、原子替换和 `0600` 保存。创建结果不明时按冻结归属核查，不能再次分配空盘。观测使用独立的有界调度与缓存，失败不完成生命周期操作。

## 网络执行前提

网卡与访问入口契约要求 Console／Agent 协议 67、`cubevs-attachments-v2` 及实际 `managed_networks` 能力；协议 66 及更早的 Agent 不领取网卡与入口的期望状态，界面显示需要升级。B／H 需要 Linux 网络管理权限、iproute2（含 tc／ss）、nftables、conntrack 和可用的 IP forwarding；WireGuard 另需内核支持与 `wg`，Xray 另需匹配的 Brocade Xray 和 `/dev/net/tun`。缺失能力明确拒绝挂载，不依赖旧 Agent 忽略未知字段。

Agent 自动收敛自己拥有的命名空间、bridge、路由、nftables 与邻居代理，保留宿主默认路由和其他服务；发生归属冲突时报错，不接管未知设备。使用 journald 日志命名空间等私有挂载视图时，网卡命名空间在宿主持有独立句柄；Agent 重启后沿同一身份接管，普通卸载在归属核查后释放两侧句柄。旧进程退出留下的空占位文件，只有归属记录匹配且旧设备已消失时才回收。B 的公网地址、实际端点连通性和上游路由仍须真实可用。节点控制中断时已有数据面继续收敛本地保存的意图，已分配的月额度由 H 的持久计量边界继续执行；跨 UTC 月重置不依赖 Console 在线。新分配与配置变更等待 Store。

网络执行器每轮连续处理全部有界承载，每八条上报一次，完成整轮后才等待下一次轮询；实际执行耗时仍会影响观测新鲜度。离线恢复先恢复保留资源的隔离规则，再逐卡收敛；单张网卡失败不阻止其他网卡恢复。即使承载已清理，只要资源仍等待释放确认，其隔离规则也继续恢复。

## 产品变体与数据库

CVM 是默认不安装的扩展能力。先按[安装与升级](install.md#产品变体与扩展切换)切换为 `cvm` Console；普通机器继续使用 `base` Agent。仅提供入口或出口网络的机器安装 `--agent-flavor cvm` 即可，不要求 Cube 或 KVM；计算宿主使用 `--enable-cvm`，同时安装容器 Agent 和经过校验的运行栈。

Agent 重装省略变体时保留已安装身份。发布更新默认保持变体；基础 Agent 升级为容器 Agent 必须显式批准。退回基础 Agent 需要先排空全部 CVM 资源、等待实际清理回执、停止 Agent，再以 `--agent-flavor base` 运行安装器。在线自更新不承担 CVM 降级；其执行进程持有资源锁，不能替代停机检查。

两种 Console 共用首发统一 schema。全新安装执行正常迁移；切换产品变体不删表、不改写 SQLx checksum、不重建普通数据。基础版会拒绝仍在使用或待清理的实例、卷、网卡、入口、地址端口与网络额度。实验 schema、旧 CVM 执行记录和中间协议不属于首发接管范围，已移除实验转换开关。

## 独立配置 CPU 与内存

创建实例时分别填写 CPU（核）、内存（MiB）和系统盘（GiB），不选择命名套餐。API 使用 `resources: {vcpus, memory_bytes, root_disk_bytes}`。机器通过可选的 `resource_limits` 上报各维度的最小值、最大值与内存／系统盘步长；Console 和 Rust 执行库分别校验，额度与机器总容量仍按实际数值分配。

独立数值直接保存于不可变实例规格的 `resources`，不包含套餐 ID 或名称。机器开放创建时必须提供 `resource_limits`；额度、机器总容量和步长均按实际数值校验。所有 CVM 功能共享同一版本门槛；先更新 Console，再安装匹配的 Agent 和 Cube 运行栈。

## 开机、关机、重启、改配与重装

详情在实例名称旁展示实际运行状态，正常运行时不重复展示“期望运行”。概览／网络／监控页签与实例操作位于同一工具栏，窄窗口下分行显示。开机／关机和重启直接可见；“更多操作”提供修改配置和重装系统。关机、开机、重启保留系统盘数据与网卡地址分配。CPU、内存及名称在确认关机后独立修改，额度按新配置原子校验，镜像不因此改变。当前不提供运行中热改 CPU／内存和系统盘缩容。

重装明确清空系统盘并重新初始化 SSH 身份；要求填写完整实例名称并确认数据清除。实例身份、CPU、内存、系统盘容量和网卡配置保留，可另选系统镜像与 SSH 公钥。重启和重装各有单调递增代次，重试或进程重启不会重复重启或再次清盘；回执必须包含对应完成代次。

关机后的重装同样先确认旧系统盘已物理删除，再启动新系统。执行记录单独保存已确认清盘的重装代次，启动回执丢失或恢复启动失败时继续使用本轮新盘，不重复清盘。

Cube 的默认 storage DB 位于临时状态目录，不能承担断电恢复登记。protected-root-v1 将受保护原盘的执行清单同步写入持久 DataPath 下的 `brocade-roots/`，文件及目录均 fsync。普通 GC、关机和失败清理不能删除受保护系统盘；只有明确删除数据或重装才允许删除。宿主重新启动后按清单与真实 CoW 对象恢复登记，沿原盘冷启动，并重新核对主网卡、副网卡、路由与隔离规则。缺失物理盘不会触发新盘分配。

持久清单损坏、物理对象缺失或归属不一致时保留分配并报错。Agent 重启后清除缓存的成功状态，重新核查实际运行结果。

## ext4 兼容边界

ext4/plain 使用同一份固定只读系统镜像，每个实例新建独立、足额预分配的可写文件盘，Guest 沿用 OverlayFS；创建不复制镜像，也不使用 reflink。与 XFS 相同地支持当前已开放的独立 CPU／内存／磁盘创建、原盘关机／开机／重启、关机改 CPU／内存／名称、明确清盘的重装、删除及重试、服务／宿主重启后的原盘恢复。网络、转发、监控与终端不依赖宿主文件系统类型。

plain 不实现磁盘或内存快照、克隆、暂停快照恢复、跨节点迁移、磁盘扩缩容及保留盘管理；这些也不属于当前 CVM 的公开能力。卷核查 API 仍保留，用于确认原盘与物理删除，不代表开放快照功能。

plain 的卷文件与目录仅服务 UID 可访问，池采用独占进程锁。分配在私有暂存目录完成后原子发布；删除先持久记录删除意图，再回收文件。启动会恢复未发布分配与未完成删除，遇到未知对象则拒绝接管。格式化完成后持久保存磁盘名称、容量和 inode 回执；恢复只认原盘。回执缺失／损坏、稀疏盘、路径或权限异常时停止使用该盘并保留分配，不自动格式化或补建替代盘。初始化过程中断且无法证明完成的盘需要管理员核查后处理。

新安装按宿主全部 CPU、实际物理内存及当前可用磁盘空间生成容量，不由安装器扣减固定或比例预留；额度由 Console 管理。plain 另在每次分配时检查可用空间并实际预分配，格式化使用 `nodiscard`。该模式创建较慢且立即占用分配容量，不具备 reflink 的共享空间收益。安装器将实际文件系统 UUID 固定在私有 `generated/storage.json`，启动与升级时核对；数据盘未挂载或文件系统改变时拒绝初始化替代池。升级保留原容量预算与后端身份；其他宿主程序占满磁盘仍会导致分配或写入失败，应监控共享文件系统空间。

本地存储配置 `local_backend = "plain"` 与 Rust 客户端 `storage_backend = "plain"` 必须一致，安装器自动生成；`plain_reserve_bytes` 默认 0，安装器不自行设置预留比例或固定空间；管理员显式配置的值在升级时保留。已建卷禁止通过改配置切换 XFS/plain，也不隐式迁移卷。节点包必须通过 `storage_backends` 明确声明支持范围；ext4 主机在停服务前拒绝激活不支持 plain 的版本。

## 安装与运行包

Agent 安装器支持 `--enable-cvm`，从控制面提供的架构清单获取并校验运行包及安装器。先安装包含 Rust Cube 客户端的 Agent，再安装 Cubelet、Shim／Hypervisor、CoW 和固定系统制品。安装器配置 Cubelet 服务及 Agent 的 CVM drop-in，校验实际运行进程与能力；首次纳管在消费纳管凭据之前完成制品和宿主预检，需要换核时保存待重启状态并继续普通 Agent 纳管。

小内存宿主可显式调整 `generated/cubelet.toml` 的预建池：`io.cubelet.internal.v1.cgroup` 下的 `pool_size = 50` 使用小型 cgroup 池，网络插件默认 `tap_init_num = 1`，预建 1 张空闲 TAP，其余按需创建；可设为 `0` 完全按需创建。模板的 3,000 个 cgroup 预建量可能耗尽 1GB 宿主内存。这是管理员的运行时缓存配置，不扣减可分配容量；升级保留该配置。

### 原生 KVM 与 PVM

新运行包支持 `auto`、`kvm`、`pvm` 三种节点模式。首次安装默认 `auto`，先加载并实际检查 KVM（包括创建一个无 vCPU、无内存的临时 VM）；没有可用原生 KVM 时准备 PVM。正在正常使用 PVM 的节点在 auto 下继续使用 PVM。后续安装省略模式时保留已保存的选择；可用 `--enable-cvm --cvm-mode auto|kvm|pvm` 显式修改。权限、I/O、包校验或其他系统错误不会被当作缺少 KVM 而自动换核。

PVM 通过专用宿主内核提供 KVM 接口，不需要云服务商向 VPS 暴露 VMX/SVM。运行包必须同时提供经过 SHA-256 核验的宿主内核 `.deb`、匹配的 PVM Guest 内核与配对元数据。Cubelet 的实际内核源和系统镜像内核缓存按虚拟化模式隔离，避免复用另一模式的 Guest 内核。选择 PVM 前会核对完整配对制品；仅给安装命令添加环境变量不能补齐内核。

运行包统一使用 `brocade-cvm-stack-v2`，每个包均包含固定的宿主模式管理程序。换核和激活前还要求 Agent 支持 `cvm-check --maintenance-contract`（输出 `brocade-cvm-maintenance-v1`），确保待重启期间的暂停实际生效。升级顺序为先 Agent，再使用匹配的新安装器与运行包。

自动准备宿主内核目前支持 x86_64 Debian/Ubuntu、GRUB 与 dpkg。安装器从系统生成的 GRUB 条目复制实际 root、initrd 与原启动参数，增加独立的原内核/PVM 条目；不改网卡命名或 IPv6 设置。PVM 所需的 `nopti pti=off no5lvl rt_group_sched=0` 参数只作用于 PVM 条目；后者关闭该内核的实时任务分组，使 cgroup v2 CPU 控制器可与 `multipathd` 等实时线程共存，不停止其他宿主服务或修改全局实时带宽上限。当前上游内核不支持 KPTI，这会改变宿主的侧信道防护边界，应在发布该内核配对前评估。其他系统可手动准备匹配内核后使用 PVM，但不宣称自动换核支持。

准备完成后返回退出码 **75（等待重启）**，不自动重启。普通 Agent 纳管仍完成，CVM 暂不分配实例；用户手动重启后，固定版本的 systemd 恢复程序会继续安装。首次仅单次启动新内核，核对实际内核、模块、启动参数、Cubelet 与能力后才设置后续默认。新内核不能启动时，下一次启动仍有原内核入口；机器已回到原内核时恢复程序撤销失败切换、恢复原配置。内核卡死时仍需要服务商控制台或人工重启，无法由未启动的系统自行恢复。

已安装节点可以使用：

```sh
sudo python3 /usr/local/lib/brocade/cvm-stack.py mode auto
sudo python3 /usr/local/lib/brocade/cvm-stack.py mode kvm
sudo python3 /usr/local/lib/brocade/cvm-stack.py mode pvm
sudo python3 /usr/local/lib/brocade/cvm-stack.py status
```

每次只执行需要的一种选择。显式 `kvm` 不会回退到 PVM；切回原生 KVM 仍需要 CPU 暴露 VMX/SVM。切换前必须清空该节点的 CVM 实例并确认清理；关机实例也不能直接跨模式启动。安装器短暂停止 Agent，以执行目录排他锁和实际 Cube 列表共同确认空节点，再让 Agent 的其他收敛域继续工作。原盘、系统制品与审计记录不会因模式选择被删除。

取消尚未完成的切换用 `sudo python3 /usr/local/lib/brocade/cvm-stack.py cancel-mode`。如果已经进入新内核，该命令先选回原启动项，需手动重启后再次取消/恢复；状态和失败证据保持可查。待切换状态位于 `/opt/brocade/cvm/host.json`，不要手动删除它来绕过暂停或恢复。

运行包保留不可变版本、摘要和兼容的持久状态 ABI。升级或回退保留仍被实例引用的系统制品及原执行记录；匹配的 Rust Agent 是前提。安装器启动 Cubelet 和 Agent，Agent 内的 Rust 库承担本机执行。未知安装来源或不兼容状态拒绝接管。手动构建、安装与恢复见 [Cube 节点运行栈](cube-runtime.md)。

## 连接入口

实例详情优先展示已生效的访问入口：指向 22 端口的 TCP 入口使用入口端口，整 IP 入口使用 22 端口，均以访问者使用的地址展示。生效中、撤权或容器未运行的入口不推荐为连接入口。没有可用入口时可使用实例终端；宿主内管理地址单独标注为“在宿主上执行”。当前 Guest 使用 `cube` 用户和创建时的 SSH 公钥。

“地址已分配”“Guest 设备已配置”“承载已连接”和服务可达性分别展示，不能从配置受理推导实际服务正常。修改、关机、离线和切换保留地址；卸载后须同时获得 Guest 设备与两端网络清理证据才释放。网络回收包括旧 nftables 规则、路由、邻居代理及连接跟踪，未知结果不会按超时重新分配。

## 实例监控

实例详情提供轻量的监控概览，以及独立“监控与诊断”页签。四类卡片按需展开：CPU 使用率、采样峰值、时间分项、每核读数、负载及压力；内存分类、Swap、重大缺页及 OOM；根文件系统空间、inode，以及能够可靠归属到根设备的 I/O、IOPS、等待与队列；逐网卡收发 bit/s、包速率、丢包、错误与 carrier，以及整个 Guest 的 TCP／UDP 计数。内核未提供的指标显示未知；根文件系统没有独立块设备映射时明确显示 I/O 不可用，不取宿主磁盘总计代替。

Rust 执行库通过本机 Cubelet 任务 API 执行固定只读命令，不依赖 SSH 私钥，也不安装额外 Guest 服务。监控独立于配置收敛、能力目录和八实例生命周期轮转。每机器最多 256 个对象，采样池并发 2–32，目标周期 15 秒；慢 Guest 会延长实际周期，界面始终使用实际观测时间。Rust 执行库每实例仅缓存最近四份数据，Agent 每轮按八实例分页遍历全部分配对象，上传与生命周期分开。采样失败不完成任务、不重建系统盘，也不抹除最后有效样本。

速率从相同 Guest boot_id、接口身份及 ifindex 的相邻计数计算。CPU 来自 `/proc/stat`，内存使用 `MemTotal − MemAvailable`；容量均为 Guest 可见值，与配置的物理容量分开。第一份样本、重启、设备重挂、计数器回退、采集通道中断或超过两分钟的间隔断开速率，曲线不补零。网卡总计不包含 loopback，不作为计费用量。TCP／UDP 诊断为整个 Guest，选择网卡不会改变这些计数。

运行时、Guest 管理采样通道、SSH TCP 22 和已配置 TCP 服务端口分别表达健康。SSH 与服务探测从承载机器连接此实例已确认的地址；成功不代表公网路径可用，UDP 不用 TCP 成功替代。监控页另提供承载机器观测入口。配置失败与实例仍在运行、仍能采样可以同时成立。

Console 使用独立的监控状态、分钟历史和事件表，不修改实例规格或生命周期回执。提供 1／6／24 小时范围；每分钟的 CPU、网络及 I/O 速率按有效持续时间聚合，保留 CPU 采样峰值、最低可用内存和窗口计数。展示最多 2,000 点、100 条事件；重启、OOM、通道和服务连接变化与既有实例操作关联。独立清理任务每分钟分批删除超过 25 小时的记录，无活跃上报时仍会执行。日历史从启用后逐步累积，不虚构过去数据。接受的一分钟内时钟领先会保留真实上报时间并扩展相同长度的查询窗口；超过五秒时提示校准机器时钟，避免新样本被查询上界隐藏。有效窗口内的计数器缺失或回退会保持该分钟速率未知，不按零参与平均。

`GET /cvm/{id}/monitoring?window_secs=3600|21600|86400` 按实例租户／用户鉴权；Agent 使用独立 `/agent/v1/cvm/observation-targets` 和 `/agent/v1/cvm/observations`。生命周期回执不携带监控数据，查询只读取独立观测状态和分钟历史；尚未采样时显示未知。滚动升级先 Console，再 Agent 及其内置执行库。

## 实例终端（WebShell）

运行中的实例可在详情点击“终端”。浏览器通过同源 WSS 连接 Console，宿主 Brocade Agent 转接到实例 CubeShim；Shim 持有经 vsock 创建的 Guest PTY 和 Shell。无需实例公网地址、SSH 端口或密码。Guest 业务网络异常时仍可维护；Guest 内核或 cube-agent 不可用时无法连接，本功能不提供启动救援串口。

终端以 Guest root 运行。本人、作用域内租户管理员和系统管理员可以使用，只读及其他管理角色不能连接。浏览器不能选择任意 runtime、进程参数或本机路径。会话按操作者和实例运行身份隔离；新页面连接同一会话后，旧页面不能继续输入或调整尺寸。

系统管理员和所属机器租户作用域内的租户管理员，在 **容器 → 宿主 → WebShell** 按机器开启或关闭，默认关闭。关闭立即拒绝新连接并关闭 Console 中的现有连接；Agent 每 20 秒同步策略，随后要求 Shim 结束被撤销版本的 Shell。Agent 离线时需等连接恢复后执行清理。先关闭再开启也会撤销旧版本会话，不影响重新开启后创建的会话。普通用户和只读账号不能管理开关。Console 保存策略版本和操作审计，节点能力上报不会覆盖设置。`PUT /cvm/hosts/{node}/terminal` 接收 `enabled` 与 `expected_revision`，版本冲突返回 409。

使用前须升级 Console、宿主 Brocade Agent、Rust Cube 客户端和支持持久终端及实际 `ResizePty` 转发的 CubeShim。执行库同时上报 `guest_terminal` 和 `guest_terminal_persistent`；缺少任一能力时不开放入口。已有实例继续使用启动时绑定的 Shim，需按保盘流程切换运行栈；仅替换磁盘二进制不会更新正在运行的 Shim。创建 Shell 时会验证两组 Guest 实际窗口尺寸，拒绝窗口调整未生效的运行栈。

终端使用独立版本 `x-brocade-terminal-version: 2`。旧 Console 端点或旧 Agent 不支持时连接失败或按有界退避等待，不影响配置收敛及实时监控。Agent 使用 `/agent/v1/cvm/terminal/policy` 读取本节点策略和撤销版本。Shim 的本机套接字及 FIFO 位于 `/run/brocade-cvm-terminals/`，目录权限 0700、套接字 0600，并校验对端 UID；不对网络开放。

每个节点最多保留 **3 个存活 Shell 会话**，不同实例的 Shim 通过节点级文件锁共同执行限额。**不设置操作者维度的数量限制**。每会话最多保存 **4 MiB 已滚出的格式化历史字节**，超过后按完整行淘汰最旧内容；收到 Guest 退出回执后，在最终输出交付、分离或最多 30 秒的尾部交付等待结束时清理历史并释放名额。仅收到终止信号的确认或本机缓存的退出码不足以释放名额。浏览器滚动回看最多 3,000 行。当前画面、备用屏幕和连接队列另有边界，4 MiB 不是整个进程的内存上限。输出按浏览器渲染完成后的字节 ACK 限速；持续输出不会重新开始尚未完成的历史回放，慢连接在回放完成后可只同步最新画面，不积压无限输出。调整普通终端窗口大小时会保留长行、颜色和光标，并重排软换行。Shell 内运行的程序仍占用实例自身的 CPU 和内存。

会话不因无人输入自动过期。关闭窗口、刷新、网络断开、Console 或宿主 Agent 重启只分离连接；实例及 Shim 仍存活时，重新打开默认恢复本人最近的会话，保留 Shell PID、变量、工作目录和终端画面。标签可切换会话，“新建”创建独立 Shell；操作菜单中的“结束会话”经确认后结束 Shell 并释放名额。停机、实例重启、重装、删除、Shim 退出或宿主重启会结束该运行身份的会话；历史仅存内存，不跨这些边界恢复。

连接票据绑定操作者、实例、节点和运行身份，30 秒内一次使用。Console 的临时连接最多每节点 6 条、每进程 128 条，允许旧连接与新连接短暂交接；这些传输保护不增加节点的 3 个 Shell 名额。若 Guest 清理未确认，Shim 保留名额并拒绝恢复该会话，需完成实例重启或销毁后重试。连接最长两小时，届时可重新连接原 Shell。登录失效或权限撤销会关闭页面连接；该连接关闭不等同于结束后台 Shell。运行连接每两秒复核权限与实例身份，不重放输入。Console 日志记录签发、连接结束及对象身份，默认不记录键盘输入、命令正文或终端输出。

支持中文输入、Ctrl-C、Tab、Escape 和窗口调整。手机可使用屏幕快捷键，屏幕阅读器可开启“辅助阅读”。Escape 留给终端程序，Ctrl+Shift+Escape 或“关闭”分离窗口并保留会话。支持系统键盘粘贴和工具栏“粘贴”；无法直接读取剪贴板时，可在弹窗粘贴文字后发送。粘贴使用终端原生 bracketed paste 行为，每次最多 32 KiB，超限需分段；切换连接后不会把旧的剪贴板读取结果发送到新会话。

反向代理需保留浏览器 Host，并支持管理面 `/cvm/{id}/terminal/{session}/stream`、Agent 面 `/agent/v1/cvm/terminal/control` 和 `/agent/v1/cvm/terminal/{session}/stream` 的 WebSocket 升级；生产入口使用 HTTPS／WSS。同源校验拒绝跨站借用登录 Cookie，票据只在首个 WebSocket 消息发送，不放入 URL。多 Console 进程仍需把同一节点的控制连接、管理请求和数据连接路由到同一进程；重新建立连接后才能恢复 Shim 中的 Shell。

## 用户在宿主上的网络额度

系统管理员在「容器 → 额度 → 编辑额度」中，为每个已授权宿主设置一个「网络连接额度」。同一用户在这台宿主上的全部容器、主网卡和业务网卡共享此额度；同一双向会话计一次，活动状态及等待关闭/超时回收的状态都占用额度。

界面直接展示 Store 的权威试算：`最多可设 = 宿主可分配 − 其他用户已分配`。其他用户的待生效增额、尚未确认释放的减额仍计入已分配。保存会原子校验用户授权、额度版本和宿主预算版本；过期试算不能覆盖新分配。节点实际执行并回报对应版本后才显示「已生效」，并允许新建或启动该用户的容器。

默认新建速率为 1000 条/秒、突发额度 2000 条；在「高级设置」中可分别修改。任意 t 秒内新建数不超过 `速率 × t + 突发额度`，且始终受连接总额约束。这些是限额，不是宿主吞吐量保证。设为 0 会暂停新建，已有连接正常保留；调小额度不会强制断开旧连接，待实际占用降至新额度后 Store 才释放差额。

「计算详情」展示固定开销、每状态预算、系统保留、当前占用及容量模型。宿主容量同时受到真实可用物理内存、已分配 Guest 内存和其他用户网络分配限制；网络分配也会反向收紧可分配 Guest 内存。离线或执行失败不会释放分配。网络额度需要 Console/Agent 协议 66 和 `cubevs-user-quota-v1` 能力，旧运行栈显示能力尚不可用，不能伪装已执行。
