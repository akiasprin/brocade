# 机器观测与通知

机器指标、Ping、公网 IP、通知与日志，以及 Console 自身的性能诊断。

默认「黛蓝」配色在明暗模式下均使用低彩度灰蓝，亮色使用更深的灰蓝以保持白底可读性；次要文字在卡片、标题带和名册等底色上保持至少 4.5:1 的对比度。导航、按钮与图表主序列共享同一色系，绿色、金色和红色仍分别表示正常、需注意和错误状态。

线路端到端探测的高延迟仅通过数值和曲线表达，不会使状态灯、延迟读数或曲线变黄；出口 IP 不符仍以金色提示，不通仍以红色提示。

## 采集与保留

链路分项中的未知或已删除对端会单独拒收并计数，不使同批主机/NIC 窗口回滚；分族解锁探测出口不进入物理链路指标或连接归属。

主机指标与网卡累计流量计使用独立采样线程：指标仍每 10 秒采集、每 30 秒汇总，完成的指标窗口先进入私有磁盘队列，再由独立线程上报；队列只保留最近 120 个窗口（约一小时），Console 短暂停机后按时间顺序补报，重复窗口由数据库键去重。流量计独立每 10 秒原子持久化。运行状态报告只读取成功落盘后的内存快照，不触发流量采集或写盘；超过 30 秒的旧快照不再携带，恢复后用累计值补回已知流量。正常退出由流量线程完成最后一次持久化。磁盘慢写不会通过流量计锁阻塞指标采样；异常轮次会记录采集耗时、调度延迟及缺口原因，但真实主机停顿、磁盘队列写入失败或 Console 不可达超过一小时仍可能造成指标缺口。

除配置收敛外，agent 还负责上报用量与运行指标、执行链路探测，并给出路径 MTU 建议。用量按固定窗口累计，配额状态的变化会触发相应的授权调整。机器观测最近约 1 小时保留原始 30 秒窗口，较早历史逐步按分钟聚合，保留期仍为 7 天；超过 1 小时的历史查询统一分钟粒度，最新状态和告警仍使用原始上报。聚合保留峰值、事件总数和真实断档，容量/内存组成取末次快照，Ping 与计费用量不受影响。磁盘面板针对 agent 状态目录所在文件系统，区分容量、inode、块设备吞吐、IOPS、完成延迟、队列与 I/O PSI；网络面板除连接与内核错误外，还按真实匿名端口范围估算最繁忙目标的出站端口压力。目标地址只在节点内参与聚合，不会上报控制面。兼容与不可逆边界见 [Load 分钟历史](../.agents/runbooks/console-deployment.md#load-分钟历史有损)。

运行状态中的 GeoIP/Geosite 文件摘要按文件身份缓存，文件被替换或原地修改后在下次观测时重新计算；队列变化触发的即时上报复用未变化文件的摘要，减少单核节点上的周期性 CPU 尖峰。Xray 交接状态采用有大小上限的批量读取，避免每秒守护检查产生逐字节读取开销。进程发现结果按受管配置缓存，每次使用仍核验 PID、启动时间、进程名和配置路径，失效后重新发现；历史代目录每 30 秒清理，故障检测仍每秒执行。两项优化只需更新 Agent，采样频率、上报字段和文件校验保持不变，无需更新 Xray 或重新发布线路。

## Agent 控制连接与恢复

Agent 的普通 HTTP 请求使用 reqwest 与 rustls，并为每次请求设置总期限：默认 30 秒，覆盖域名解析等待、TCP/TLS 建连、上传、响应头和完整响应体；公网 IP 探测沿用设置中的单次期限。收到少量响应字节或 TLS 控制消息不会重新计时。超时会结束本次请求并关闭连接，重试仍由各上报通道负责，HTTP 库不自动重放请求、不跟随重定向、不使用环境代理，也不自动解压响应。TLS 使用 Agent 内置的信任根，证书名称、有效期和信任链仍须通过校验。

控制面与可选外部服务使用独立的客户端和 DNS 预算：系统解析分别最多 200 个和 2 个并发工作，不排队；额度耗尽会返回可重试错误。系统 `getaddrinfo` 已开始的工作无法强制取消，因此请求超时后仍保留其额度，直至实际解析结束，避免重试不断创建线程。客户端初始化因线程或文件描述符不足失败时，按 1–15 秒退避重试，成功后才复用实例。

WebSocket 建连从 DNS 到 TLS、HTTP Upgrade 共用 10 秒握手期限；握手成功后清除该期限，继续使用实时通道自身的非阻塞读写。普通响应正文最多 16 MiB，响应头另限 64 KiB；响应只接受未指定 Transfer-Encoding 或 chunked 的传输方式，分块开销不占正文额度。HTTP 语法由库校验，响应尾部字段不覆盖初始策略头。HTTPS 以关闭连接定界时必须收到 TLS 正常关闭；有 Content-Length 或 chunked 边界的完整正文不要求额外等待断开，截断正文始终失败。这些限制仅影响新 Agent，不改变 Console/Agent 协议或升级顺序。

Agent 与 Console 的常驻 WebSocket 使用 yawc 0.5.0，在建连时协商 `permessage-deflate`，压缩等级、窗口和上下文复用沿用库默认参数；未声明该扩展的旧端继续使用未压缩消息，支持任一端先升级。帧与完整消息在解压后仍受 512 KiB 上限约束，单次写入最多等待 5 秒，超时后断开并按既有退避重连。压缩只改变传输表示，不改变实时 JSON、按需采样或 HTTP 上报和补报语义。

运行状态、在线来源等即时快照在恢复后发送最新值；计费用量先落磁盘，未收到完整成功响应时保留原记录和去重标识，重试由 Console 识别重复。连接恢复不能重建停报期间的历史在线快照。HTTP 传输失败日志保留阶段、错误类别、状态码、已收字节和耗时，不记录令牌、完整 URL 查询或响应正文。

## 时间范围

机器详情的吞吐两图在实时范围内按相邻的完整采样窗口对齐后显示，减少等待更新造成的尾部留白。网卡、XRAY 接入与中继、转发仍保留各自真实的窗口时间与读数，配对允许 15 秒偏差，不要求时间戳完全一致；对齐最多延后 30 秒，落后超过 30 秒的来源显示「滞后」，与网卡、MTU 等元信息使用相同的字体、行高和颜色，其他数据继续更新。没有样本的来源不阻塞显示，首批样本尚无可配对窗口时先显示已有数据，延迟来源恢复后不撤回已经展示的样本；固定历史区间保留原请求边界。历史缺口断线，没有样本时显示 `—`，只有已上报的零字节窗口才显示为 0。标题栏不显示样本距今时间，图例显示实际已展示的最后样本，其采样时间可通过图例悬浮提示查看。

机器详情观测页的时间范围写在地址栏：默认近 1 小时不写参数，其余快速范围为 `?range=6h`，固定区间为 `?from=<unix 秒>&to=<unix 秒>`（1 分钟–24 小时，参数不合法时按近 1 小时显示）。在任一图表的绘图区按住左键横向拖动，松开后整页切换到所选时段；起止按图上一个像素对应的时长取整，不足 1 分钟按 1 分钟补足。双击图表把范围扩大一倍，结束不晚于当前时间，最长 24 小时。每次切换写一条浏览器历史，前进、后退、刷新和复制链接都保留所选时段；时间按钮左侧的返回按钮与浏览器后退相同。固定区间不自动刷新，在时间菜单选择快速范围即恢复实时；触屏不启用拖选。

机器观测页中，网卡流量、XRAY 流量、Ping，以及 CPU、内存、磁盘、连接表等展开曲线均支持通过图例聚焦：点击一个图例项突出该曲线，其他曲线与图例变淡；再次点击选中项恢复全部曲线，也可直接选择另一项。图例支持键盘 Tab、Enter 和空格操作，每张图独立保存选择。聚焦保留原始样本、坐标轴范围、单位和堆叠关系。Ping 图底部的丢包细条仅显示聚焦目标的丢包时段，目标零丢包时不显示细条；取消聚焦后恢复全部目标的合并丢包时段。

### 校时与指标连续性

主机指标以 Linux `boot_id` 识别真实重启，以不随墙钟跳变的 `CLOCK_BOOTTIME` 计算采样间隔、速率和重启交接有效期。NTP 校时改变 `/proc/stat` 的 `btime` 时，不再据此清零计数或把有效采样标为重启缺口。尚未上报的窗口按校正后的时间和实测时长定位；已经保存的历史不改写，因此大幅校时仍可能在日历时间轴上留下真实的跳跃或重叠，不能据此推断 Agent 断线。

时钟回拨后，Console 允许即时发送且偏差已改善的新报告更新被旧未来时间戳挡住的最新主机与进程状态；延迟补报和乱序报告继续受原有保护。机器详情、机队列表和网卡小图以已接受的新鲜报告为最新指标的时间上界，校时前保留的未来样本不会挡住当前读数；显式历史区间仍可查看原始记录。此项需要同时更新 Agent 和 Console，不改变公开协议或数据库结构。旧版单次重启交接文件会被安全丢弃并重新建立采样基线；真实停顿、计数回退、进程崩溃及 OOM 仍会形成实际缺口。

## Ping

Console 按原始采样时间接收 Ping 历史补报，不把历史样本的年龄当作节点时钟偏差。
数据保留期内的样本正常入库；超过「Ping 探测样本」保留期的有效样本返回成功确认，计入
`skipped_samples`，不重新写入已过期历史，因此不会阻塞旧 Agent 的后续上报。重复样本沿用
同一序列、采样时间去重，最新读数按采样时间选取；补报不会覆盖更新的读数。非正时间戳和
超过当前时间 10 分钟的未来时间仍会被拒绝。该修复只需更新 Console，不依赖 Agent 的缓存

Ping 探测目标在设置页按 ICMP / TCP 分类，每个目标有 IPv4、IPv6 两个地址栏，至少填写一个，留空的地址族不探测。地址栏填写该地址族的 IP 或域名，域名只取该族记录（A 或 AAAA）；TCP 写作 `主机:端口`，IPv6 地址写作 `[地址]:端口`。Agent 按地址族分别解析并行探测，各自计时；机器没有该地址族的路由、域名没有该族记录或解析失败时，样本记为未探测并附原因，不计作丢包。Agent 协议 v24 之前的节点只收到 IP 字面量地址，域名目标在节点升级前没有样本。

Ping 链路探测最多保存 6 个目标，IPv4 和 IPv6 分别配置。设置页按“北京 → 上海 → 广东 → 重庆”提供方案，每组填入电信、联通、移动各一组 TCP（80 端口）与 ICMP 双栈地址，点击保存后才生效，不改变巡检周期和单次超时。已保存的目标照常读取，不会自动套用方案。北京使用百度和微信静态资源 CDN，上海使用 QQ 首页 CDN，重庆使用腾讯视频和微信头像 CDN；北京、上海、重庆地址于 2026-10-19 按 ITDOG 当地测点延迟核对，不能仅凭 IPv6 地址库的位置标注判断物理位置。

广东方案的 IPv4、IPv6 地址于 2026-10-28 更新：电信使用微信头像 CDN（`wx.qlogo.cn`），IPv4 为 `183.61.254.74`，IPv6 为 `240e:97d:10:1705:3a::e`；两族均由广东电信网段的 DNS ECS 查询取得，并通过固定 IP 的 `wx.qlogo.cn` HTTPS 证书校验。IPv4 地址库标注东莞电信，ITDOG 广州电信测点的 IPv4、IPv6 延迟分别约 6 ms、7 ms；另从远端双栈机器连续 ICMP 各 30 次、TCP 80 连接各 10 次，均成功且 ICMP 零丢包。联通的 IPv4 使用阿里图片 CDN（`img.alicdn.com`）、IPv6 使用微信头像 CDN，移动的 IPv4 使用腾讯视频 CDN、IPv6 使用 QQ 首页 CDN；这两组优先选择广州目标，IPv4 的 ICMP 与 TCP 80 已从香港 FXT 验证，其中联通 IPv4 经广州测点查询广东联通 DNS 取得，并通过 `img.alicdn.com` 的 HTTPS 证书校验，连续 ICMP 30 次、TCP 80 连接 10 次均成功；IPv6 的 ICMP 与 TCP 80 已从广州、深圳测点验证。城市结合地址归属和当地测点延迟核对；ICMP 与 TCP 的可用性分别判断，TCP 连通不代表同一来源的 ICMP 一定可用。

机器详情的 Ping 面板一次只显示一个地址族，由面板右上角的地址族开关切换，ICMP PING 与 TCP PING 两张图同时切换；没有填写或机器没有路由的地址族不可选，另一族在所选时段有丢包时开关上显示圆点。图例显示当前所选时段、当前地址族的丢包率，即已实际发出的探测中未响应的比例；未发包与缺少上报不计入分母，没有有效探测时显示 `—` 或未探测原因。部分丢包为金色，已探测的全部无响应为红色。曲线在丢包处断开，x 轴下方的红色细条标出丢包时段；悬浮提示显示毫秒延迟，无响应为红色。切换时间范围时图例同步重新统计，复用已有历史数据，不增加请求。机器卡片的 TCP 读数优先取 IPv4，最新一轮无响应显示红色「—」，IPv6 最新一轮无响应时读数后追加红色「v6」。

控制台不再提供独立的「链路与 MTU」页面；旧 `#/links` 地址回到机器列表。机器详情、线路及设置页已有的拨测和 MTU 功能保留，后端采集与接口不受影响。

## 解锁检测

### DNS 回退标记

连接路径证据的 DNS 收集、代理中继、TLS、重定向和正文共用下述链路请求预算，不因补查重置。此期限覆盖规则 DNS 的 4 秒预算，避免诊断尚未完成就被 HTTP 提前截断。

Agent v57 配合新版 Brocade Xray，在原有 IPv4／IPv6 检测的实际连接内采集解析与拨号证据，不增加一整轮服务检测。每条连接在私有临时客户端生成随机编号；认证过的分族探测流沿原路携带编号，由实际出口返回节点身份、DNS 策略步骤、实际连接地址族和成功／失败结果。普通代理连接不携带额外帧。YouTube 网页、Premium、视频 CDN 使用独立子项，各自保留实际出口；同一服务可以跨出口，不再要求整条链只有一个出口。

Console 将实际出口限制在本次链路的受管可达范围内，核对检测修订、出口实际加载的 DNS/Freedom 配置指纹、出站策略和解析器标识。相同 DNS 配置在两台机器上不会混淆来源。证据在连接开始／完成时按编号配对；整轮重试的所有连接都保留在所属子项，数量与实际发起的 HTTP 请求相符才视为完整，不按到达时间把迟到结果分配给另一条连接。原始观测与服务结论保留；Console 派生的标记不可由 Agent 指定。

已确认某族经后续自定义解析器或机器 DNS 回退取得，并且常规策略会先取得另一族地址时，才将其视为条件性回退：磁贴保留地区和状态读数、去除状态色与投影，不计入可用数的分子或分母，不参与双栈比较，列表使用常规族的结论，不显示「仅 v4／仅 v6」，悬停提示保留分族与 DNS 路径说明。另一族的补充诊断优先保证与常规解析一致：通过同一解析器、地址策略、UDP/TCP、IP 筛选及缓存策略执行真实查询，缓存缺失时实际查询，不仅凭缓存是否存在作结论。主查询与补查仍共享该成员 4 秒及 5 次发送额度；补查失败或额度耗尽时保留「待确认」，不把 DNS 超时推断为没有地址。默认／优先地址策略、源地址绑定都参与判断。正常运行本来就依赖的回退仍保留计数；DNS 请求失败后回退、另一族未确认、配置不符或数据不完整时明确显示实际路径及不确定性，不静默排除结果。部分连接属于条件性回退时显示「部分回退」，保留计数。未取得可归因的解析路径时不增加额外标记，YouTube 分项也省略对应路径说明；服务状态、失败原因与计数口径保持原样。

点击标记可查看出口、命中规则、解析器、地址策略、回退原因和实际连接。停止连接且确认缺少该族地址时，分别显示无 IPv4／IPv6 解析；固定策略可显示「DNS 策略只解析 IPv6／IPv4」。地区、页面与 CDN 的结论仍来自对应服务响应，不能用出口机器位置替代。链路匿名请求不复用前次出口的 TLS 会话票据。

规则 DNS 组保留逻辑规则及真实胜出成员；详情展示已完成成员的结果、发送次数、耗时、缓存命中及 DNS RCODE。仍在运行或未被采用的后续规则不冒充实际路径。组内只要还有失败成员，就不能凭另一个成员的空回答确认整组缺少该地址族。Console 按该次配置核对成员序号和归属；历史单地址证据继续可读，旧证据缺少组成员信息时标记路径未确认，不猜测胜出地址。组配置、独立预算与升级顺序见[规则 DNS 组与重试](routing.md#规则-dns-组与重试)。

节点身份通过已认证的 Console 响应持久化到 Agent 私有状态，受管 Xray 每代启动时注入实际配置指纹。只有链上相关节点具备新能力，且运行／安装摘要和环境已确认，才启用新帧；升级期间基本分族请求仍保持原路径。私有证据文件、帧长、连接数、DNS 步骤、字段长度和启动环境都有上限，检测结束删除临时进程及文件，不存服务响应原文、地址列表、路径参数或认证内容。证据缺失只影响路径覆盖，不能伪造常规地址族。

旧 EDNS 预检归因和单出口归因分支已移除；旧证据不做猜测转换。本次升级完成后清理解锁历史并全量刷新，解释仍保存在已有结果 JSON，无数据库结构或迁移变化。已排队的同节点任务在成功上报后通过实时通道继续唤醒，避免每项之间等待 60 秒。两族都不可用时列表显示对应限制或失败结论。

所有可访问控制台的账号都可查看权限范围内的机器和线路解锁报告（包括地区、视频 CDN 和 IPv4／IPv6 结果）；开启访客访问后，访客也可查看。报告与地址族能力接口沿用现有可见范围和脱敏规则；关闭访客访问后，匿名请求立即失去读取权限。手动重新检测仍需编辑权限。

机器详情中位于“观测”右侧的“解锁”页签、链路详情页头的“解锁”按钮提供 ChatGPT、Claude、Gemini、Netflix、Disney+、YouTube、YouTube Premium、TikTok、Prime Video、Reddit、Spotify、HBO Max、DAZN 的可用性和地区参考。设置页的“解锁检测”可选择**手动**或**定时循环**，循环间隔可配置为 1–720 小时，默认为 24 小时；每轮全量刷新所有运行中的机器、线路及其地址族，不按结果新旧筛选，无需保持页面打开。系统管理员可用“立即全量检测”发起独立的全量刷新；手动模式不产生循环轮次，仍保留单对象和全量手动检测。编辑者及以上角色可为权限范围内的对象手动重新检测，两次发起至少间隔 60 秒，正在进行的任务会复用。循环时间从启用或调整循环设置时开始计算，单对象手动重测不推迟全局下一轮；正在进行的同路径任务复用，完成后补齐较新的全量请求。链路配置或机器 DNS 变更生效后立即唤醒 Agent，重测受影响路径，不受手动／定时模式限制；无关修订不触发。

机器检测由目标机器 Agent 使用默认网络出口直连服务，需要 Agent 协议 v46。链路检测需要入口 Agent 协议 v47，由入口机器启动仅绑定 loopback 的临时 Xray 客户端，使用既有专用探测身份连接该链的真实本机入口，再沿实际转发和分流规则访问服务。普通 TCP 入口优先选择既有 VLESS 探测路径，AnyTLS-only、VLESS Encryption-only 和 Hysteria2-only 入口沿用各自端到端探测路径；面板记录本次协议。默认不穷举混合入口的全部协议，也不复现某个用户的入口投影、前置组合或账号策略，MTProxy-only 入口不支持通用 HTTP 解锁检测。

机器直连检测每次 HTTP 请求最多 3 秒；链路检测统一最多 10 秒，包括自动选路、分族和不带连接诊断的外部代理路径。DNS、重定向、TCP/TLS 和完整响应正文共用单次预算，每项服务包含重试仍共用 60 秒总期限。

链路的服务域名默认交给链路处理；HTTP、HTTPS、重定向、地区查询和 Disney+ 会话请求均强制经过该客户端，代理失败不会回退到机器直连。临时进程及凭据文件在检测结束后清理，不重启承载业务的 Xray。机器控制连接不使用该代理，节点凭据不会发送给外部服务。

Netflix 的两个固定测试片目独立取证，共享包含重试的 60 秒服务期限。一个片目发生连接错误或超时，不会覆盖另一个已确认的正常片目页；没有有效片目证据时保留真实错误，不能用一份 404 和一次连接失败推断“仅自制剧”。片目网页可访问不等于已验证账号播放权限。公网诊断在 TLS 中明确声明实际使用的 HTTP/1.1 协议，避免部分服务因缺少 ALPN 而提前断开握手；控制面与 WebSocket 沿用原有 TLS 配置。 网站诊断单独协商 gzip 压缩，避免大型 HTML 在慢链路上因下载正文耗尽单次预算；先读完有效 HTTP 正文边界，再校验完整 gzip 流及校验尾部，压缩前后均受 16 MiB 大小限制并共用原有总期限。控制面、普通公共请求和二进制下载不隐式解压，检测也不把截断网页当作成功。

所有地区都来自对应服务的响应，不使用机器标注地区，也不会将未知地区默认成 US。同一条链可能将不同服务分流到不同出口，因此每项独立显示地区；未知显示 —。IPv4 / IPv6 分别检测、保存与展示，不保证同一族的多个请求经过负载均衡时保持相同物理出口。

结果区分可用、地区不支持、访问受限、部分可用与检测失败。ChatGPT 同时检查网页地区接口和 App 入口，可能显示“仅网页可用”或“仅 App 可用”；Claude 检查页面与地区限制跳转（包括 `claude.com`）；Gemini 检查页面中的服务开关与地区；Netflix 检查两个片目，均 404 时显示“仅自制剧”（启发式参考）；Disney+ 使用主页公开客户端标识，注册匿名设备、交换临时 token 并读取会话的 `countryCode` / `inSupportedLocation`；YouTube Premium、TikTok、Prime Video 使用各自页面中的特征与地区字段，TikTok 只读取访问者应用上下文的地区，不使用 CDN 数据中心或视频作者的地区；Reddit 检查页面可访问性。已识别的浏览器验证页（包括返回 HTTP 200 的 Cloudflare、TikTok SlardarWAF）记为访问受限；正常登录页加载的 Cloudflare 后台检测脚本不作为拦截依据。访问受限表示自动检测请求受到限制，不代表浏览器交互验证后一定无法使用；TikTok 应用首页跳转到公司介绍页时也记为访问受限，不将介绍页当作应用可用。TikTok 首先请求应用首页，未确认可用且未收到明确地区限制时，在同一链路和同一服务总期限内尝试 `/explore`；地区兼容当前 `__DEFAULT_SCOPE__.webapp.app-context` 与旧版 `SIGI_STATE` 的 `AppContext.appContext`，只采用成功页面的访问者地区。明确的 `/hk/notfound` 限制保持 HK 地区不支持结论。Reddit 以匿名网页访问为检测口径：HTTP 200 的正常 `<shreddit-app>` 页面或 `js_challenge` 自动继续表单判为可用；普通登录按钮不表示封锁。HTTP 403/451、明确的网络封锁或要求登录才能继续的封锁页仍判为访问受限，优先于自动继续表单。未知页面不直接判为通过。Reddit 地区优先取 `X-Served-By` 最后一个 Fastly 缓存节点的 POP 代码（例如 `HKG`），直接显示为地区参考；多个节点时不取前面的 shield 节点。界面保留原始 POP 代码，并按 Fastly 公开的节点位置为已知代码显示地区旗帜（如 HKG 对应 HK、SIN 对应 SG）；旗帜代表 CDN 节点位置，不是访问者地区，未知代码不猜测旗帜。同一次 Reddit 请求携带 `Fastly-Debug: 1`；`X-Served-By` 缺失或格式未识别时，取 `Fastly-Debug-Path` 开头的 delivery 节点代码，不取后面的 shield/历史缓存节点。两个响应头都没有有效代码时再取应用标签的 `country` 属性，均缺失则显示 —；不增加请求或运行浏览器。ChatGPT 的网页、App 与地区查询分别保留首个明确结果，每个请求独享上述单次预算，包含 DNS、重定向、TCP/TLS 和完整正文；三部分共享包含重试的 60 秒总预算，每部分首次加最多十次重试，成功的部分不再请求。地区接口超时或响应未包含有效地区时单独补查，不会耗尽在前两个请求的共享预算中；补查仍无有效地区时显示 —，不覆盖已经确认的可用性，也不借用机器或其它服务的地区。服务未提供地区时仍显示 —。未知响应、超时与网络失败不会被当作可用。检测不登录账号、不付费、不实际播放内容，网页判断不能保证具体账号或内容版权的最终使用体验。

YouTube 从 Agent v49 起单独展示分项结果：网页首页可访问性、Premium 可用性、各页面的地区证据，以及 Google Video CDN 映射。首页 `https://www.youtube.com/`、Premium `https://www.youtube.com/premium?hl=en` 与 `https://redirector.googlevideo.com/report_mapping` 独立请求，共用该项服务包含重试的 60 秒总期限和同一 DNS/代理路径，单次请求沿用上述机器／链路预算；任一失败不覆盖其它分项，也不切换为客户端 DNS 或机器直连。顶层 `youtube_premium` 状态、原因与地区保留为 Premium 的兼容投影，新增可选 `youtube` 对象保存完整分项；YouTube 仍占一项传输结果，网页与 Premium 独立展示。界面将 `youtube.webpage` 与 `youtube.premium` 展开为独立的 YouTube 和 YouTube Premium 磁贴，在扩展检测中共十三项展示与可用计数；各自使用对应页面的状态和地区。普通 YouTube 可用时保留绿色状态符号，正文直接展示视频 CDN，不再重复“可用”；失败时仍显示原因。YouTube 网页和 Premium 的地区不支持（包括 CN、MO）统一显示为中性的“提示 · 地区不支持”，使用信息图标，保留服务返回的地区且不计为可用；普通 YouTube 的结论独立显示，旧报告缺少网页分项时普通 YouTube 显示未取得。

Spotify、HBO Max、DAZN 从 Agent v53 起提供，仍使用原有机器／线路、IPv4／IPv6 或自动选路路径和配置的全量调度。Spotify 检查 `open.spotify.com` Web Player，要求页面含已识别的匿名播放器配置（`appServerConfig.appName`、`isAnonymous`）及有效 `market`，直接显示“可用”和该地区；仅 HTTP 200、缺失／损坏配置或验证页不会被当作可用。HBO Max 检查 `www.hbomax.com` 主页本次响应的 `countryCode` Cookie 与 `__DOTCOM_GEO__` 全局主页配置，同时核对服务区域、属地映射及实际可用的默认语言页面；地区显示响应中的实际国家代码。仅营销区域表中存在、没有直接服务页面的地区不当作可用；缺失／损坏配置或带日期限制、尚未确认生效的页面仍为无法识别。仍兼容旧版页面的 `userCountry`、`isUserOutOfRegion` 和应用配置，不从语言菜单、统计配置或主页 HTTP 200 推断地区与可用性。DAZN 使用启动接口的 `GeolocatedCountry` 与 `isAllowed`。上述检测均不登录、不播放；未知页面、无地区字段的伪成功和 HTTP 验证页不当作完整服务解锁。

Agent v54 起，新任务只检测十二项服务，YouTube 拆为两张卡片，共十三张；BBC iPlayer、Crunchyroll 和 Paramount+ 不再调度或展示。通过可选 `services` 字段协商，v54 接收十二项集合；尚未升级的 v53 暂时只领取原九项，避免继续检测已退役服务。未指定集合时仍只回报原九项。Console 接收完整九项、十二项及升级期间尚未回传的十五项报告，拒绝重复或不完整集合；十五项报告和退役服务枚举仅用于历史读取、在途任务与兼容回退。每个线程三项服务，常规十二项最多四个工作线程；网络失败、超时或未识别响应最多首测加十次重试；每项取得明确结果后立即结束，后续失败不会覆盖已确认的独立分项。每项服务含重试共享 60 秒预算，单次 HTTP 按上述机器／链路时限执行，使用十五分钟任务租约。 公网 DNS 同时最多八个解析线程，覆盖最多五个解锁工作线程和其它可选探测；与控制面的独立预算隔离，取消后仍由真实解析线程归还额度，不引入等待队列。升级顺序为 Console／前端先行，再更新 Agent；无数据库迁移、配置或 Xray 发布。回退应使用能读取扩展 DTO 的构建，不恢复整库覆盖计量数据。

旗帜数据由 `frontend/scripts/unlock-region-data.py` 从公开数据自动生成，不能手写 POP 对照表。Fastly 官方节点坐标匹配 Natural Earth v5.1.2 国家边界；少数机场填海坐标位于边界图之外时，要求 OurAirports 五公里内的全部站点只属于同一国家／地区。三位国家码使用固定版本 i18n-iso-countries 的映射，例如 Gemini 的 THA 对应 TH；Reddit 的 BKK 按 Fastly 节点位置映射 TH，不能将两种代码体系混用。保留原始显示代码，转换仅供旗帜使用。输入 URL、摘要和逐节点证据记录在 `frontend/scripts/unlock-region-data.sources.json`；页面只读取随版本发布的数据，不外联查询。

地区优先采用本次响应新发出的 `VISITOR_PRIVACY_METADATA` 中明确的两字母地区码，缺失时才采用 `desktopTopbarRenderer.countryCode`。每个页面分别保存这两种证据；`GL` / `client.gl` 仅作为页面配置单独展示，例如同一澳门响应的 GL 可能为 US，隐私地区却为 MO。Premium 本次响应地区为 CN／MO 时，即使页面包含通用订阅入口或去广告文案，也将原本的“可用”归为“提示 · 地区不支持”；依据为 [YouTube Premium 支持地区](https://support.google.com/youtube/answer/6307365?hl=en)，不会据此覆盖连接失败、超时或访问受限，也不改变普通 YouTube 与 CDN 的独立结果。Agent 解析、新报告入库及历史报告读取共用同一判定，历史原始记录无需改写。隐私元数据只保留地区码，不保存 Cookie、访客标识或原始正文。两种明确地区来源均缺失时显示 —，不继承机器标注地区，也不默认成 US。

CDN 只保存映射中的安全节点名，例如 `hkg12s15`，并按可识别的机场代码显示 HKG / HK；未知代码保留未知，不用页面地区填补。映射是 Google Video 调度参考，不保证某个视频每次都使用同一最终服务器。请求耗时包含整条被测路径及正文读取，不是出口机器至 CDN 的单段 RTT。CDN 查询失败、未知位置、网页受限和 Premium 地区不支持分别展示。

旧 Agent 的结果缺少 YouTube 分项时保留旧 Premium 结论，并提示升级后重新检测。v48 历史结果的 `client_dns` 条件继续可读，v49 不再生成这种备用路径结果。升级时先更新 Console 与前端，再更新相关 Agent；旧 Console 会忽略可选详情并读取 Premium 兼容字段，已有 v46/v47 机器/链路检测仍可用，无需数据库迁移。Agent 日志只保留固定服务 origin、失败阶段、HTTP 状态、字节数与耗时等有界信息。

链路任务从已成功发布的 Serving 拓扑生成，记录所测配置修订，草稿不参与。只有检测入口或沿途机器的实际网络配置变化时，旧结果才标记失效并重新调度；单纯修订号、显示名称、无关机器或用户授权变化不会使结果老旧，也不重置检测时间和每日调度。有效性比较包含入口、受管中继、复用监听器与最终出口的 Xray、WireGuard、Phantun 和端口跳跃配置，涵盖各分流分支和 DNS。检测期间发布无关修订，原任务仍可完成；实际路径变化时仍拒收旧路径报告。记录保留真正检测时的配置修订号，不把旧结果改写成新修订；已被旧规则误标失效的完成结果，在确认配置相同时恢复有效。每台 Agent 顺序执行任务、最多持有一个临时链路客户端；所有 Console 实例共用数据库调度，最多同时执行 16 项，每项服务含重试的总预算 60 秒，单次 HTTP 沿用上述机器／链路预算；旧机器自动任务领取后 240 秒未完成标记超时，分族与链路任务包含重试的十五分钟期限见下文。离线或停用期间不执行，恢复后只执行到期任务，不补跑每个错过的周期。

数据库为每台机器、每条链的每个检测作用域保留最新任务、最新结果、刷新时的上一份结果及下次检测时间；Console 重启后继续使用。重新检测时上一份结果仍可查看，并明确标注采样时间。相关机器或链路删除时关联数据一并清理，诊断不保存无界历史。迁移 `0003_unlock_probe_schedule.sql` 新建调度表，不修改历史迁移；升级顺序为先更新 Console，再升级需要链路检测的入口 Agent。仅识别 `0001`/`0002` 的旧 Console 不能直接读取升级后的迁移历史；部署时应准备携带相同 `0003`、仍兼容现有数据的回退构建。不能删除迁移回执绕过校验，也不能用升级前整库备份覆盖升级后的新写入；数据库恢复须另行明确维护窗口和数据损失边界。

线路列表页可在「卡片 / 解锁」之间切换。解锁视图按原分组和链顺序展示十三项服务对照表，合并展示 IPv4 / IPv6；不能传递强制分族身份的链路标注「不分族」，使用独立的原路径检测结果。任一族未解锁、缺少结果或检测异常时，以金色半圆提示，悬停查看两族各自结论。机器环境观测不取消 IPv6 实测，也不隐藏已有的 IPv6 失败或待测状态。单项 IPv6 明确返回「无 IPv6 地址解析」或「出口无 IPv6 地址」时同样采用 IPv4 的服务结论；缺少 IPv6 能力不表示服务访问受限。具备 IPv6 能力时，真实的地区限制、访问受限、网络失败和超时仍提示；新失败不能被上一次的跳过记录遮住。点一行或用键盘激活链名进入原链详情，解锁弹窗保持原有功能。检测中、超时或检测客户端失败时沿用并减淡上一份结果，悬停检测状态可查看该结果时间；线路已变更时保留正常亮度并以金色提示。与上次有效结果不同的服务带金点。地区以 IPv4 为主；两族地区不同时在主地区下方另行显示 `v6 XX`，补充说明不改变状态图标及主地区的对齐位置；仅有 IPv6 地区时明确标注 `v6`。对照表将 Gemini 三位国家码换为两位显示，悬停及详情保留原始值；Reddit 仍显示原始 CDN 节点代码。窄屏横向滚动表格时链名固定在左侧。

列表批量读取 `GET /chains/unlock-probes?limit=100&after=<cursor>`，每页最多一百条，响应包含 `chains`（应用、链、能力与 `probes.v4`、`probes.v6`、`probes.auto` 三个独立报告）及 `next_cursor`；各作用域无报告时对应字段为 `null`。按链 ID 稳定分页，先按账号租户范围过滤再分页，访客与用户只读规则和单链接口相同。此读取不会创建检测任务或重置每日调度，无新数据库迁移或 Agent 协议变更。

API：机器使用 `GET /nodes/{node_id}/unlock-probe` 读取、`POST` 手动触发；链路使用 `GET/POST /apps/{app_id}/chains/{chain_id}/unlock-probe`。Agent 使用 `/agent/v1/unlock-probe/target` 与 `/report`，轮询驱动到期任务，无需浏览器。任务按机器和链路权限鉴权，服务目标固定，只允许限定域名的 HTTPS 跳转。响应正文、链路凭据和 Disney+ 临时凭据不进入结果与调度表。

解锁检测结果以磁贴展示，按 AI、流媒体和社区保持服务位置固定。顶部可用数量只计完整可用，检测失败以灰色显示；各服务地区来自各自响应。重新检测、超时或链路级失败时保留并减淡历史结果；线路配置变更时结果保持正常亮度，在面板左下角高亮修订来源。检测时间、下次检测时间和链路协议共用底部独立信息行，链路弹窗将该行固定在内容滚动区下方。磁贴随容器宽度调整列数，保证 YouTube Premium 标题完整单行显示。完成后以金色标记有变化的上次有效读数，上次检测失败不显示为历史对比。时间显示相对值，悬停可查看具体时刻。机器“解锁”页签的重新检测按钮位于页头“更多”之前，与面板共用当前地址族、结果和冷却状态；线路详情使用弹窗入口，弹窗主标题为“区域性服务解锁状态”，链路名称放在下一行作为副标题；入口按钮预先读取并显示可用数量，与弹窗复用同一查询；YouTube 磁贴保留网页/CDN 要点，完整分项通过信息按钮展开。

YouTube／Premium 的「提示 · 地区不支持」同样适用于线路对照表：一族取得地区限制、另一族连接失败时，单元格保留中性提示图标，不合并为红色「双栈不可用」；悬停仍分别显示两族状态与具体连接错误。另一族实际可用或明确拒绝访问时，仍按原双栈比较规则展示。

### IPv4 / IPv6 分族检测

Agent 协议 v50 起，正式面板左下角切换 IPv4 / IPv6；两族分别保存当前结果、上次结果、状态、检测时间与 60 秒手动冷却。每次全量循环覆盖两族，单独重测当前族不重置另一族。API 在原有解锁入口使用 `?family=v4` 或 `?family=v6`，报告校验任务与地址族一致。地址族字段、就绪重试与解锁检测调度设置均属于尚未正式发布的解锁检测功能，合并在 `0003_unlock_probe_schedule.sql`；旧自动选路记录保留为未区分地址族，不复制填入 IPv4 或 IPv6。执行过旧预发布迁移的环境按部署手册精确转换，不能直接删除迁移回执。

机器检测强制该族解析与连接。链路分族检测的地址族是最终服务出站地址族：接入、中继仍按既有传输地址连接，专用探测身份沿受管 VLESS 中继传递族信息，原有域名规则、源地址绑定与 DNS 选择保持生效，最终自由出口使用 `ForceIPv4` / `ForceIPv6`，缺少该族地址时不回退。此能力需要支持强制分族身份的配置。Console 不再以机器地址、路由或 runtime 新鲜度推断路径不可用；入口执行时仍核对实际生效的配置，避免把 IPv4 回退误报为 IPv6 成功。配置尚未就绪显示“检测未就绪”，按 1、2、4、8、15 分钟最多五次自动重试，之后等待下一轮全量检测或手动重测，手动重测或路径变化重置次数。外部代理、反向链路与 Shadowsocks 中继使用原路径不分族检测，不将原路径结果冒充强制分族结果。此次变更不需要修改 Xray 内核代码。

每族、每项服务最多十一轮：首次加十次重试。仅网络失败、超时或未识别响应继续确认，取得明确结果立即结束该项；十一轮仍失败则保留真实错误。成功页面未返回地区时保留 —；ChatGPT 独立补查自身地区接口，其它服务不因页面缺少地区反复请求，地区缺失不改为检测失败。YouTube 的网页、Premium 和视频 CDN 分别保留已确认结果，只在仍有失败分项时继续确认。每项服务包含全部请求、重试与等待共享 60 秒预算，每线程串行三项服务，最多五个工作线程；分族和链路任务租约为十五分钟，覆盖每线程三项服务最多 180 秒及客户端启动余量，旧机器自动任务保持四分钟。Console 必须先升级租约，再发布 Agent；回退 Console 时保留十五分钟租约，或先回退 Agent，避免在途任务被旧六分钟租约提前过期。实际出口明确无 IPv6 出站时，该分项显示「已跳过 · 无 IPv6 出站」；仅到目标的网络不可达、目标不可达、拒绝和超时分别保留失败原因，不标为地区不支持，也不影响 IPv4。

YouTube 卡片直接显示视频 CDN 返回的位置代码，例如“视频 CDN HKG”；服务地区仍使用对应服务返回的地区字段，两者分别保存。

## 公网 IP

机器公网 IP 观测复用设置页的端到端探测落点。Agent 按同一间隔并行强制 IPv4、IPv6 直连该 CGI Trace 地址，从 `ip=`/`loc=` 取得两族事实，再分别上报 Console；没有 IPv6 不会阻塞或清空 IPv4。它不使用 Agent 请求的 `X-Real-IP`、`X-Forwarded-For` 或 Cloudflare 代理地址，也不把内核默认路由的 `src` 当作 NAT 后公网地址。配置中的公网地址、默认路由源地址和实际公网观测分别存放；首次观测立即生效，后续变更须跨至少 10 秒连续确认两次。稳定样本只刷新最后观测时间，变更事件默认保留 7 天，机器详情请求的最近 14 天窗口会按实际保留期收窄；保留期可在设置页调整。

## 通知

机器通知同样以控制面确认的状态转换为准：新 Agent 身份第一次轮询或离线后恢复产生上线事件，连续 90 秒没有期望状态轮询产生下线事件，公网 IP 只有在上述双样本确认完成后才产生变化事件。CPU steal 不低于 10% 持续 60 秒时开启宿主机抢占告警，不高于 5% 持续 90 秒时恢复；缺失样本和带 gap 的低值不作为恢复证据。事件与 Webhook 投递状态分别持久化；设置 `BROCADE_NOTIFICATION_WEBHOOK_URL` 后，Console 以 schema v2 JSON POST 投递，非 2xx、超时与连接失败均按指数退避重试，进程重启后继续。没有配置 Webhook 时仍可通过全局通知中心或 `/notifications` 读取默认保留 7 天的事件（保留期可在设置页调整），但不会积压日后突然补发的 Webhook 任务。Webhook URL 可能带凭据，错误日志不会输出它。

铃铛的未读角标只统计链路离线／恢复和 CPU 抢占告警／恢复；公网 IP 变化与首次上线仍保留事件历史，但不会点亮铃铛或增加未读数。打开通知会持久标记已读；尚未清空的进行中事故仍显示红色活动角标。

通知中心支持一键清空告警：系统管理员会同步清空所有账号，其他已登录账号只清空自身；服务端保存独立于已读位置的清空游标，刷新或换设备仍有效。清空不删除机器事件、公网 IP 变更历史或 Webhook 投递；进行中告警不会被视作已恢复，之后的恢复和新事件仍会通知。`POST /notifications/clear` 接受 `through_event_id`，只清空该位置及以前的通知，不会吞掉请求期间到达的新事件。访客不能主动清空，但会跟随系统管理员的全局清空；通知列表可能附带旧的告警起始事件以解释新的恢复，展示时以告警最后事件 ID 和 `cleared_through_event_id` 判断，不把上下文当作新通知。

## 日志

节点日志默认有界：设置页配置全局上限（Agent 20 MiB、Xray 20 MiB、每个 Phantun 实例 10 MiB，三类最低均为 10 MiB），机器可单独覆盖；清除覆盖后会继续继承全局值。Agent 每轮轮询直接取得最终值，不需要创建修订或发布线路。systemd 节点使用独立 journald namespace；OpenRC（Alpine）节点写入 `$BROCADE_AGENT_STATE_DIR/logs/agent.log`；Agent 拉起的 Xray 与每个 Phantun 实例也分别写入该 `logs` 目录。每个日志项的当前段与前一段合计不超过生效上限，降低上限会在线截断已有分段，不重启 Xray/Phantun。systemd 上使用 `journalctl --namespace=brocade-agent -u brocade-agent` 查看 Agent 日志，OpenRC 上使用 `tail -n 100 $BROCADE_AGENT_STATE_DIR/logs/agent.log`。不要删除仍被进程打开的日志来释放空间；有界 sink 会自行滚动。

## Console 性能诊断

Console 默认启用有界、进程内性能统计，可用 `BROCADE_PERFORMANCE_ENABLED=false` 关闭。系统管理员可读取 `GET /diagnostics/performance`，响应 `Cache-Control: no-store`：

- HTTP 按路由模板、方法及启动前 60 秒 / 稳态分组，统计次数、状态码类别、耗时直方图、已知响应字节数；P50/P95 是桶上界，不是假定精确值。
- SQLx 查询指纹与发起它的路由关联，记录查询耗时、返回/影响行数；不保留 SQL 文本、参数、请求实际 URL、机器名、订阅凭据或响应内容。指纹是对 SQL 去首尾空白后的 UTF-8 文本计算 SHA-256，短语句使用 SQLx summary，可离线从代码匹配。
- 保存最近 15 个一分钟桶，每桶最多 512 个 HTTP 分组、256 个 SQL 分组，超出进入 overflow，不追加日志或数据库时序。重启清空；诊断接口不统计自己。
- 附带当前连接池大小/空闲数，以及 PG 的缓存命中、临时文件、死锁、活动连接和锁等待数字。PG 累计值以 `stats_reset` 为起点，不能直接当作最近 15 分钟增量；活动信息受数据库角色可见性限制。只报告 `pg_stat_statements` 是否安装，不自动安装、启用或重启 PG。

API 响应的 `Server-Timing` 提供 `handler`、`db`、`pool`，可在浏览器开发者工具读取。`handler` 截止响应头就绪，不含后续流式传输、网络和页面渲染；未知长度的流不为计量而缓冲。`db` 是客户端观测的执行/获取行耗时，不是 PG CPU 时间；`pool` 仅包含成功获取连接的等待（含建立/校验连接），失败获取不会计入。它们可能重叠，不能相减冒充应用 CPU 耗时。SQL 归因范围是请求任务内的查询，不包含后台任务、另行 spawn 的任务或流返回后的查询。升级 SQLx 时必须运行性能模块的真实 PostgreSQL 事件契约测试。

通过安全方式设置 `BROCADE_ADMIN_TOKEN`（不要把令牌写入命令、报告或仓库），使用 HTTPS 或 SSH 转发的本地端口，运行顺序、只读的 HTTP 基线：

```sh
BROCADE_BASE_URL=http://127.0.0.1:8080 \
  BROCADE_BASELINE_REPEATS=10 node scripts/performance-baseline.mjs > baseline.json
node --test scripts/performance-baseline.test.mjs
```

可额外设置 `BROCADE_BASELINE_NODE` 测机器 Load/Ping 24 小时数据；默认测试 bootstrap、节点状态、模型快照和 Ping latest。脚本拒绝重定向、限制 30 秒和 16 MiB 响应，不保存正文，输出首请求、后续 P50/P95、字节数与 Server-Timing。首请求不是“已证明的冷启动”；对比时使用相同机器、数据窗口、请求次数及网络位置，记录是否刚启动和缓存情况。

Ping 无损存储兼容、隔离基准与恢复边界见 [Console 部署手册](../.agents/runbooks/console-deployment.md#ping-序列字典无损时序存储)。

Agent 实时通道以 socket 事件或下一次采样期限唤醒，不再固定每 20ms 轮询。Reverse/Mux 诊断只在有诊断订阅时后台采集，每 5 秒刷新；取消订阅或连接断开会停止采集并丢弃旧订阅的在途结果。NIC 和用户实时采样保持原有间隔。控制面 HTTP 请求复用连接，每个源最多保留 4 条空闲连接、空闲 60 秒释放；可选外部服务不保留空闲连接。总请求期限、响应大小限制和禁止自动重放的行为不变。

## 数据保留与清理状态

设置页「数据保留」列出 28 项独立策略：历史数据 24 项、临时数据 4 项。核心模型、发布及策略审计、计费日账本和永久计数基线不进入按时间删除的清单。用量与来源的日汇总在接收数据的事务内更新；负载分钟压缩继续使用原有水位和并发锁，清理不会另做一次重复汇总。

后台每分钟检查到期任务，各表独立执行有行数、锁等待和语句耗时上限的小事务；单表失败不阻断其他表。没有过期积压的表一般每小时检查一次，原始用量读数、有积压、清理失败或积压检查未完成的表一分钟后重试。修改 TTL 后在下一次调度重新检查。运行中未完成的证书扫描与外部出口探测不因历史保留期而被删除。通知投递记录随机器事件级联清理，不单列一项策略。

面板每 30 秒刷新最近检查、最近成功、上次成功删除行数、下次计划及是否仍有过期积压。积压检查有独立超时，无法完成时显示「尚未确认」，不会冒充没有积压，也不会撤销已完成的删除。最近结果仍使用旧 TTL 时显示等待重新检查；超过计划时间仍无新结果时显示清理延迟。失败只显示固定类别，不向界面持久化数据库原始错误。每张表仅保留一条最新执行状态，重启后继续调度。

行数与待回收行数来自 PostgreSQL 统计估值；空间占用包含表、索引及 TOAST。删除后依靠 autovacuum 回收死元组为后续写入复用，文件大小不一定立即下降；没有 vacuum 时间也可能是统计已重置，不代表需要执行 `VACUUM FULL`。该面板不会自动重写表或执行独占锁的空间压缩。

结构合并在尚未发布的 `0002_forwarding_rule_results.sql` 中，保留已发布的 `0001_init.sql` 不变。升级会在事务内锁住 VPN Gate 运行历史写入、回填当前证据并建立索引，失败则整体回滚后重试。应停止旧版 Console 写入后升级，避免旧版本绕过新证据投影；迁移完成后再启动新版后台清理。已按 TTL 删除的历史无法凭汇总恢复，回退依赖原始历史的旧版 Console 时可能缺失旧运行证据，需要备份恢复或接受该限制。

### IPv6 解锁检测的覆盖范围

机器和可强制分族的链路始终保留 IPv4、IPv6 检测选项和独立定时任务。入口到下一跳可使用 IPv4，服务请求的最终出口使用 IPv6；机器地址、默认路由和上报新鲜度只作为诊断信息，不用于取消检测或选择自动模式。自动模式只由线路是否能可靠传递强制地址族决定。

新版链路检测根据实际连接的解析结果区分无 IPv4／IPv6 地址与网络错误，已移除独立 DNS 预检。DNS 超时、拒绝或异常不推断为缺少某族地址；机器直测沿原系统解析路径，链路检测沿原入口和实际出口 DNS。重试次数和总期限以本页分族检测规则为准，不以本机 IPv6 路由判断链路是否能检测。

视频 CDN 映射既可能是 `hkg12s15`，也可能是 `nctsaa-ae` 这类不带数字的缓存节点名。
确认映射有效但无法可靠提取位置码时，保留原始节点名；不把位置未知判成验证挑战，也不从机器地区推断 CDN 地区。

YouTube 网页与 Premium 的匿名探测携带仅限 `www.youtube.com` 的 Cookie 同意偏好（`SOCS=CAI`），
避免欧洲入口先跳至同意页而被误判为未知响应。该偏好不含账号或地区；可用性仍取自真实 Premium 页面，
地区仍取新响应的隐私元数据或页面明确的 countryCode，不用网页可用代替 Premium 可用。

### 链路自动选族检测

外部代理、反向链路或 Shadowsocks 中继不能可靠传播强制地址族时，链路面板只显示一个「IPv4/IPv6」选项。
Agent v52 使用原入口凭据和原链路、原 DNS 自动选择地址族，保存一份检测结果，不推断或标注为某个地址族。
支持强制分族的链路及机器仍保留独立 IPv4、IPv6 选项。自动模式也支持手动重测、每天一次定时检测，
未知结果首次后最多再确认十轮（总计最多十一轮），全部请求和重试共用每项服务 60 秒总预算，单次请求沿用上述机器／链路预算；任务租约和上报缓冲为十五分钟，扩展服务最多五名有界工作线程，每线程串行三项。
自动任务以独立作用域保存，不会把之前的分族失败或旧自动结果混入另一种模式。

### 不支持强制分族的链路

外部代理、反向链路和 Shadowsocks 中继等不能传递强制分族身份的线路，使用独立的自动检测任务。
面板左下角只显示「IPv4/IPv6」一个选项；探测沿原入口、原线路和原 DNS 自动选择地址族，结果不归入 IPv4 或 IPv6。
自动检测需要入口 Agent v52，默认每 24 小时执行一次，保留手动重测。未知结果执行首次检测加三次确认，最多四轮；
任务有独立冷却、六分钟执行期限与上报缓冲。自动结果、旧未分族结果和强制分族结果分别存储，不互相冒充。

旧版 Agent v55 的「出口无 IPv6 地址」报告仍可读取。新检测由实际出口 Xray 在原请求的系统 TCP 拨号失败处保留结构化原因与尝试地址族。只有 IPv6 socket 明确不可用，或真实 IPv6 拨号返回网络不可达且同网络命名空间没有可用 IPv6 源地址，才判定「无 IPv6 出站」；源地址枚举失败、显式绑定、单目标不可达和端口耗尽均不据此推断全局缺少 IPv6。入口本机地址、路由及公网地址配置不用于提前取消远端检测。无 AAAA 只由沿实际路径完成的 DNS 查询确认；DNS 超时或异常不推断为无 AAAA。就绪重试字段合入现有 `0003_unlock_probe_schedule.sql`。已运行旧预发布 0003 的环境经精确校验及原子兼容转换升级，保留旧观测事实，并使旧 `family_unavailable` 任务尽快重新检测；不新增迁移文件。

解锁检测中的结构化拨号原因通过原有连接证据字段上报，普通业务出站沿原有路径。确认无 IPv6 出站、绑定源地址不可用、地址族绑定不匹配或本机策略拒绝时，该域名停止当前轮重复请求；网络不可达、目标不可达和连接被拒绝最多尝试两次；超时、连接重置和旧版通用错误保留首次加十次重试及每项 60 秒总预算。域名和 YouTube 网页／Premium／CDN 分项分别判断，失败不扩散到其他实际出口；ChatGPT 各域名中已取得的成功或明确失败也不会被另一域名的跳过结果覆盖。详情与线路对照表复用具体原因，明确无 IPv6 出站时对照表采用 IPv4 的服务结论，目标不可达仍保留为失败。没有新增迁移、额外整轮请求或入口 IPv6 预检。

设置 → 解锁中的「老旧结果自动重新检测」默认开启。实际路径变化后，由配置发布成功事件唤醒后台调度，在线 Agent 下一次常规轮询即比较配置并领取重测，不依赖打开页面；开启设置也会立即检查已有老旧记录。关闭后保留每日定时检测和手动重测，不取消已经运行的任务。该开关保存立即生效，不创建模型修订、不发布机器配置，仅系统管理员可修改。

### 常驻通道 RPC 与控制通知

支持 `x-brocade-channel-rpc: 1` 的 Agent 在 Console 明确确认后，复用压缩 WebSocket 执行小型节点 RPC：配置/授权和转发期望状态、来源策略、机器限流、用户流量策略与确认、拨测任务及结果、运行态/负载/链路健康/公网 IP、Agent/Xray 发布查询与回执。计量及明细批次、同步流量预算、注册、二进制和大型目录传输继续使用 HTTP。旧 Console 或旧 Agent 未协商此能力时保持原有 HTTP 行为。

数据库迁移 `0003_unlock_probe_schedule.sql` 为发布、策略和任务的权威记录增加提交后通知；事务回滚不会通知。节点目标变化定向唤醒，采样 Start/Stop 不会覆盖更新信号。连接建立及数据库监听恢复后重查期望状态，每个工作线程保留通知代次，运行中收到的变化会触发下一轮；通知本身不构成执行成功。Agent/Xray 空闲检查仍保留十分钟兜底（Xray 另有最多两分钟抖动），检查失败按十五秒重试，沿用原有发布身份、下载校验、安全替换与结果确认。

来源策略、机器限流和按需拨测在常驻通道可用时通过通知及时检查，并保留一分钟兜底；断线时恢复原来的短周期查询。用户流量策略沿用每秒刷新以满足两秒的放行租约，只替换传输，不延长其安全有效期。常驻通道不改变本机限流、计量采样或既有收敛时钟。每条消息解压后仍限制 512 KiB，RPC 正文限制 128 KiB、最多 16 个执行中请求，待发送队列最多 16 项，每次调用沿用原超时且最多三十秒。未发送或过大的请求可以走 HTTP，过大的 GET 响应由服务端明确要求改走 HTTP；已发送后超时/断线不由传输层自动重放，交给原业务的持久回执或重试机制。持久补报只在原服务端业务确认后删除。
