# 用户、访问与订阅

账号访问、客户端订阅、接入配额与在线设备。

## 访问与会话

当前前端不开放租户管理、选择与分组，列表、详情、悬浮提示和引导流程均隐藏租户信息；`tenant-admin` 在界面显示为「管理员」。内部归属与服务端权限规则保持原有含义。

用户详情页头显示账号的接入可用状态，区别于下方在线设备的实时在线状态。UUID 使用短形式展示，点击复制完整值，也可在「更多操作」中查看完整标识；流量读数集中在对应的用量区域。窄屏将页签放到身份与操作下方，保留「节点」「订阅」和更多操作入口。

普通用户的「转发」页签只在本人详情中显示。从本人的转发页切到其他用户时，自动显示对方的公开接入信息，不请求其转发规则或私有额度策略，避免正常浏览触发权限错误。
转发额度按用户 × 机器独立设置和执行，不提供用户转发总额度。

浏览器登录会话以 12 小时无活动为过期界线，而不是从登录时刻计算固定期限。已打开的控制台每 5 分钟发送一次轻量保活；其它已认证请求也会延长服务端期限并同步续写 Cookie。关闭页面或设备休眠后若连续 12 小时没有成功请求，会话仍会正常过期；重置密码和主动退出仍会立即撤销对应会话。

访客模式使用无状态访问：无登录凭据的请求每次检查访客开关和可见范围，沿用只读权限与服务端脱敏，不签发 Cookie、API 令牌或数据库会话。关闭开关后，后续匿名请求立即被拒绝；已有账号的 Cookie 或 Bearer 凭据仍优先校验，失效凭据不会自动降为访客。升级启动时只清理旧实现遗留的访客会话，保留管理员和用户会话。`public` 是保留的访客配置身份，不能用作初始化管理员用户名。

用户详情的「生成直达登录页」会签发 UUID + TOKEN 组合，用于直接换取同一类 HttpOnly 浏览器会话。完整凭据只在生成响应中展示一次，服务端只保存 TOKEN 的 SHA-256；重新生成或撤销后旧页面立即失效，现有浏览器会话不受影响。链接把凭据放在 `#/login/...` 片段中，浏览器不会把它写入 HTTP 请求路径，前端读取后也会立即从地址栏移除。更换用户 UUID 会同时撤销直达登录页。

## 账期与服务有效期

用户账期汇总接口 `GET /usage/user-cycles` 与用户名册共用只读访问范围，普通用户登录（包括直达登录）和已开启的访客访问均可读取；现有归属范围与响应脱敏规则继续生效，修改账期及服务有效期仍需编辑权限。

用户详情「接入」「转发」页读数栏的「计量口径」下方显示该用户的「重置日」和「有效期」。有效期通常显示到期日期或「长期有效」，七天内到期和未生效以注意色标出，已到期以错误色标出。具有编辑权限的账号点击这两行，可在弹出面板中设置每月重置日（1–31 日）、生效时间和到期时间。接入与端口转发共用该用户的 UTC+8 账期，接入额度按 app（界面中的线路）分别配置，转发额度独立配置；当月没有所选日期时取月末，下个月重新按原日期计算。生效选择「立即」表示立即生效，到期选择「长期」表示长期有效；有效区间包含生效时刻、不包含到期时刻。旧用户默认每月 1 日重置、立即且长期有效。

修改后，面板自动预览新账期的起止日期和按现有日账本重算的接入、转发用量，并标出保存后服务是否会暂停或恢复；预览不是保存的前提。未作修改也可以保存，此时不写入新的审计记录，但同样立即评估该用户并唤醒配额执行器。改重置日不会清空账本，也不会凭空赠送整期额度，重算可能立即触发配额暂停或恢复。用户名册、详情和订阅显示当前用户账期；全局用量页的本月／上月仍按自然月汇总。续期快捷操作「+30 天」「+1 个月」「+1 年」从现在、生效时间和当前到期时间中最晚的时间开始计算；按月／年延长时，目标月没有原日期则取月末。

服务未生效或已到期时暂停接入和转发，保留配置、手动开关、历史用量与控制台登录。续期仅恢复仍授权、仍手动启用且额度充足的服务；账期重置不能解除有效期限制。Console 每 60 秒评估有效期，保存策略会立即评估该用户并唤醒配额执行器。有效状态变化和授权同步工单、转发同步代次在同一事务提交，重启后可重试；每轮最多处理 128 个到期或生效用户，大批用户可能跨轮处理。节点离线或配置交接期间仍需等待节点收敛，界面显示到期不等于所有旧连接已经瞬时断开。现有 Agent/Xray 协议不新增字段，旧连接关闭能力沿用下文的接入配额说明。

策略及修改审计保存在运行态数据库，模型回滚不回退策略；暂停用户的授权在目标接入点仍存在时予以保留，以便续期恢复。结构升级仅由迁移 `0002_forwarding_rule_results.sql` 提供，`0001_init.sql` 保持不变。回退到不支持有效期的 Console 前，应先取消有效期限制并等待节点恢复，不能通过删除历史账本或工单解除暂停。

### 本期用量归零

有编辑权限的操作者可以点击用户详情「接入」或「转发」读数栏中「本期接入」「本期转发」右侧的「重置」，确认后同时重置该用户所有线路接入与机器转发的本期读数。原始计量、历史累计、全局自然月统计和节点计数器保持不变；用户详情、订阅流量头与接入/转发额度统一从归零分界重新累计。每月重置日、服务有效期及手动启停不变；下个正常账期自动不再扣除旧基线。随后调整每月重置日时，仍保留适用于新账期的归零分界。

因额度耗尽而暂停或限速的服务，在额度重新评估及节点同步后恢复；已过期或手动停用的服务不因此启用。操作本身不发布模型配置、不重启 Xray，也不要求清空 Agent 上的累计计数器。正在继续使用的用户，归零成功后可能很快显示新产生的少量用量。

归零与配额执行在事务内串行，接入执行器取得锁后重新校验停用或恢复条件，转发执行器取得同一控制状态锁后才读取本期用量并更新暂停状态。归零先提交时，旧停用计划不再生效；归零后新增用量已再次耗尽额度时，旧恢复计划也不再生效。

节点迟报的归零前流量继续记入原账本，同时补入归零基线，不重新消耗已归零的额度。跨归零时刻的实测采样窗口按时间比例分摊，精度受该采样窗口限制；缺少窗口起点的旧式转发读数按读数时间归属，既有计量缺口提示保留。细粒度原始样本过期不会使基线失效。

接口为 `POST /users/{tenant}/{user}/cycle-usage/reset`，权限与用户额度编辑一致。请求携带 32 位小写十六进制 `request_id`，以及账期查询返回的 `expected_reset_id`（首次为 null）、`expected_period_start` 和 `expected_period_end`。起止时间按接口返回的 UTC 字符串原样回传；重复请求返回原结果，不再清除新增用量，已经发生手动归零、自然换期或账期策略变化的旧确认请求返回冲突。归零事件记录操作者、账期、时间和前次事件；基线保存在运行态数据库，不随模型配置回滚。

结构追加在尚未发布的 `0003_unlock_probe_schedule.sql`；正式 v0.3.3 的 `0002` 保持原始字节。正式版本通过普通升级应用 `0003`。已经运行过旧开发版归零结构的环境须按 [Console 部署手册](../.agents/runbooks/console-deployment.md#本期用量归零归入-0003-与旧开发库兼容)核验精确旧 checksum、完整结构并演练受控转换，保留归零事件、用量基线和原始账本。兼容升级本身不会归零任何用户。

## 客户端订阅

koipy 测速订阅仅允许管理员（`system-admin` 或作用域内的 `tenant-admin`）查看、生成和撤销。普通用户自助订阅及编辑/发布角色的订阅响应不下发测速地址，普通 Clash 订阅不受影响。首次生成使用 `POST /users/{tenant}/{user}/clash-subscription/haitun`，重复请求返回现有有效地址；`DELETE /users/{tenant}/{user}/clash-subscription/haitun` 停止旧地址后续拉取，不自动生成新地址。撤销后可由管理员再次 POST 生成新 Token；重复 DELETE 保持首次撤销时间。移除直接重新生成接口，不提供 `/me/clash-subscription/haitun` 自助操作，无需数据库迁移。

**风险：测速地址是可转交的访问凭据，不要求测速客户端登录管理员账号。** 其内容包含用户 UUID 等真实节点凭据，持有者可以使用节点，应只交给可信服务。撤销仅停止后续拉取，不修改 UUID、普通订阅或节点授权，也不会触发发布；已下载的节点配置仍可使用。若凭据已泄露，需要同时撤销测速地址、更换用户 UUID 并发布授权，待节点生效后旧凭据才失效。收紧管理权限不会自动替换已签发的地址；管理员应对曾交给不可信服务的地址执行上述处置。

普通订阅地址 `/sub/v1/{uuid}/clash.yaml` 在拉取时按 `User-Agent` 的首个产品名协商格式：`Shadowrocket`（大小写不敏感，可带版本号）返回 Base64 编码的节点 URI 列表，其 `STATUS` 行展示 `↑:1.23G,↓:2.34G,TOT:21.21T`。单位按 1024 进位、最多两位小数；上传、下载和总额统一使用 `K/M/G/T` 等紧凑单位，不限量显示 `TOT:∞`。订阅状态文字不展示统计缺口，但保留原有 `x-brocade-usage-gap` 响应头供诊断。其余客户端、浏览器和缺少 UA 的请求仍返回原有 Clash YAML，`subscription-userinfo` 的键名和字节整数不变。UA 只决定表现形式，不参与鉴权；若客户端伪装成 Clash，仍会收到 Clash 格式。Haitun 测速链接固定返回专用 YAML，不受 UA 影响。

两种格式使用同一份已生效服务视图、地址/协议筛选和用户账期计费数据，不增加数据库查询或改变 Agent 协议。若当前筛选结果包含前置代理或自签证书，Brocade 现有通用 URI 导出器尚未完整实现对应的路由或证书信任信息，整份订阅保持 Clash YAML，不丢弃节点、不启用 insecure。这是当前导出实现的兼容边界，并非断言 Shadowrocket 或所有协议 URI 都不支持这些能力。此兼容路径仍使用标准流量响应头，暂不提供自定义状态文字。响应的 `x-brocade-subscription-format` 表示实际格式，`x-brocade-subscription-fallback` 标明 `front_proxy` 或 `self_signed_certificate`；所有响应继续禁止缓存，成功响应增加 `Vary: User-Agent`。流量重置时间与服务到期时间分别返回：`x-brocade-quota-reset-at` 表示账期结束，Clash 的 `subscription-userinfo` 仅在设置真实服务到期时间时携带 `expire`；长期有效时不提供 `expire`。

用户详情「接入」页签的「订阅」卡列出 Clash 订阅地址（koipy 测速订阅只给管理员），协议、地址族筛选只影响订阅地址；页面上遮住地址里的 Token，完整地址只在「显示」或「复制」时使用。「节点」卡把网络拨测与节点链接合在一起：一个接入点一行，格子写 IP + 端口与安全层 · 传输，点格子复制分享链接。URI 表达不了的条目（带前置代理、VLESS 自签入口）没有分享链接，格子里只有拨测状态，服务端的跳过说明写在矩阵下方。节点链接默认同时列出自签证书节点：这些链接带 `insecure=1`，客户端不验证证书，格子标 insecure。这只影响卡片里显示的链接，订阅地址与未带 `insecure` 参数的 URI 导出仍不启用 insecure。网络拨测从控制台发起，只给通过 / 失败与失败原因，不显示首字节时延。

## App 额度与用户限速

线路额度条的额度边界下方直接显示超额处理：未用满时写「用满后限速 N Mbps」或「用满后停用」；用满后改为黄色「限速中 · N Mbps」或红色「已停用」，服务不可用时显示灰色「服务暂停」。用量超过额度时，轨道按实际用量展开，额度边界保留在对应位置，超出部分以同色斜纹表示，百分比可以超过 100%。等待限速策略同步时，文字旁显示转圈和「同步中」。不限额不绘制额度条，服务暂停和同步状态仍直接显示。

用户页保留导航、名册、详情标题和页签框架；首次进入时，用量与当前可读的策略一起就绪后显示完整读数和状态。切换用户时不显示加载画面：暂留上一位用户的完整详情，目标用户数据就绪后连同姓名、额度和状态一次替换，不混用两位用户的数据。名册悬停、键盘聚焦或触屏按下会提前准备该用户的策略。未打开的「转发」「统计」页签按需读取，打开后保留同一用户的表单，换用户时重置。后台刷新保留已有内容；策略读取失败时在额度栏显示错误，不将失败解释为正常或不限额。

用户详情「接入」的每个 app 行独立显示用量、额度、剩余量和进度条，点击行内铅笔后，保留该 app 的用量与进度，在原行下方展开与转发授权一致的表单，编辑本期额度、常态限速及「用满后停用／限速」，保存或取消后收起。流量配额与常态限速各自可选：配额留空仍可立即限制速度，常态限速留空表示正常使用时不限速。填写配额后才显示「用满后」及超额速度。常态速度、超额速度均支持 Mbps / Kbps，切换单位保持同一速度，统一以 bps 保存，范围为 1 Kbps–1 Tbps。A app 用满只处理 A，B app 继续按自己的额度运行；不再设置或显示用户级接入总额度，也不合并不同 app 的额度。

常态与超额速度均是同一用户在同一个 app 内，跨所有机器、设备、连接与接入协议的上下行 payload 合计上限。同一 app 不按机器或连接重复发放速度，不同 app 的额度、用量和速度预算互相独立。端口转发的额度在各机器授权编辑器中设置，不占用 app 的接入额度或速度预算。

接入额度继续以 `user_app_quotas` 为唯一来源，在原行增加超额动作和速度；已有 app 额度默认保持「用满后停用」，无需重新设置或转换。普通停用沿用配额执行器和授权工单；超额限速保留授权与既有连接，通过 Xray 的实时用户预算调整速度。账期仍按用户 UTC+8 重置日，单／双倍计费只影响额度扣减，不改变速度单位。增加、取消该 app 的额度或进入新账期后，解除该 app 的超额限制并保留常态限速。超额降速与常态上限取较低值，超额停用和服务暂停优先；不会恢复手动撤销、手动停用或已到期的服务。

机器上限优先作为整机总约束：所有用户、app 和转发的合计不能超过机器上限，每个超额 app／转发同时受自己的速度上限约束。恢复或取消用户侧额度不会解除机器限速。

控制面按实际入账账本判断，超额状态每 5 秒执行一轮有界评估；停用沿用授权／动态转发收敛。Agent 用量采样约为 30 秒，因此存在采样、离线上报、评估及节点收敛延迟，不承诺最后一个字节处切换。超额后，各入口从同一用户/app 或用户/转发的持久化预算领取短期字节额度，Agent 本地平滑发送。单次预取最多为一秒速度对应的字节数、上限 16 MiB，有效期最多 2 秒，允许预算与数据块带来的短时突发。未消耗或丢失的预算不返还，重试回执幂等，Console 重启不重置发放时钟。

仅配置超额降速的策略在未超额时采用短期本地放行状态；配置常态速度后立即领取共享预算。策略／预算过期且控制面不可达时，无法确认状态的受管理流量会暂停，不静默解除限制。未设置限速动作的接入 app 保留原授权配额路径，不因升级 Agent 就要求更新 Xray。限速需要 Agent 协议 v44 和带 `user-traffic-limit-v1` 的受管 Xray，运行中的新旧代际共用 Agent 预算；界面提示缺少能力或等待同步的相关机器。建议先部署 Console，再升级 Agent/Xray，等待能力确认后启用限速。仍有限速策略时，Agent 拒绝启动缺少能力的 Xray；回退旧 Console 前先取消全部常态限速，并将相关 app 改为停用动作或取消额度、取消转发限速，并等待节点确认。旧接口的 404 不能解除已经确认的限制。

App 额度、超额动作、预算与审计沿用已发布的 `0002_forwarding_rule_results.sql`；独立常态速度由 v0.3.5 新增的 `0004_user_app_rate_limits.sql` 保存，已发布的 0001–0003 原字节不变。新安装执行完整的 0001–0004，官方 v0.3.4 的已有库只执行 0004，保留原额度、用量、预算时钟及迁移回执。应用 0004 后不能直接回退官方 v0.3.4；取消限速后仍须使用携带相同迁移且兼容现有数据的回退构建，详见[安装与升级](install.md#升级)。不删除迁移回执或改写 checksum 绕过校验。

## 接入配额

普通用户登录后可以通过 `GET /users/{tenant}/{user}/traffic-policy` 读取本人的接入额度、常态及超额限速策略，不能读取其他用户的策略或修改策略。查看其他用户时，页面沿用公开的用量与额度读数。访客不能访问策略接口；管理员读取仍受原有归属范围约束，修改仍需编辑权限。

用户名册按所有设有限额线路的合计用量与合计额度计算比例：已用不足 80% 显示「余裕」，从 80% 起显示已用百分比。详情中的单条线路额度条也从 80% 起使用注意色，用尽停用后使用告警色，超额限速保持注意色，并继续显示精确剩余量。注意档只影响展示，服务暂停仍按实际额度耗尽判断。

接入配额沿用授权自动化工单和 Agent 的 `SyncGrants`。带 `user-session-revocation-v1` 的 Xray 在移除授权时，VLESS 会取消并关闭该入站、该授权的现有 TCP/复用载体（含 Vision），Hysteria2 会关闭该用户的整个 QUIC 会话及其 TCP/UDP 流；AnyTLS 和 MTProto 保留既有按用户关闭语义。不关闭共享监听、不重启 Xray，其他用户及另一入站的同名授权不受这次撤权影响，累计计量不重置。认证和撤权竞争时会重新核对授权实例；重新授权只允许新会话，不复活旧载体。纯静态 Hy2 密码配置保持兼容，但动态用户全部撤销后不会回退到静态密码。VLESS UUID 和 Hy2 auth 在同一入站内必须唯一，拒绝以另一个用户身份覆盖现有凭据。

这项接入修复须单独发布 Xray；Console/Agent 的授权协议无需改变，也不能仅凭升级 Console 声称旧连接已关闭。计量、后台评估、工单和交接/离线等待仍决定实际延迟；配置交接期间既有授权队列的等待策略不变，不承诺瞬时硬限额。调高配额或跨月后，授权工单恢复访问，客户端重新连接；回退旧 Xray 会退回其原有撤权语义，不会复活已经关闭的套接字。

## 来源 IP 封禁

机器详情「配置 → 来源 IP 封禁」常开显示本机名单，影响这台机器的所有用户及动态端口转发。每行显示地址、地区与网络归属，可直接解除；点「封禁 IP」行内输入地址，红色「封禁」按钮即确认。输入时提示地址是否已在本机或用户名单中；添加表单打开时才读取在线来源，若有用户正从该地址使用这台机器，会提示封禁后断开。保存后标题显示这台机器的实际执行状态：同步中、已生效、待升级或执行异常；待升级和异常原因在正文显示。空名单也需要节点确认。

这台机器上有接入授权（含额度暂停）的用户封禁名单，收在卡底的头像、人数与封禁条数一行中；展开后按租户、用户只读列出，点击用户名进入用户详情管理。条数按各用户名单条目计数，同一地址可以出现在不同名单中；解除本机名单中的地址不会解除用户名单中的封禁。较长的本机名单和用户分组可点「显示其余」展开。旧 Console 未提供用户名单时明确提示升级，不把缺失数据当作空名单。两类名单地址都使用本地 GeoIP 补全归属；这是管理端查询和呈现的增补，不改变 Agent/Xray 协议或封禁执行方式。

用户级名单在用户详情「接入 → 在线设备」里管理。具有编辑权限的账号点时间线某一行复制钮旁的禁行钮，确认后封禁该来源；也可用卡底「封禁其他 IP」输入一个 IPv4/IPv6 地址，输入的是已知来源时，下方显示它的地区和是否在线。已封禁的地址移出时间线，在卡底「已封禁」一组列出最后出现时间、地区和接入链，可逐个解除；30 天内没有出现记录的写「30 天内未出现」，在线统计不完整时不作此判断。组标题显示整份名单在各相关机器的执行情况（已生效、同步中、待升级或异常），点开逐台列出。经过该来源的机器尚未确认当前名单时，仍在线的来源标为「仍在线」。只读账号看到的是脱敏后的地址前缀，不同地址可能同形，界面不据此对照在线来源，也不提供修改。用户级名单阻止该来源使用此用户的全部接入授权，保留其他来源和其他用户的访问。系统管理员还可在机器详情「配置 → 来源 IP 封禁」管理节点名单，阻止该来源使用这台机器的受管代理业务；不会修改宿主机 SSH、Console 或系统防火墙。节点名单也作用于动态 TCP/UDP 端口转发；用户名单仅作用于带用户认证的接入，不把无认证的端口转发来源冒充为接入身份。

两种名单同时有效：解除用户封禁不能覆盖节点封禁，反之亦然。名单接受单个数字 IP，不接受域名、端口、CIDR 或 IPv6 zone；IPv4-mapped IPv6 与对应 IPv4 合并。每份名单最多 256 个地址，全部名单合计最多 8,192 个地址，同步策略最多 2 MiB。名单读写接口与在线来源一样，附带由本地 GeoIP 得出的国家／地区和运营商（`source_countries`、`source_operators`），从未出现在在线统计里的地址也能显示地区。每次修改都带上名单版本，期间有人改过名单时保存被拒绝并重新读取，输入保留。解除后客户端需重新连接，已关闭的会话不会复活。

策略保存为独立运行态数据，不创建模型修订、不发布配置，也不撤销整名用户。实时通道连通时由 Console 推送变更，Agent 拉取名单并原子保存；等待 Xray 确认时每约 3 秒复查，确认后每约 60 秒上报一次，确认有效期为 180 秒。没有实时通道时保留每约 3 秒轮询。界面在有机器待同步时每 3 秒刷新执行情况，其余时候每 30 秒；Xray 每约 250 毫秒检查本地策略，拒绝命中的新会话并关闭已有载体。VLESS 包含 TCP、Vision 和复用载体，AnyTLS 关闭认证会话，Hysteria2 关闭整个 QUIC 会话及其 TCP/UDP 流，MTProxy 在认证后检查并关闭连接。认证与封禁并发时仍重新检查策略。两代 Xray 共用策略文件，Agent 按 PID、启动 ticks 和 boot ID 核验每代实际应用回执，界面显示「已生效」「待同步」「待升级」或「执行异常」；保存成功不代表离线节点已经生效。等待 Xray 读取新名单或完成代际切换显示「待同步」，应用失败、回执身份或版本异常才显示「执行异常」。网络与调度影响实际延迟，不承诺瞬时断开。

判定使用实际传输来源。Hysteria2 的 QUIC 会话若因连接迁移换了对端 IP，Xray 也会在下一轮本地检查时重新判定，命中名单就关闭整个会话。受管 Xray 启用此能力后不采信客户端可写的 HTTP `X-Forwarded-For`；外部反向代理后的来源按代理地址判定。受管 XHTTP 独立下载前端通过仅监听 loopback 的 PROXY protocol 后端保留来源，需发布本次生成的新配置；旧配置或尚有旧代交接时会显示具体等待原因，不确认已生效。外部可信代理名单和按终端 IP 的代理头信任不在此功能内。

控制面离线、Agent 重启或模型回滚不会清空已保存的名单。损坏或倒退的策略不能静默解除既有封禁，可由认证的 Console 完整快照恢复；新进程遇到损坏的检查点会拒绝启动。需要 Agent v45 和带 `source-access-v1` 的 Xray；仅升级 Console 不会更新节点。仍有封禁时 Agent 拒绝启动缺失该能力的旧 Xray。回退前如需解除，应先在新控制面清空相应名单并等待节点确认。

本次表结构位于 `0002_forwarding_rule_results.sql`，不新增迁移；包含策略、全局版本、审计事件和节点回执。已应用早期不同内容 `0002` 的数据库不能通过改写 SQLx checksum 绕过升级校验。

## 在线设备

新系统初始化时，「设置 → 在线来源」默认开启「记录公网 IP」，用于显示在线设备和来源流量。升级保留已有设置；已保存的关闭选择不会自动改为开启。

用户详情的「在线设备」是一条按公网来源 IP 排列的时间线：在线来源在最前，最近 30 天已结束的在线周期按最后出现分到今天、昨天、7 天内与 30 天内，来源封禁名单在卡底单独成组（见上文「来源 IP 封禁」）；打开详情即读取离线来源，在线来源集合变化时重新读取。每行按 ingress 反查并合并为实际接入链，不展示入口机器；同时显示当前连续在线周期的流量、在线时长和 Console 上次接受该来源快照的时间。来源流量由 Xray 按用户、入口和来源 IP 直接计数，不从月用量或机器用量推算；来源完全离线或 Xray 重启后重新起算。旧 Agent/Xray 未上报会话字段时显式显示「—」。本地 GeoIP 仍提供国家／地区及可识别的中国运营商，支持 IPv4、IPv6 和 IPv4-mapped IPv6；查询不会把来源 IP 发给外部服务，也不把归属信息写入 PostgreSQL。同一 IP 跨节点或多条接入链使用时，全局来源数只计一次，各链保留自己的协议和会话指标。

同一 IP 已结束的在线周期按最后出现时间从近到远排列：同一 IP 的组内最早与最晚记录时间跨度不足 1 小时就合并成一行，跨节点、接入链和日期也可合并；恰好 1 小时或更长则另起一行，不按相邻间隔不断延长合并范围。合并行按最新记录归入日期分组，显示最新时间、接入链与协议汇总、记录段数和累计流量；任一段缺少流量时，合计也保持未知。展开后逐段保留原始时间、接入链、协议、流量和在线时长，不把断开间隔算作连续在线。历史不并入当前在线行，同一 IP 可以同时有一条在线行和多条历史行，卡头地址总数仍按 IP 去重。历史默认显示合并后的最近 5 条，其余使用时间线底部统一的「显示其余 N 条历史记录」展开。

每个周期按节点和入口记录，同一公网 IP 同时经过多条接入链时，各链分别保留周期，不将重叠时长相加。已封禁地址的历史会话也保留在日期分组中，封禁名单及解除操作集中在卡底；只读账号的 IP 已脱敏，相同前缀可能属于不同地址，历史逐段显示，不据此前缀合并。历史只在打开用户详情时读取，并每 30 秒刷新；在线地址或接入周期变化会立即重新读取。

成功快照中来源消失，或 Xray 上线时间变化／流量计数回退时结束旧周期；统计失败、缺失或过期只表示状态未知，不据此制造离线记录。结束时间是 Console 确认周期结束的快照时间，流量是结束前最后一次成功采集的观测值，可能少于实际最终流量；它们不替代计费用量。旧 Agent/Xray 缺少周期字段时，连续成功快照仍属于同一周期，但无法识别两次快照之间的断开重连，时长保持未知。

历史沿用「设置 → 数据保留」中的用户在线来源保留期（默认 30 天），每次最多读取最近 256 段已结束周期，超出时显式提示；地址总数在历史截断时标为「至少」。新逻辑从升级后开始保留，旧实现已覆盖的周期无法恢复；升级会保留尚存的在线与离线记录。

接入协议跟在各自的接入链之后列出（VLESS / AnyTLS / Hysteria2 / MTProxy）。协议来自 Xray 已认证入口的连接引用，不根据配置、端口或嗅探到的 HTTP/TLS 猜测；同一 IP 可同时使用多种协议，断开一种后下一次快照会移除它，不改变来源计数和计费标签。每段历史保留该周期最后观测到的协议和会话指标，不是逐连接审计。旧 Agent/Xray 或旧观测缺少字段时显示「协议未知」。这些可选字段不提高最低 Agent 协议版本；完整展示需要对应版 Xray 和 Agent 都已发布，单独部署 Console 不会升级它们。已有数据库按 [Console 部署手册](../.agents/runbooks/console-deployment.md) 做受控兼容处理，全新安装由程序按序执行内嵌迁移。

运营商索引独立于国家库及 Xray 路由规则，使用 MIT 许可的 [gaoyifan/china-operator-ip](https://github.com/gaoyifan/china-operator-ip) 中电信、移动、联通、教育网、科技网五类双栈网段。Console 后台每天从同一提交版本下载完整列表，校验成功后整体替换内存索引，并在 `BROCADE_CACHE_DIR/geoip-china-operators-v1.json` 保存重启缓存；失败时保留上次有效数据并退避重试。首次下载未完成不阻塞页面，来源接口只查询本地内存，不需要 Agent 升级或数据库迁移。

常态速度独立保存在 `user_app_rate_limits`，新增迁移 `0004_user_app_rate_limits.sql`，0001–0003 保持不变。删除额度、归零或账期重置不会删除常态配置或重置仍在使用的共享预算时钟。策略、审计和通知在同一事务提交，不触发模型配置发布或 Xray 重启。旧 Console 缺少 `base_rate_supported` 确认时，前端禁用常态限速输入并提示升级；写入未被读回确认不会显示保存成功。

兼容旧版管理客户端：策略写入省略 `base_rate_bps` 时保留现有常态上限；只有显式传 null 才清除。该保留操作与同一用户的并发策略修改在事务内串行。
