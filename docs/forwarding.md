# 端口转发

用户端口转发的可见范围、目标地址防护、用量与配额。

## 可见范围

用户详情的「转发」页签向访客开放只读查看，保留机器、规则协议、状态和用量。访客及只读操作者收到的地址、目标域名、端口与授权端口范围均在服务端脱敏，规则名称和错误详情隐藏，避免从这些字段还原目标；访客不能修改规则、授权、配额或执行拨测。普通用户仍只可读取和管理本人的完整转发规则。

创建或修改转发入口授权时，租户管理员必须同时具有用户所属租户与入口机器所属租户的权限，范围包括其子租户。知道其他租户的机器 ID 不会获得授权；越权请求返回 403，且不改变已有授权或节点同步版本。系统管理员可显式授权跨租户入口。

## 逐条同步与连接影响

新增规则时，仅新规则显示「同步中」；未改变的旧规则继续显示「已监听」，已有 TCP 连接与 UDP 会话保持，其他用户在同一入口上的规则也不受影响。机器摘要按当前用户的规则显示正常、同步中、失败和待确认的数量。只改名称不推进节点同步版本，也不重装监听。

单条安装失败只在该规则显示原因。Agent 会记录自己正在安装的规则，清理失败或中断留下的半安装监听，再独立重试；端口冲突解除后会自动恢复，不必删除重建或重启 Xray。无法证明由本次安装留下的既有监听仍保留并报告错误，避免误断正在服务的连接。

修改目标、入口端口或协议仍会重建该条监听，关闭该规则已有的 TCP 连接；编辑器在保存前说明影响范围，其他规则继续运行。禁用、删除或撤销授权也会关闭受影响规则的连接。此版本不提供单条目标编辑的连接排空切换。

有效期或配额暂停只撤销对应用户的监听，续期或恢复额度后按原规则重新建立；同节点的其他接入与转发继续接受新连接。本版本同时修复 Xray 代际监听组在运行时移除转发监听后无法恢复的问题，启用这项行为需同步更新内嵌 Xray。监听被撤销后，尚未关闭的连接仍纳入代际排空检查。

超过 90 秒没有收到匹配的运行回报时，规则显示「状态待确认」，详情保留上次回报时间；缺少回报不能当作正常或确认断流。「已监听」仍不代表目标可达，目标可达性通过独立拨测判断。

逐条回执使用 Agent 协议 v41。数据库变更独立保存在 `0002_forwarding_rule_results.sql`，不修改 `0001_init.sql`。新安装依次执行两份迁移；已有数据库的 `0001` 与本版本基线一致时，更新后的 Console 启动会自动应用 `0002`，添加 `forwarding_node_state.rule_results` 并记录迁移结果，无需手工执行 SQL 或修改 checksum。升级前仍须备份并验证恢复；更早且初始定义不同的历史数据库需要先接入兼容基线，见[安装与升级](install.md#升级)。先更新 Console，再更新 Agent；无需为这项修复单独更新 Xray。

旧 Agent 的成功回执可按当次完整期望状态恢复逐条结果；旧 Agent 失败回执缺少定位证据时显示待确认。新 Agent 的新增字段可被旧 Console 忽略，但旧 Console 仍按原来的节点级方式显示状态。回退 Console 时须使用识别 `0002` 迁移历史且兼容新增列的回退构建；不能直接启动只认识 `0001` 的旧二进制，也不删除迁移记录来绕过校验。回退 Agent 时保留本地安装记录，不清空规则或计量状态。

可重复 Docker 验证见 `scripts/tests/forwarding-continuity/README.md`。

## 目标解析与地址防护

新授权默认拒绝私网。显式允许私网时可访问 RFC1918、CGNAT 和 IPv6 ULA 地址；回环、链路本地、云元数据和其它特殊地址始终拒绝。Console 在规则写入时检查 IP 字面量；保存授权和节点领取期望状态时，也会停用违反当前策略的存量 IP 规则，保留规则标识与历史用量。之后重新允许私网不会自动重新启用这些规则。

已知元数据端点也保留独立拒绝项，包括 [AWS 的 IPv6 IMDS](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/instancedata-data-retrieval.html) `fd00:ec2::254` 和[阿里云元数据服务](https://www.alibabacloud.com/help/en/ecs/user-guide/view-instance-metadata/) `100.100.100.200`，不会因允许 ULA 或 CGNAT 而放行。

每条动态转发规则携带目标策略。域名由入口 Xray 在新连接建立时解析，在 TCP 的实际 socket connect 前、UDP 的每次目标发送前检查最终 IP，包含系统 DNS、IPv4 映射 IPv6 和缓存结果；不会用一次 DNS 预检查替代拨号检查。转发固定使用专用直连出口，不能被模型路由转入丢失地址策略的代理链。Agent 按 15 秒周期先撤销再独立增改规则，单条失败不阻止其它规则收敛。

只修改私网策略不会重新生成整份模型配置。目标、协议、监听端口均未变化的公网 IP 规则保留原监听与连接；域名规则需要替换旧的无策略监听，收紧权限时不得因安装失败恢复原来的宽松监听。被停用或撤销规则的已有 TCP 连接会由带 `forwarding-close-connections-v1` 能力的 Xray 关闭；界面的「已监听」只表示入口安装完成，不表示目标可达。域名策略允许的既有连接不会仅因 DNS 记录变化主动迁移。

本项加固使用 Agent 协议 v43 和 Xray 的 `forwarding-target-policy-v1` 能力，不需要数据库迁移或额外发布一份静态配置。先更新 Console，再更新 Agent，最后按现有发布流程更新 Xray：旧 Agent 只领取公网 IP 规则，域名与私网转发暂停并提示升级；新 Agent 遇到旧 Xray 时保留未变化的公网 IP 监听，其它目标暂停，新的受保护监听也须等待新版 Xray。首次 Xray 二进制更新仍执行现有平滑交接或已批准的重启流程，不能把“无须重发配置”理解为“二进制升级保证零中断”。

Agent 从正在服务的 API 查询能力，不依赖已安装文件的版本；受保护监听使用独立的 protobuf 类型，旧 Xray 即使在混合版本交接中接到请求也会拒绝，不能静默忽略新增策略字段。新版 Xray 拒绝没有目标策略的 `fwd:` 监听。只升级 Console 不等于完成节点防护。回滚 Agent/Xray 会影响安全能力或规则恢复，须先停止域名与私网转发；不要通过回退地址策略恢复不安全的监听。

## 用量

转发用量保留独立事实账本，与接入账本按查询边界合计：用户本月、用量页每日/月累计、机器 XRAY 月量/角色曲线和容量预测均纳入转发；物理网卡账本已经包含转发，不能再叠加一次。规则移机、撤销或删除不删除历史归属；收据指纹、持久计数头与顺序检查保证重放不重复记账，Agent 实例变化不重置连续计数。细窗口可清理，日汇总持续保留；首读、同秒尾部和旧数据没有实际区间时只显示总量，不伪造曲线。按线路的订阅额度维持接入口径。已有部署的兼容、独立 Agent 29 发布和回滚边界见[部署手册](../.agents/runbooks/console-deployment.md#转发统一统计兼容)。

## 账期配额

转发仅提供每台机器的独立额度，不再提供或执行用户转发总额度。旧总额度配置由完整 `0002` 的退役段归档，原机器额度、用量和手动规则状态保留；已有旧预算缓存会随完整策略快照更新解除。

系统管理员和所属租户管理员可在用户详情「转发」的机器菜单中设置独立的账期流量配额（GiB，留空不限制）。按用户 × 机器、用户配置的 UTC+8 账期累计上下行，删除规则不会清除已用额度，也不占用线路接入配额。Console 每 60 秒评估，修改配额后立即唤醒评估；耗尽时用持久 `forwarding-quota` 工单暂停该用户在该机器上的全部转发，调高或取消额度、进入新账期后自动恢复。服务有效期和配额分别限制转发，恢复配额不能解除未生效或到期限制。暂停层不改写规则的手动开关；已禁用、删除、撤销授权的规则不会自动开启。工单分页可查，节点离线或移除失败时保留待执行/错误，只有匹配当前完整期望状态的节点回执才能确认完成，更新意图会取消旧待执行工单。计量上报、后台评估和节点收敛均有间隔，不是逐字节硬限额；配置/Xray 交接期的旧进程也须完成排空，暂停不能视为瞬时全局断流。

现有数据库需在备份及隔离恢复演练后使用 `scripts/compat-forwarding-quota.sql` 应用目标 `0001_init.sql` 中的 `BEGIN/END FORWARDING QUOTA SCHEMA` 块，并单独核对 SQLx 兼容与对象所有权；脚本不设置额度、不删除历史。启用前必须独立发布并验证带上述连接关闭能力的 Xray，不能只升级 Console 后声称已有 TCP 会话也已停止。回滚 Console 不会自动解除已下发的配额暂停，应先取消配额并等恢复工单成功，或使用支持该暂停层的版本恢复；不得清空用量、作业或手动状态来回退。
