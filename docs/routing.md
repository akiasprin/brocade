# 接入与出口

接入保护、TCP 保活、外部隧道与出口拨测。VPN Gate 出口见 [VPN Gate](vpngate.md)。

## 链路规则编辑

链路规则在链详情和机器详情中默认显示链路可视化，并显示流量的匹配条件。切换到列表编辑后，链详情和机器详情均默认全部收起；点击机器行头可单独展开或折叠规则表，折叠保留未保存的输入。

规则按顺序匹配，只配置匹配条件和处理目标。匹配类型和内容是两个独立控件，「传输层」规则可选 TCP 或 UDP。转发目标使用可搜索、分组的目标菜单；连接方式菜单列出各档实际连接的地址，最后一项可直接填写自定义地址，地址跟在连接方式之后、过长时省略。指向同一目标的规则共用一条连接；监听端口、承载协议和 Mux 在规则表下方的「下一跳」统一修改，这里同时列出反向接入、引用的其他链监听和代理出站。明文暴露、端口冲突、VPN Gate 不可接入、WARP 缺身份以行内 ⚠ 标记提示，点开查看原因。反向连接的端口属于本机；引用其他链的监听时，源监听的端口、安全参数和规则仍由来源链维护。

规则列表按每台机器编辑器的实际内容宽度在表格、双行和紧凑列表之间重排，不按设备类型切换。中宽时匹配与动作上下排列，并共享固定的类型列和弹性内容列，匹配内容、转发目标与连接方式沿同一列线对齐，操作按钮与第一行对齐；窄屏下每条规则是一张卡片，卡片头放序号与操作按钮，「匹配 / 动作」标签在左，同组字段改为等宽单列。机器 DNS 解析策略面板使用同一套骨架和描边下拉：中宽时「自定义 DNS 解析」落在类型列，DNS 地址与传输、地址策略、失败处理落在内容列。连接方式和地址仍保持同一行，长地址只在自己的空间内省略；空间不足时，DNS 解析方式和「查看」会重新排列，确保「查看」可用。LISTENER 目标紧凑显示名称与端口，本机监听的连接地址显示为 `本机回环:端口`，与普通地址使用相同的文本样式。只读视图中的「下一跳」承载协议允许换行；未登录的访客不显示规则编辑按钮，仍可查看 DNS 策略和 Mux 参数。

新建链的「路径」使用同一套规则表、菜单与弹层，入口和刚加入路径的机器默认展开；改动在提交时与链一同加入草稿，不经过链路规则的保存条。

路径底部的「添加下一跳」将所选机器接到主干末尾，按钮旁显示实际接续的机器；菜单支持按机器名称或 ID 搜索。已有支路保留，各机器内的「加一条」用于添加该机器的匹配规则。没有可添加的机器时，按钮禁用并显示原因。

规则编辑器和建链向导的转发目标菜单中，「自定义」直接打开手动配置，可填写代理服务器的 IP／域名、端口、协议及所需凭据，也可切换为粘贴分享链接。创建后自动选为当前规则的目标，与规则一起保存到草稿。「复用其他链的监听」是独立入口，按来源链选择已有监听，端口、安全参数和后续规则跟随来源链。

DNS 策略整机生效：出网规则的「默认 / 自定义 DNS 解析」右侧为「查看」，打开「本机 DNS 解析策略」弹层编辑；机器没有出网规则但已有策略时，入口在规则表下方的工具栏。折叠机器保留尚未保存的输入，「还原」恢复本面板的编辑，「保存到草稿」统一保存改动；提交与配置发布仍由顶栏执行。只读角色可以展开和浏览所有机器。DNS 策略弹层和机器详情的只读视图（含未登录访客）使用与编辑时相同的控件和排版，仅禁用编辑，不提供删除、复制和排序操作。选择菜单支持方向键、回车和 Escape，手机从底部展开。

每条链在规则卡内有独立标题行，右侧的列表／分叉图标开关可切换「列表编辑」和「链路可视化」，默认显示链路可视化。机器详情的标题显示本机角色及规则数，点击链名打开线路详情；各条链的视图和追踪输入互不影响。切换保留未保存的规则输入。

可视化的机器标题将监听端口放在角色文字之前，同一行显示：入口显示「:8448 入口」；其他节点标明监听用途，例如「中转 :20012 / 出口」，中转和引用节点沿用这一格式。可视化按机器逐行展示规则，转发规则连到目标机器，出网、代理和拒绝显示在行尾；手机及窄面板改为竖排卡片。连接方式、承载、Mux 和编译器补齐来自编译视图；未保存的连接改动显示「待编译」。引用监听继续展示所属链的规则，同一机器在不同链上的监听分别展示。点击机器、规则或连接可检视详情；「在规则表中查看」只切换当前链、展开机器并定位高亮对应行，引用监听则打开它的所属线路。

画布使用随明暗主题变化的波点背景，入口机器的标题栏默认带有浅色强调底。宽画布中可拖动机器卡片标题调整位置，连线和连接标签跟随移动；聚焦标题后可用方向键微调，按住 Shift 每次移动 1px，Home 恢复该卡片的位置，拖动中按 Escape 取消。位置只保留在当前视图，不修改规则或草稿；窄面板仍采用竖排卡片并保留触屏滚动。虚线流动表示配置中的连接方向，不代表实时流量；已被覆盖的规则连线和系统「减少动态效果」模式保持静止。

追踪输入位于可视化图顶部中央，输入、框内清除和 TCP／UDP 分段控件组成胶囊。点击或聚焦输入后展开常用域名菜单，包含 Google、YouTube、ChatGPT、Claude、Muse 和 GitHub，并带本地单色图标；支持方向键、Enter 选择和 Escape 收起，输入时收起菜单。输入支持域名、IP 和可选端口；下方展示经过的机器、终点动作或待确认的规则与原因。geosite 使用设置中的全局统一规则集，由 Console 加载同源数据库判断域名归属，命中后继续沿下一跳追踪，确认未命中时继续检查后续规则；支持分类属性（如 `google@cn`）。Console 按来源缓存规则集 24 小时，更换来源后立即重新加载，不要求逐节点读取文件。规则集暂时无法加载、分类不存在或条目无法确认时明确停止，不将未知当成未命中。

追踪仍是配置预览，不保证真实流量命中：遇到需要目标 IP 解析、geoip 或节点嗅探结果的规则就停止；独立域名正则留给 Xray 引擎判断。DNS 检视展示机器上配置的完整策略，不根据域名样本标记「DNS 本链用不到」。

## 匹配值校验与规则集预览

geosite 和 geoip 使用单行多选器，只能从「设置 → 规则库更新」所配置的同源文件中选择。长列表折叠为 `+N`，点开可查看和移除全部已选值。geosite 的主题集合使用灰黑实底语义图标（AI 直接显示 `AI`），地区与顶级域使用浅灰底图标，具体服务使用本地单色品牌标识，未映射服务使用文档图标；geoip 的地区用旗帜，私有网段用锁形图标，其他特殊网段用 `IP` 标识。

选择菜单按分组浏览：左侧是「常用」「本条已选与已用」、分组和「A–Z」，右侧是该组的分类，每行显示条目数，属性作为行内标签，点击即加入 `名称@属性`。geosite 的「常用」与订阅规则的标准模块和服务目录使用同一份 geosite 列表；分组有「地区与汇总」（`cn`、`geolocation-*`、`tld-*` 等）以及 AI、影音娱乐等主题，服务按完整包含它的最窄 `category-*` 归入主题，归不进去的列在「未归类服务」。同族的地区变体折叠成一行，如 `category-ai` 下的 `-!cn`、`-cn`、`-ru`。geoip 按大洲分组，其余代码列在「其他」。A–Z 按首字母分页，每页最多 80 个，其余分组同样分批显示，不会静默截断。

输入用于搜索：完全一致的名称排在最前，其次是整段一致（搜 `cn` 时的 `geolocation-cn`、`tld-!cn`），再到前缀和包含；同一档内条目多的在前。侧栏显示各组的命中数，点击可只看该组。`名称@` 列出该分类的属性及条目数，`@属性` 列出所有带该属性的分类；geoip 也可以按中文地区名搜索。拼写不匹配时显示相近选项，由操作者选择替换；回车只加入完全一致的输入，或用方向键移到的选项。输入完整域名时按条目数由少到多列出包含它的 geosite 分类，标出最精确的一项和条目上万的汇总集，并显示命中的条目。已选值集中显示在搜索框下方；本条或前面规则已有更宽的分类时，被包含的选项不可选，并注明原因。桌面上选择菜单距匹配输入框边缘 2px，下方空间不足时改在上方展开，校验提示不改变锚点。视口宽度不超过 820px 时使用贴附字段的浮卡，最高 320px，随可见空间向上或向下展开并避开软键盘；直接在原字段搜索，行尾「完成」收起。打字时只显示最近一项及 `+N`，点 `+N` 管理全部已选。分组横向滚动，属性通过结果行的「N 属性」展开；「查看条目…」位于分组栏。

菜单底部「查看条目…」、已选值，以及设置中的「预览」均可打开规则集浏览器。左栏依次列出打开它的那一行已选的分类（如「D1 已选」）、其他规则已用的分类和「全部 A–Z」，搜索与选择菜单使用相同的排序。右栏头部一行显示分类、条目数和对那一行的操作：「加入 D1」「已在 D1 · 移除」，查看同名分类的其他属性时为「把 google 改为 google@cn」，被同一行或前面规则的更宽分类包含时注明原因并禁用。属性带条目数；「包含于」列出完整包含它的分类，「包含 N 个分类」「引用 N 处」展开被它完整包含的分类和引用位置，均可点击跳转。分类、条目数、属性条目数、分类间包含关系与引用位置由后端提供；包含关系在每次加载规则集后按真实条目精确计算一次并缓存。

条目按类型分节（geosite 依次为后缀、完整、正则、关键词，geoip 为 IPv4、IPv6），节内保持文件顺序，每节按条目长度排成多列；类型和属性都可用来过滤。条目由服务端筛选和分页，每次 200 条，滚动到底继续加载，一次最多展开 2,000 条，其余请用筛选缩小范围。同一个输入框按子串筛选条目；输入完整域名（geoip 为 IP）时同时检查是否命中，命中时写明由哪几条条目匹配（最多列 8 条），未命中时列出包含该域名的其他 geosite 分类，含 Xray 才能确认的条目时标为「待确认」。按域名反查（`GET /routing/geodata/lookup?domain=`）使用同一份 geosite 规则集，含 Xray 才能确认的条目时注明这类分类的数量，不当作未命中。设置中可在保存前预览新来源，查看当前引用中缺失的分类。浏览和反查只需读取权限，预览未保存的来源需要系统管理员权限。手机上浏览器分两级：先选分类，再看条目，标题行左侧返回。

「加 AI 组合」要求当前规则集同时包含 `huggingface` 和 `category-ai-!cn`，在 AI 分类之前加入 Hugging Face 直出规则。已有匹配会复用，重复点击不会重复创建；已有 Hugging Face 例外在后面时会前移。

线路规则与本机 DNS 策略保存到草稿前先请求后端检查，最终提交在持有控制状态锁的事务内对整批结果再次检查，任何错误都回滚整批写入。校验覆盖匹配格式、分类与属性存在性、完全重复和前面更宽规则已包含的值；同条列表按「或」判断，窄规则写在宽规则之前作为例外允许保留。不同链的规则表和本机 DNS 策略分别比较。包含关系使用 dat 中已展开的真实条目集合，不能证明包含时不推断为包含。

切换页面时，尚未完成或匹配值有误的线路规则仍保留在浏览器本地草稿中，提交时继续由后端校验。显式保存期间暂时禁用规则编辑及本机 DNS 弹层；统一保存时整棵规则树共用该状态，保存结束后恢复编辑。完全重复检查会保留嵌套「且」条件中的端口等限制，带额外限制的前置规则不会覆盖后续仍可匹配其他流量的规则。

关键词产物统一使用 `keyword:` 前缀；IP 匹配不接受 `geoip:`、`ext:` 等混入的类型或文件前缀。端口、CIDR、域名等纯校验与编译器共用实现；cron 的结构校验也在 core，时区和完整 cron、RE2 正则另由 Console 调用本次内嵌的 Xray 解析。界面错误只占一行，后端拒写时返回 HTTP 422 和 `issues`：`location` 为线路/链/机器或 `dns/机器`，`rule` 为从零开始的规则位置，`field`、`value`、`message` 定位具体字段。前端据此显示错误并定位规则。

规则集正常加载期间，匹配输入框保留已选分类，不额外显示状态文字，避免规则行高度变化。规则集无法加载时，新增或修改的分类拒绝保存；同一张表中未改的旧值保留并标记「未确认」。更换来源时必须加载成功并确认已有引用仍有效。Console 缓存每个来源 24 小时，来源变化立即重载，失败重试间隔 30 秒。发布前复查、节点规则集时效上报及节点产物预检暂缓；发布继续沿用现有编译诊断与节点收敛流程。

## REALITY 指纹兼容

内置 Brocade Xray 的上游基线为 `v26.10.31`。服务端保留旧 TLS 1.3 X25519 ClientHello 的兼容入口，旧客户端的 `edge / ios / qq` 可继续连接；现代混合 ML-KEM 握手沿用上游校验。兼容入口仍校验密钥、SNI、short ID 和时间，不接受声明混合组却剥离其 key share 的输入，也不让旧指纹获得后量子密钥交换能力。

TCP 监听默认关闭 MPTCP，不再继承 Go 的默认开启行为；显式设置 `sockopt.tcpMptcp: true` 仍可请求启用。该变更作用于新建监听，FD 热交接保留旧监听的实际协议；要关闭已有 MPTCP 监听，应先在宿主机禁用并重建相关监听。此项是针对 CVE-2026-98432 的应用侧缓解，不能替代 Linux 内核安全补丁。

服务端 `realitySettings.allowLegacyX25519` 缺省为 true，已有发布快照无需重写；手工配置可显式设为 false，恢复上游仅接受现代混合握手的策略。该字段是 Brocade 扩展。版本横幅另声明 `reality-legacy-x25519-v1` 与 `reality-empty-ee-v1` 能力，官方二进制不提供这些兼容约定。

新版同时修复 cover 的空 EncryptedExtensions 无法容纳可选 SNI 确认扩展的问题，并规范本机 `randomized` 指纹中声明混合组却未生成对应 key share 的情况；固定浏览器指纹保持原始格式。旧外部客户端自身的随机握手缺陷仍需更新客户端，不能只升级服务端解决。升级生效须发布新版 Brocade Xray；只更新 Console 不会替换节点运行时。

## REALITY 回落限速

新建 VLESS REALITY 接入及启用 AnyTLS REALITY 时，fallback 限速默认使用「严格」：上传超过 256 KiB 后约 64 KiB/s，下载超过 1 MiB 后约 256 KiB/s；编译时按入口生成稳定的 ±10% 扰动。该限制只作用于未通过 REALITY 验证的回落连接，不限制已认证用户的代理吞吐。修改其他字段不会覆盖已有明确选择；存量入口需要通过草稿和配置发布切换档位，历史快照中缺失的策略仍按原来的关闭语义读取。

## TCP 保活

受管 TCP 入站（包括 VLESS、AnyTLS、MTProxy 和中继）在节点配置中显式开启 TCP keepalive：空闲 300 秒后探测，无响应时每 90 秒重试，连续 3 次失败后由内核关闭连接；探测次数通过 Linux `customSockopt` 固定，不依赖宿主机 sysctl。健康的空闲连接仍可复用，不因 5 分钟没有业务流量而被保活机制主动关闭。纯空闲连接失联的最坏检测时间约为 570 秒，之后还需 Agent 上报和页面刷新；已有未确认数据时由 TCP 重传或单独设置的 `TCP_USER_TIMEOUT` 决定，不承诺所有场景的固定离线时限。API、Hy2/QUIC、出站和客户端订阅不受此策略影响。新渲染的配置需经配置发布生效，已建立的旧连接不保证获得新参数；不会通过授权同步自动修改，也不为此重启全部节点。

保活优先于 MPTCP：旧内核 MPTCP（例如 Linux 5.15）无法应用保活配置时，Xray 在新建监听时回退普通 TCP，包括显式开启 `tcpMptcp` 的配置；普通 TCP 也无法应用时明确报错，不带着失效保活继续服务。Linux 启动与 FD 交接会回读校验实际参数；交接保留已回退的真实 TCP 协议、身份与配置摘要，不修改共享监听来掩盖不一致。因此本功能需要更新 Xray 并发布新配置，不能只更新渲染配置。经过 CDN 或反向代理的连接，TCP 保活也只能确认直接 TCP 对端的可达性，不能代替终端应用心跳。

## 中继 Mux 参数

规则中的 Mux 可跟随全局参数，也可单独配置。数值框允许先清空再逐键输入；参数未填完整，或不满足范围与交叉约束时，不能应用。应用先更新当前规则编辑状态，保存到草稿、提交修订并发布后才影响节点。

## 反向链路健康与排空

反向专用 VLESS 凭据只建立反向载体连接。Brocade 不再为中继出站生成普通 HTTP Observatory 探测；反向连接使用独立的双向探测、租约与健康 RPC。渲染调整通过新配置发布生效，历史修订保持原有内容。

默认健康失败先隔离 worker，保留已接入的业务连接。最后一个会话退出后，还需确认已排队的数据与结束帧被对端处理，才关闭载体；确认最多等待 10 秒，与较短的健康隔离期限分开。版本横幅中的 `reverse-drain-fence-v1` 表示支持该行为；双端排空保护需要升级反向链路两端的 Brocade Xray。显式开启健康失败断开连接时仍按该策略执行。

Hy2 服务端初始 QUIC 包从 1200 字节开始，再由 PMTU 探测增大，已验证 IPv4 接入在 MTU 1280 的路径完成握手。旧入口仍使用原来的初始包行为，升级出口不能修复旧入口的低 MTU 握手问题。

## WARP

WARP 使用 Xray MASQUE 出站，默认 HTTP/3（UDP/443），也可在隧道参数中选择 HTTP/2（TCP/443）；两者都承载 TCP/UDP 业务，不自动互相回退。Endpoint 默认 `162.159.198.2:443`，TLS SNI 固定为 `consumer-masque.cloudflareclient.com`；设备使用 P-256 密钥认证并校验注册返回的服务端公钥。隧道内 DNS 默认 `1.1.1.1`、`1.0.0.1`，域名目标通过 WARP 查询。

申请流程仍是“创建并提交隧道 → 按机器同意条款并申请身份 → 发布”。注册适配器先创建临时设备，再登记 MASQUE 公钥；登记失败会注销临时设备。密钥和设备令牌加密保存，草稿预览不调用 Cloudflare。WARP 不再接受 WireGuard 的 MTU、Keepalive、Allowed IPs、TUN、Workers 和 reserved 参数；旧 WG 身份不能复用，需重新申请。此变更不兼容旧 WARP 模型和绑定数据，升级已有安装前须完成旧绑定清理与重新注册；运行时仅接受 MASQUE 格式，不转换旧快照。已有安装应先备份、停止 Console 写入，再使用 `scripts/migrate-warp-checkpoints.py` 审计并以 `--apply` 迁移未绑定、未引用的旧默认配置；脚本原子更新存储格式和订阅摘要，保留修订编号及运行引用。携带旧 WG 身份或引用旧隧道的数据会拒绝迁移，必须先显式重新注册并发布。先发布支持 MASQUE 的 Brocade Xray，再发布使用它的配置。

## 外部隧道标识

外部隧道的资源 ID 是不承载业务语义的随机标识：手工隧道使用 `custom-xxxx-xxxx`，WARP 使用 `warp-xxxx-xxxx`，VPN Gate 地区池或固定节点使用 `vpngate-xxxx-xxxx`，其中 `x` 是小写十六进制。地区、节点、租户和展示名称只保存在各自字段中，旧前缀或语义化 ID 不再接受。

## 外部隧道证书验证

TLS 隧道默认验证服务端证书。导入 AnyTLS、VLESS TLS 或 HTTPS 代理时，`insecure=1` / `allowInsecure=true` 会保存为该隧道的 `security.v.allow_insecure`；也可在手动编辑的 TLS 扩展中切换「跳过证书验证（insecure）」。显式开启后，节点配置与 Console 拨测均生成 `tlsSettings.allowInsecure: true`，前置隧道订阅生成 `skip-cert-verify: true`。XHTTP 独立下载的 TLS 设置可以单独开启。缺省、`0` 和 `false` 均保持证书验证。

AnyTLS 链接支持 `peer` 作为 `sni` 的别名、`fingerprint` 作为 `fp` 的别名，并接受 `udp=1` / `udp=true`；AnyTLS 原生承载 UDP over TCP，不额外生成 UDP 开关。别名冲突或布尔值无效时会明确拒绝导入。

本功能需要配套的 Brocade Xray，内置 fork 保留显式 `allowInsecure`，不受上游的日期停用逻辑影响。升级时先发布新版 Xray，再发布开启 insecure 的隧道配置；只更新 Console 不会升级节点上的 Xray。开启 insecure 会跳过服务端证书身份验证；现有证书钉扎与名称约束仍按 Xray 的独立规则生效。

## 隧道目标域名解析

手动隧道的编辑设置支持「目标域名解析」，导入分享链接时也可选择。默认「远端解析（AsIs）」把目标域名原样交给代理服务器；旧隧道缺失此字段时保持这一行为。选择本地策略后，Brocade 节点先解析目标域名，再把 IP 交给隧道。这是出站顶层 `targetStrategy`，不控制 AnyTLS 等隧道服务器自身地址的解析，也不能要求远端优先选择 IPv4。

WireGuard 的 `AsIs` 表示由其自身的域名策略处理目标，不表示远端 DNS；原有 WireGuard 协议内域名策略继续独立配置。

`UseIPv4v6` 先查询 IPv4，解析报错或无结果时再查询 IPv6；已经取得 IPv4 但连接失败时不会回退 IPv6。`UseIPv6v4` 顺序相反。`UseIP` 查询双栈，`UseIPv4` / `UseIPv6` 仅查询相应地址族；这些 `Use` 策略在解析失败时可回退到系统解析，并非强制限制地址族。

修改随隧道一起保存到草稿，经配置发布后在引用它的节点生效；历史修订和回滚保留该选项，Console 隧道拨测使用相同配置。前置隧道的客户端订阅仍使用客户端自身的解析设置，不继承此节点侧选项。

此策略控制发送给隧道的目标 IP，不保证远端最终出口使用同一地址族。远端仍可能根据 HTTP Host、TLS SNI 或自身代理链重新选择目标和出口。Console 公共落点会提前解析、验证并固定公网 IP，拨测显示的出口 IP 是远端响应中的观测值，不能单独据此判断本地解析策略是否执行。

`targetStrategy` 只处理目标域名。客户端已经提供 IP 字面量时不会重新解析或跨地址族转换；例如 `UseIPv4` 不会把一个已经指定的 IPv6 目标改为 IPv4。Console 拨测在固定 IP 之前，单独按该策略选择已验证的公网地址：IPv4 档优先选 A 结果，IPv6 档优先选 AAAA 结果，所选地址族无结果时允许 `Use` 策略回退。IP 字面量保持原地址族；缺省、AsIs 和 UseIP 保持原有默认选择。固定后的 IP 不会再次经过 Xray 的域名解析分支。

## 规则 DNS 组与重试

机器 DNS 规则和线路规则中的「自定义 DNS 解析」可在同一地址框填写逗号分隔的 IP，例如 `1.1.1.1, 8.8.8.8, 2606:4700:4700::1111`。前端每组最多 3 个成员；同组共享端口、UDP/TCP、地址策略与失败处理。保存时规范化 IP 并去重，单地址仍沿用历史字符串格式，多地址保存为数组，无数据库迁移。

「本机 DNS 解析策略」弹层在桌面将服务器、端口、传输、地址策略和失败处理对齐到列，端口由整组地址共用；窄屏按块显示。弹层内可新增策略、调整优先级和删除整条机器策略；已有策略的匹配条件以选择器为键，不在弹层中修改。新建链在弹层中的改动（包括优先级）与链一同加入草稿。

机器详情的「DNS 解析策略」表每行末尾依次是复制、优先级和删除；规则区较窄时这几个按钮排成两行，把宽度留给解析设置。删除已保存的策略后该行变淡并标为「保存后移除」，行尾只保留「撤销」，点「保存到草稿」才写入草稿；尚未保存的新行点删除直接去掉。把解析方式改为「默认 DNS 解析」同样会移除该策略。

新建机器 DNS 策略默认使用 `geosite`。新建和输入过程中不显示校验错误；点击「保存到草稿」失败时，在对应行的 DNS 输入控件右侧以单行提示，继续编辑后清除提示。新建链没有保存失败这一步：DNS 地址未补全时页脚提示并禁用「加入草稿」，「查看」旁标出「需要修正」，弹层中对应行给出原因。

机器 DNS 策略支持逐条复制：副本紧跟原规则，保留匹配条件和全部解析参数，可继续编辑。拖动 D 序号旁的抓手可调整优先级，鼠标和触屏均可使用；聚焦抓手后也可用上下方向键，原有上下移动按钮继续保留。选择「从节点导入」后，来源节点的策略按其原顺序直接追加到当前列表末尾；导入时不检查冲突、不去重、不合并，也不覆盖现有规则。复制、排序和导入均先保留在编辑列表，沿用「保存到草稿 → 提交 → 发布」流程。

有规则 DNS 时，生成的 Xray 配置开启 `enableParallelQuery`：组内成员竞速，多个命中组及机器 DNS 可以提前查询，但结果仍按规则优先级采用。前组有地址时使用前组；前组全部无地址或失败后才采用后组。选择「停止连接」时，整组成员都参与竞速，整组无结果才停止，不查询其后的规则或机器 DNS。

每个规则解析器成员独立拥有最多 4 秒和 5 次发送额度，首发计入上限，同次查询的 A、AAAA 及诊断补查共用该成员额度；组内成员不共享额度。未完成的请求在约 250、750、1500、2500 毫秒处重发，成功或明确的无地址／NXDOMAIN 回答不重试。调用方期限更短时提前结束自己的等待；已开始的共享工作仍受成员独立预算约束，不继承首个等待者的短期限，个人超时不写成 DNS 失败缓存。UDP 包含协议内 EDNS 重发，TCP 包含失败建连尝试，均计入额度；配置 UDP 就只用 UDP，TCP 就只用 TCP，不混合切换协议。该上限作用于首个及后续命中的规则 DNS；机器系统 DNS 保持其原生策略。

正结果按 DNS 应答 TTL 缓存；暂时失败最终缓存 1 秒，失败和无地址结果不作为长期旧缓存继续提供。开启 Xray 旧缓存能力时，刷新失败保留已有可用地址并限制刷新频率。相同解析器的并发同域名／地址族请求可合并等待，取消某个等待者不会中断其他等待者。

先更新支持成员路径证据的 Console／前端和 Agent，再更新相关节点的 Brocade Xray，最后保存并发布组配置。只更新 Console 不会改变线上 Xray 重试行为。单地址历史可直接读取；启用数组配置后的修订不能交给仅支持字符串的旧 Console。需要回退旧 Console 时先恢复单地址配置并发布，再按正常发布流程回退，不修改历史修订。

## 出口拨测

用户页的「授权验证」会使用当前 Serving 中的真实用户授权发起短生命周期拨测；隧道详情页的手动拨测可选择当前 Serving 或点击时的完整草稿，设置页的定时监测则始终只列出并监测 Console 能执行的 Serving 出口。它们都由 Console 机器发起，并强制流量只经过所选外部出口。Serving 任务引用不可变发布快照；草稿任务只把所选出口加密冻结到任务中，并在任务结束时清除密文，不会创建模型修订。公共落点和超时同样在入队时冻结，结果与定时策略持久化到 PostgreSQL；Console 重启或多实例抢占不会重复执行同一任务。草稿结果会进入最近记录，但不参与 Serving 健康、趋势或告警。定时任务采用稳定抖动且不补跑错过的周期，记录保留 7 天。WARP 因身份按节点分配，在 Console 拥有独立身份前不会出现在定时监测列表；VPN Gate 由引用它的节点 Agent 实拨，同样只在自己的观测页展示。

公共落点只支持明文 HTTP。Console 会先解析并拒绝回环、私网、链路本地、文档和其它非公网地址，再把已批准的 IP 固定写入 SOCKS 请求，避免 DNS 重绑定；原始主机名仅保留在 HTTP `Host` 头。Console 会把本次构建内嵌的对应架构 Brocade Xray 校验并原子写入 `BROCADE_CACHE_DIR`，无需再单独安装。`BROCADE_PROBE_XRAY_BIN` 只保留为显式运维覆盖；一旦设置，路径或版本错误会直接报告，不会静默回退。
