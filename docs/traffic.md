# 用量与实时流量

用量记账、实时速率与机器流量统计。按站点的统计见[出流量统计](site-usage.md)。

## 用量账本

用量以日账本和计数器最新基线为准，不依赖逐笔历史重新计费。逐用户明细只保存非零流量或缺口事件，正常零流量窗口不再逐用户落盘；机器曲线改读独立的机器/租户/原始时间点投影，保留真实零点和原有精度，不插补缺失上报。明细接口因此不是完整采样时间线。机器投影与剩余用户/链路明细仍保留 7 天，日账本长期保留。原始累计读数只保留最近 24 小时的排错历史，每分钟最多清理 50,000 行，首次缩短保留期时渐进追赶；正常运行下清理有约一分钟调度延迟，故障或积压时可更长。它不影响最新计数基线、账本和曲线；代价是无法再用超过 24 小时的原始计数快照逐笔复核。幂等回执独立保留 7 天，不随原始读数一起缩短。

用户的额度、订阅和用户详情按各自配置的每月重置日汇总；全局用量页继续按 UTC+8 自然月汇总。更改重置日只改变汇总范围，不重写日账本。具体有效期和恢复规则见[账期与服务有效期](users.md#账期与服务有效期)。

用户的「本期用量归零」只调整当前周期的读数与额度判断，保留历史账本及这里的自然月统计；归零范围、迟报处理与精度见[本期用量归零](users.md#本期用量归零)。

## 配置重启的连续用量

拓扑或授权移除后，Xray 仍可能保留旧标签的累计计数。当前用量代次标为“非本机”的旧标签，只有在同一台机器、同一计数代次且上下行均与最后有效基线完全一致时才会跳过，不重复入账，也不触发拒收告警。这类标签缺少本机基线、计数增长或倒退、代次变化及早于基线的读数仍按异常拒收；跳过不会改写计费基线或历史归属。

Agent v28 与对应受管 Xray 支持跨进程的用户 / 转发累计计数，配置重启不再清空尚未上报的值；splice 每次内核传输后递增。已确认的重启停机区间单独上报为零窗口，未知采集缺失仍断开。近一小时用户图按真实采样时长重采样，不改写计费；队列满或采集落盘失败时保留检查点并暂缓破坏性操作。兼容、存储上限和回滚边界见 [配置重启的连续用量](../.agents/runbooks/console-deployment.md#配置重启的连续用量)。

## 实时速率

实时网卡速率是第三条独立通道：Agent 主动维持到控制面的 WebSocket，无浏览器查看时只保活、不采样；查看机器或机器总览时，控制面下发临时租约并按全局 1/2/5 秒配置采样，最后一个查看者离开 15 秒后停止。控制面只保留每台机器最近 120 秒、最多 600 点的内存环，进程重启即可丢失，不写数据库、不进入离线重放，也不改变诊断和用量的 30 秒口径。浏览器仅通过控制面的 SSE 读取数据，永远不连接 Agent，也不会收到节点地址或节点令牌。

「用量 → 实时」的机器 × 用户速率矩阵允许访客只读访问，沿用站点的访客开关、租户范围与资产脱敏。快照和 SSE 均只返回可见范围内的接入、转发速率及网卡读数，不返回机器诊断；公开读取不开放实时设置、凭据、目的站点／域名／地址明细或下述用户历史明细。矩阵展示用户与机器的名称或标识、关联及当前速率，内部响应保留归属标识以区分身份，不是匿名统计；资产地址沿用掩码。

机器详情和用户详情的「用户实时流量」向已登录的操作者开放，包括只读、编辑、发布者、租户管理员与系统管理员。Agent v29 按同一实时频率读取入口 Xray 的接入用户与转发规则累计计数器，保持 `reset=false`，用本地两次读数计算上下行速率；机器页按用户汇总，用户页汇总该用户当前授权的所有入口机器。带租户范围的操作者仅可读所属租户子树，普通用户与访客不能获取。控制面合并并发观察需求，再按每个请求的权限过滤输出；用户速率只保留最新内存报告，关闭页面后随观察租约停止，不进入计费或历史。旧 Agent 明确显示未支持；断线、采样失败、计数器重置和截断不会冒充正常零流量。转发按规则所属租户、用户和机器归属合计，并保留来源分类；中继、出口不提供最终用户身份。旧 Agent 只有接入统计时明确提示转发实时待升级。用户详情打开时另读近 1 小时的真实计费窗口（`GET /users/{tenant_id}/{user_id}/realtime/history`，权限与实时接口相同），画成合计图和每行走势，之后每 30 秒重读；当前速率只显示为读数，与历史分开呈现。未采集的窗口在图上断开，不画成 0。出现过的行保留到离开页面，实时通道断开时保留最后一次读数并提示；默认按名称排列，选择按下行、上行或近 1 小时用量排序后每 5 秒重排，指针停在列表上时暂停；支持按名称或租户搜索。用户详情的入口机器排成多列紧凑格，每项两行：名称与用量，走势与当前下行、上行。机器详情的布局见下段。

## 机器用量弹层

实时读数栏的「当前经过的接入链」按名称排序，列出全部已出现的接入链与端口转发来源，不再按当前速率取前几项。在本次查看期间保留来源身份，完整报告确认没有流量后显示 0；报告不完整或通道未就绪时不把未知值当作零。保留范围沿用实时报告上限，每个用户最多 2,048 个来源身份，超限时优先保留本次报告的来源；关闭弹层后清除本次查看记录。

机器用量弹层（「用量 → 实时 → 机器」）提供实时流量、流入统计与流出统计。实时读数显示当前速率与接入链；历史柱图与流入、流出统计共用 UTC+8 的当天、当周、当月和自选区间，也可拖选历史图定位尖峰。历史图分别按 5 分钟、15 分钟、小时汇总；自选区间按长度选用 30 秒至小时粒度，每 30 秒刷新。速率为已观测窗口均值，总量仅含保留的机器记账窗口；未采集或已清理时段留空，不用日账本反推走势。当前速率持续实时更新。流入按用户与接入链（含端口转发）展示流向，窄卡切换为排行条形；点击用户打开该用户的流入明细：读数栏写所选时段的合计、上下行、来源 IP 数与接入链数，下方按来源地址排行，同一地址在几条链上只占一行，条形按接入链分段，颜色与流入统计一致；地址旁注明本地 GeoIP 的国家／地区与可识别的中国运营商，可复制地址。「合计／下行／上行」同时切换排序、条形与占比；两条链以上时显示组成条与图例，点图例只看这条链的来源。地址多于 11 个时只列前 10 个，其余可展开。旧数据、观测遗漏和端口转发明确保留为未按来源拆分的合计（「未记录来源」「端口转发 · 不区分来源」），始终列在最后；来源记录不完整、采集缺口与用量账本不一致只在出现时写一行，账本值点开再看。只读账号收到的是脱敏地址，同形的掩码可能是不同来源，明细逐行保留、不提供复制、不写来源 IP 数，掩码唯一时才标注地区。来源数据来自独立有界观测，不改变计费；需要新版 Agent/Xray 及启用在线来源统计，无法追溯补齐采集前的 IP 流量。流出包含站点类别与独立端口转发类别，点类别可看主要用户；目标仍是小时汇总，自选区间显示实际小时覆盖范围。中继、落地没有最终用户身份，来源与目标也没有逐连接关联。接口为 `GET /nodes/{node_id}/traffic-history`、`/inflow-usage`、`/inflow-details`、`/site-usage`、`/other-domains`、`/sniffing-failed-targets`，支持 `period=day|week|month`；自选区间同时提供 `start_unix_secs`、`end_unix_secs`（30 秒边界，最多 31 天），来源明细另需 `tenant_id`、`user_id`，所有接口不缓存。保留期、精度及排查方法见 [尖峰流量排查](../.agents/runbooks/incident-response.md)，已有数据库升级见 [Console 部署手册](../.agents/runbooks/console-deployment.md)。

历史流量图对长于一天的区间按日期标注横轴；若刻度间隔不足一天，则同时显示日期与时分，跨年时补全年份。当天及近一小时等短区间保留时分，悬停提示在跨日区间包含日期，避免当周、当月的零点刻度全部显示为 `00:00`。流出统计的自选区间也按实际跨度和粒度标注 UTC+8 刻度，悬停显示完整时间范围，历史区间终点不标为“现在”。刻度间隔随区间长度调整，不改变采样与汇总粒度。

来源流量支持 IPv4 与 IPv6，IPv4-mapped IPv6 与对应 IPv4 合并记录。旧版 Xray 会漏采带方括号的 IPv6 来源，表现为在线设备可见，但对应流量仍显示为未归属来源；需升级节点 Xray，修复版本接收的新连接才会记录这部分来源流量。已漏采的历史来源无法从用量账本补回。

## 网卡流量统计

机器列表的累计用量沿用机器保存的计量口径；单向入站、单向出站和双向取大显示为「单·XX GiB 本月」，双向合计不加前缀。悬停累计用量可查看具体口径和统计周期。

机器配置中的「流量统计」另行记录默认路由网卡的累计接收与发送字节，并与 Xray 用户/中继用量同时展示。Agent 每 10 秒把逻辑累计值原子写入私有状态文件，进程重启沿用原值；整机重启时保留累计值并接入新 boot 的内核计数。异常断电、网卡替换、计数倒退或状态文件丢失时不会猜测缺少的字节，而是把该边界标为缺口；控制面跨 UTC 日期长时间失联时，绝对累计值仍会补回，但无法精确拆分到可能经过的重置边界，也会标出缺口，供操作者以当前总量校准建立新锚点。月度或年度重置均以 UTC+0 的 00:00 为界；当月不存在所选日期时取月末。重置策略与校准属于运行态账务设置，不进入模型修订，也不触发发布。

## 用量页

用量页保留本月 / 上月切换与每日日期，不在面板标题后重复显示年月；汇总、每日柱形和详情不再展示采集缺口提示。统计仍使用实际收到的数据，后台缺口记录和请求失败提示不受影响。

实时和汇总页签首次读取时保留页头，并分别显示「读取实时用量」「读取月度用量」。首次读取和「实时 / 汇总」切换时，内容就绪后使用与其他页面一致的淡入与轻微上移动效。实时读数刷新、本月 / 上月切换和日期选择保留当前内容，不重复播放入场；系统开启减少动态效果时缩减动效。

实时页签收到首个快照即展示，并自行播放布局入场动画，不等待整支机队都有读数，也不等待机器、用户名册读取完成。已有速率立即显示，尚未采集的机器分别标为连接中或无读数；名册名称随后补齐，名册请求失败在现有布局内报错，不挡住已收到的实时读数。

实时推送不携带授权名单；授权快照尚未取得时，先按已取得的用户、机器名单画出真实矩阵，未确认的格子直接留白，已有速率照常显示，授权人数显示「—」。获取成功后在原表格内更新授权：未授权留白，已授权按实际采样显示空闲、速率或无读数；窄屏在确认授权前也显示可横向滚动的矩阵。请求失败或超时会自动退避重试，不能据此判断没有用户或没有授权。只有授权快照明确返回空名单时才显示授权为空；只有机器的当前读数完整时才判断没有用户流量，连接中、离线和不完整报告均保留对应状态。

实时和汇总页签的读数栏横排时，总量、上下行读数与比例条位于左侧，其他摘要位于右侧；手机窄屏按同样顺序纵向排列。访客与登录用户的流向列表均保持在纸面宽度内。

实时页签的内容区域宽于 900px 时保持左侧读数栏、右侧用户 × 机器矩阵的两栏布局；左栏沿用「月累计流量」边栏的固定宽度、字号和留白，不随桌面内容宽度缩放。矩阵采用固定列宽、方格、字号和间距，不随右栏空间拉伸或压缩：普通列宽 30px、方格 24px、格间距 6px，地区组之间额外留 8px；不超过六台机器时保留固定宽度的横排读数列。空间不足时在右栏内横向滚动。内容区域宽度不超过 900px 时改为上下排列，不超过 680px 且授权已确认时改用按用户的流向列表。

接入额度与超额限速按用户、app 独立设置，同一 app 跨机器共享上下行合计速度；不同 app 不合并额度，转发另行设置。具体行为与升级要求见[App 额度与超额处理](users.md#app-额度与超额处理)。机器自动限速继续约束所有用户、app 与转发的合计流量。

## 机器自动限速

机器配置的「流量统计 → 自动限速」按机器独立保存，默认关闭。可设置最多 8 条规则：本账期累计用量达到额度的指定百分比，或达到指定 GiB/TiB 后，限制为指定 Kbps/Mbps；阈值单位选「%」即按额度百分比。百分比必须大于 0 且不超过 100%，并且需要机器额度；绝对阈值不依赖额度。达到包含等于，多条命中时取最低速度；此前已有更低限速的规则不会生效，界面将其标淡。速度使用十进制比特单位，100 Mbps = 100,000 Kbps。

规则与计量口径、重置、额度、校准在同一张卡片中编辑，共用一个保存。保存时先写计量设置、再写限速策略，因此百分比规则可以与额度一起保存；清空额度并同时撤下百分比规则时顺序相反。其中一步失败时，已保存的部分生效，未保存的部分留在表单中，可修改后重试。额度条在每档阈值处切口，条下标出阈值与速度；越过阈值后的已用部分以斜纹表示，机器确认限速后，起作用的一档与卡片标题的状态以金色标出。未设额度时，只要有绝对用量阈值，额度条按最高阈值绘制。

触发用量沿用机器的计量口径、UTC 月度/年度重置与校准。策略保存后由 Agent 独立同步，不需要发布模型或重启 Xray。正常情况下下一个约 10 秒的本地采样轮次执行阈值判断；跨阈值可能多用一个采样窗口的流量。控制面离线时仍使用耐久策略和本地累计量判断；账期重置自动恢复，调整配额、规则或校准后重新计算。计量基线丢失、计数倒退或缺少重置边界时保留已有上限，并显示等待/错误状态，不把未知用量当作零。

执行层有三种选择：

- **应用层**（Xray）：默认选项。受管 Xray 的 TCP/UDP、代理与动态端口转发业务共用一个聚合预算，上行和下行 payload 共同消耗预算。普通双端转发中，每个 payload 字节在机器接收、发送各经过一次，因此对应收发各约为所设速度；协议头、封装开销、回落流量、系统程序、独立 OpenVPN 和纯内核 WireGuard 转发不在应用层上限内。无需 `tc`、IFB 或网卡管理权限，适合不同 Linux 发行版和受限容器。Xray 限速实现使用 Go 通用文件与 loopback TCP 接口；Brocade Agent 的安装与物理用量采集目前仍面向 Linux，并不因此增加 Windows/macOS Agent 支持。
- **网卡**（系统层）：默认出口网卡接收、发送分别限速，同一方向的所有连接共享上限。例如收发各 100 Mbps，合计可能达到 200 Mbps。需要 Linux HTB、fq、IFB、mirred、iproute2 及网络管理权限；部分 OpenVZ/LXC 不支持时会明确失败。只接管可识别的普通调度队列或自身队列，遇到已有整形、分类或无法确认安全的 QoS 会拒绝覆盖，具体接管边界见下文。HTB 上限通过 Linux rtnetlink 按网卡和类句柄匹配，直接校验内核的 32/64 位精确速率，不依赖 iproute2 的 JSON 层级或文本单位与舍入。读取有 3 秒、1 MiB 和 4,096 个类的上限；截断、转储中断或无权限会明确失败，下一轮重试。旧 Agent 在 Debian 13 / iproute2 6.15 上可能在上限已生效时误报「限速上限回读不一致」，升级 Agent 即可，无需重设策略。此项不改变协议、Xray 或数据库；仍只支持具备 HTB/IFB 等所需内核能力的 Linux。
- **双层**：两层使用相同触发规则并独立执行。即使系统层失败，仍会尝试应用层；界面分别显示结果，任何一层失败都会显示应用失败，不将另一层的成功当作全部成功。

网卡接管按队列结构与行为判断，不把 `1:`、`8001:` 等句柄编号当作自定义限速的证据。支持单层 `fq`、`fq_codel`、`pfifo_fast`、`pfifo`、`bfifo`、`sfq`、`codel`、`pie`、`fq_pie`、`noqueue`，以及子队列全部为这些普通调度器的 `mq`。`mq 0:` 的子队列父句柄兼容 `tc` 输出的 `:1`、`:2` 等省略零主编号的写法，与 `0:1`、`0:2` 等价。旧 Agent 可能把普通 `mq 0:`、`mq 1:` 或 `fq 1:` 误报为自定义 QoS，升级 Agent 后自动重试，无需重设策略。

接管前检查物理网卡和已存在的限速 IFB 的队列、每个可寻址队列的过滤器与已有入站过滤；`fq maxrate` / `defrate`、外部 HTB/TBF/CAKE、分类优先级树、未知队列和读取失败仍拒绝覆盖。空的普通 `ingress` / `clsact` 可以复用；共享入站过滤 block 即使为空也不接管，避免修改其他网卡共用的策略。`clsact` 的普通或共享出站过滤保持原位。队列检查最多接受 4,096 条记录，过滤检查有 3 秒调度预算，单次工具调用仍最多 5 秒，超时后下一轮重试。已经接管后仍在每轮检查分类过滤器；即使 HTB 类的速率正确，存在可绕过整形的外部分类规则时也不会确认成功。入站确认要求 `protocol all`、chain 0、可在软件执行、唯一的 IFB redirect 动作和对应的终止语义，不把仅覆盖 IPv4/IPv6、镜像、跳链或共享 block 中的同名过滤器视为成功。

关闭时先确认资源归属，再清理 Brocade 自有资源，恢复原调度器类型的默认参数；原先为 `mq` / `noqueue` 时交回内核默认队列，不还原原句柄和逐队列调优参数。检查点中的网卡、调度器或速率无效，IFB 被其他配置占用，或存在无法确认归属却仍指向限速 IFB 的过滤器时，会保留现场并明确报错，不删除依赖资源或报告已解除。该路径需要完整支持相关 JSON 输出的 iproute2；缺少工具、内核模块或网络管理权限时明确失败，不通过清空外部 QoS 或改用文本猜测绕过。

这一接管策略沿用 Linux 根队列出站整形、IFB 入站整形的通用路径；[CNI bandwidth](https://www.cni.dev/plugins/current/meta/bandwidth/) 使用 TBF 与 IFB，[wondershaper](https://github.com/magnific0/wondershaper/blob/master/wondershaper) 使用 HTB 与 IFB。Brocade 在已有宿主机上持续收敛，因此保留外部整形与分类策略的冲突检查，不采用清空全部队列再重建的方式。

应用层要求带 `machine-traffic-limit-v1` 能力的受管 Xray，Agent 协议要求 v42。 建议先升级 Console，再升级 Agent 和受管 Xray；新 Agent 连接旧 Console 时保留最后保存的策略，接口不存在不会解除上限。需要回退控制面并取消限速时，应先在新控制面关闭并等待机器确认。旧 Agent 显示待升级；缺少 Xray 能力、本地 API 或内核权限时显示明确错误。已有连接通过动态预算更新响应，Vision splice、AnyTLS kTLS 快速路径同样受限。新旧两代 Xray 在热切换期间使用同一份 Agent loopback 预算，避免并存时上限翻倍。预算服务只监听 loopback，以私有状态文件中的随机凭据认证；凭据不进入接口响应、日志或用户配置。应用层已限速而本地预算服务不可用时，数据传输报错，不放行无限速流量。

热切换时会逐个检查仍存活的受管代际是否支持机器限速，并接入同一预算文件。旧代缺少能力或未接入预算时，应用层暂不确认整机上限；等待旧代排空后自动重试，不为确认限速而主动中断旧连接。新代的局部成功不代表旧连接已经受限。

Agent 在本地持久化最多 400 个 UTC 跨日累计检查点；正常上报只携带尚未确认的边界。新版 Console 按这些检查点拆分离线期间的日账本，重复上报不重复入账。跨午夜的约 10 秒采样窗口计入新一天；关机期间或超出检查点保留范围的缺口仍明确保留。

界面区分保存的策略与机器确认：开关旁显示执行状态和确认时间，双层执行或有一层出错时在执行层下列出各层结果。当前修订的报告在 300 秒内有效，旧修订或过期报告显示等待应用确认；这只是状态确认的有效期，不会使实际限速到期解除。正常交接、旧代排空及 Xray 尚未读取新上限显示等待应用确认，真正的执行或校验失败仍显示应用失败；双层执行时任一层真正失败优先于另一层的等待，不把局部成功当作整机已确认。关闭后清理 Brocade 自有系统限速资源，应用层预算恢复不限速；不会删除其他程序接管的 QoS。

限速同步与本地执行使用独立工作线程。实时通道连通时，已确认状态每约 60 秒上报一次；缺少当前修订的确认、仍在等待或执行异常时临时每约 3 秒复查，确认后恢复 60 秒心跳。没有实时通道时正常每约 15 秒轮询，待确认时同样加快复查。本地执行仍约每 10 秒一轮，不因上报频率变化而解除或重设策略。系统工具缺失、权限不足或执行失败只影响限速结果，不阻止配置发布、授权收敛和其他报告；单条系统命令最多等待 5 秒，失败后下一轮重试。执行可能部分成功，关闭失败时旧上限也可能保留，须以机器确认结果为准。本地执行状态超过 45 秒未更新时停止重复上报，避免网络同步正常掩盖执行线程停滞。

应用层预算初始化失败不再中止 Agent 或 Xray 启动，本地限速线程会重试。明确没有生效上限时，预算不可用不阻止未限速业务；已有上限或无法确认历史状态时仍保留故障保护，相关业务可能等待后报错。低速 UDP 保留完整报文，分段等待共享预算；正常限速等待不计为预算服务故障，等待支持连接取消。

本地策略缓存损坏后，可由控制面重新下发有效策略修复，包括明确关闭；无效、截断或旧修订的响应不会替换最后有效策略。应用层控制文件丢失或损坏时，会从仍有效的内存预算恢复；重启后须先用有效策略与计量重新计算，才能重建未知的应用层状态。系统层所有权检查点损坏会显示错误并拒绝猜测资源归属，但不阻止应用层独立更新或关闭。自有 HTB 默认分类漂移会自动重建，其他程序的 QoS 和过滤器仍受保护。

限速检查点仅接受有大小上限的普通文件，不跟随文件本身的符号链接。异常 FIFO 等特殊文件不会卡住 Agent 或 Xray 的限速读取；修复时原子替换检查点路径，不改写符号链接指向的文件。

系统层的入站整形发生在数据已到达机器之后，不能保证这些字节不被服务商计费。限速控制消耗速度，不是服务商配额的精确硬封顶。

系统层同样限制经该网卡传输的 SSH 和 Console 连接；极低上限可能使远程操作、策略同步和上报变慢或超时。需要保留这些连接的正常速度时，可选择应用层。

### 升级与迁移

本功能结构合并在开发中的 `0002_forwarding_rule_results.sql`，保留原有转发结果迁移，并新增 `node_traffic_limit` 与策略审计表；不修改 `0001_init.sql`。新安装执行 0001、0002，已有 0001 库执行 0002。若某个数据库已经应用过更早内容的开发版 0002，SQLx 会拒绝变更后的校验值；不得修改迁移回执绕过，应使用未应用该开发版的数据库或为已发布环境另行安排前向迁移。一经发布，0002 内容冻结。

流入统计及用户来源明细按全局 chain ID 识别接入链。迁移分组后，同一条链的历史与新流量仍合为一个来源，名称和地区取当前链，已删除的链保留历史编号；分组 ID 保留为原始计费归属，不因展示合并而改写。来源观测与账本也按同一链合并比对，分组迁移本身不触发账本不一致提示，真实超额观测仍保留提示。
