# 机器 IP 养护

机器列表的每张卡在国旗右下角显示无底色的养护角标，自动养护开启时高亮，其余状态弱化。悬停可查看「开启」「关闭」「未设置」或「状态未知」说明，辅助技术也可读取；旧控制面未提供该字段时保留未知。图标表示已保存的自动养护策略，不表示当前有轮次正在运行。

IP 养护位于机器详情「配置」页右栏、证书组上方。卡片保留自动养护与状态两行：「关闭 / 开启」分段开关下显示目标地区和频率，行尾「策略 ›」打开居中的策略弹层；状态行先放「立即执行」或「停止」，再显示状态，行尾「记录 ›」打开记录弹层。卡内不展示定位与 x/3 读数；今日用量、24 小时图表、执行记录及记录中的地区旗帜保留在记录弹层。访客和只读操作者可以查看可见机器的信息，地址沿用现有脱敏规则；保存、执行、停止和重置会话仅限系统管理员。它独立于线路草稿、修订发布和 Xray 重启；base 与 cvm 均提供这项宿主机能力。自动开关即时保存，其他参数由策略弹层页脚统一保存。

默认关闭自动养护，执行频率为每 45 分钟一轮；已保存策略沿用原频率。 首次配置依据机器旗帜（手动地区修正优先，其次公网 IP 的 GeoIP/同址观测）生成地区草稿，优先 IPv4、仅有 IPv6 时使用 IPv6。机器名称匹配同国城市，只有一个城市模板时直接选取；无法确定城市、未知地区或没有对应模板时要求选择，不预设日本。首次执行前显式保存该策略；已经保存的目标不随旗帜或 IP 变化自动改写。首次手动执行会先保存关闭自动养护的默认参数；首次支持的 Agent 协议为 **68**。当前版本以前的 Agent 显示需要升级，仍可预存关闭状态的策略。养护结构与用户 Clash 规则合入当前未发布的 `0007_user_clash_rules.sql`，新安装执行完整迁移链，既有 0006 数据库执行 0007；0001–0006 不改写。使用过旧预发布 0007 字节的数据库会被 checksum 校验拒绝，不能直接替换迁移回执或把它视作 0006 基线。 精确 Clash-only 0007 的受控转换见[Console 部署手册](../.agents/runbooks/console-deployment.md#ip-养护与旧预发布-clash-only-0007)，须先恢复演练，再由安装器完成停写备份和原子转换。

## 操作与反馈

- **保存并应用**：以策略版本做并发校验；保存成功和节点实际应用分别显示。修改参数会中断使用旧策略的轮次。
- **立即执行一轮**：创建带 `request_id` 的幂等意图，有效期 120 秒。每个地址族同时只运行一轮，双栈模式并发启动两族；手动执行保持自动开关原值。
- **停止本轮**：提交当前 `round_id` 和控制序号，取消该轮的在途 HTTP 和停留；不匹配该地址族最近回执轮次的停止返回冲突，不能覆盖当前待确认的停止。同一请求重试保持幂等。页面等待匹配回执，离线时不能视作已经停止。
- **暂停自动**：关闭后续调度，取消当前轮次与未消费的手动请求。自动本来关闭且只有待执行手动请求时，显示「撤销待执行」。
- **重置本机养护会话**：Agent 协议 69 起支持完整重置。空闲时经确认，保留已保存的地区、频率、限额和行为参数并关闭自动养护，清空该机的养护记录、检测结果、Cookie、冷却和养护请求/流量计数，回到尚未执行状态。旧会话的离线回执不会重新生成已清空的记录；控制代次和审计事件继续保留。重置请求发出后显示「正在重置会话」，持续到节点确认；记录缓存按会话隔离，其他窗口已打开的旧轮次详情随会话更新关闭。
- 重置后重新开启自动养护，开关立即反馈保存状态；节点确认后显示下一轮时间，无需等首轮产生记录才显示已开启。
- **执行记录**：打开时才分页读取，每页 20 轮，每台机器的两个地址族合计保留最近 100 轮，点击轮次读取动作和地区证据。运行快照不夹带历史列表。
- **Google 定位**：按 IPv4 / IPv6 独立保留最近一次完整取证与原检测时间；地区站点轮次、等待和下一轮执行不会清空上次证据。新的完整未知结果会替换旧结果；策略版本改变或重置后不复用旧证据。只读视图从同机、同地址族、同策略与会话的保留记录恢复证据，不修改单轮历史。记录中的旗帜与轮次详情分别展示 Google 搜索、YouTube Premium、YouTube Music 的地区，未知结果保持未知。
  Google 搜索通过同一出口访问 HTTPS 首页，读取页脚明确给出的国家或地区。检测使用无历史 Cookie 的独立会话，只指定英文界面以解析名称，不传 `gl`、`uule` 等指定地区参数，也不以 Gemini、YouTube 或机器旗帜推断搜索地区。页面不提供可识别国家、返回限制页或检测出错时保留未知；IPv4 和 IPv6 独立取证。线上回执沿用兼容字段 `google_jump`，不改写历史记录。
- **24 小时**：按小时显示 Google、地区站点与中断动作，并标出冷却；页面按游标读取该范围的保留记录，最多 100 轮，读取失败会明确显示错误。正在执行的轮次只计一次。

地址族可选 **IPv4**、**IPv6**、**IPv4 + IPv6**。双栈需要 Agent 协议 **70**：两个出口并发执行，各自保留轮次、重试、冷却和地区证据，一族失败不取消另一族；两族共用整机的每日请求和流量额度。策略可分别指定 IPv4、IPv6 来源地址和预期出口，不会在某族不可用时退回另一族。卡片合并显示整体状态，不拆成 IPv4/IPv6 两行，也不另设出口切换；有任一族执行时显示正在养护，全部空闲才显示空闲，回执未知和异常会保留提示。历史记录仍标注地址族并保留各自地区证据。「停止本轮」依次停止点击时正在运行的两族轮次，等待前一族确认后再提交另一族，最多等待 90 秒；等待期间策略或会话改变时中止后续提交，不会停止之后自动开始的新轮次；关闭自动养护和重置会话影响两族，重置必须等两族均空闲。既有单栈策略不自动变更。

后台执行不依赖浏览器页面。Agent 独立拉取期望、执行和补报；复用现有 Desired 唤醒与观测 SSE。中间状态合并、终态持久补报，长停留期间仍每 30 秒刷新执行器健康。页面同时考虑 Agent 在线、服务器收到回执的时间和执行器健康时间；超过 90 秒的执行器信息显示待确认。模型快照读取失败也保留养护操作。

机器隔离或停用后不允许新手动执行，Agent 接口遵循现有生命周期鉴权。管理视图保留已保存的自动意图，可以继续保存关闭策略；页面显示「执行状态待确认」，机器状态不能替代停止回执，断连继续模式下后台仍可能执行。

## 参数与行为基线

嵌入数据固定于 IP-Sentinel **4.3.5**、提交 `0d477e5f9939f037d0481f4e9a1f26f05810c545`，包含 67 城市、31 国家或地区、4000 个 UA。保留地区语言、坐标、关键词、站点、IP 稳定设备组与分模块 Cookie 会话。

| 参数     | 默认值                           | 可调整范围或含义                                                                      |
| -------- | -------------------------------- | ------------------------------------------------------------------------------------- |
| 目标     | 按机器地区，优先 IPv4            | 国家、城市、IPv4 / IPv6 / 双栈、分别绑定来源与预期公网出口                            |
| 模块     | Google / 地区站点 70% / 30%      | 单独启停模块，Google 比例 0–100%，每轮选一个模块                                      |
| 周期     | 45 分钟                          | 5–1440 分钟；定时错峰 0–180 秒及轮次错峰 0–179 秒                                     |
| Google   | 5–8 动作，停留 45–75 秒          | 搜索、新闻、地图、平台生态；数量及平台动作权重可调                                    |
| 地区站点 | 3–6 动作                         | 停留四档：45% 8–20 秒、35% 20–60 秒、15% 60–180 秒、5% 180–479 秒                     |
| 会话     | 14 天未使用清理                  | 1–30 天，Referer 默认 70%，最大 16 个 Cookie 文件                                     |
| 请求     | 默认 15 秒                       | 3–60 秒，全跳转链共用期限，最多 50 次跳转                                             |
| 每机预算 | 1500 请求、128 MiB 流量 / UTC 日 | 按下载响应正文计量，包含出口与取证探针、跳转及压缩正文；共享 NAT 的机器不自动共用预算 |
| 冷却     | 60 分钟                          | 1–1440 分钟，429 同时支持两种 Retry-After，取较长时间                                 |
| 断连     | 失联 120 秒暂停                  | 高级设置可选择继续最后策略；这会影响离线停止和回退能力                                |

执行只使用 Rust reqwest / rustls 请求，不启动 shell 或浏览器，不模拟 JavaScript、渲染、硬件或浏览器 TLS 指纹。HTTP 成功、轮次完成和地区证据分别呈现；无法解析的证据保持未知，不承诺 IP 定位一定改变。

YouTube Premium / Music 检测复用解锁检测的浏览器请求头、匿名同意偏好与地区解析，使用独立会话和当前地址族，不按目标地区填写结果。Google 和 YouTube 的同意偏好仅按已知目标主机设置，并保留养护会话的其他匿名 Cookie；跳转到其他站点不转发该偏好。

实际内容访问不只看 HTTP 200：同意页、验证页、未解析的新闻跳转页和空正文会记录明确原因并跳过，之后继续后续动作；同意页和空正文最多尝试三次，验证页和新闻跳转页不重复下载。需要 JavaScript 的提示页按正常 HTTP 成功访问处理，不运行脚本；缺少地区信息时仍保留未知。地区站点优先把 Google RSS 文章跳转链接替换为同一地区目录已提供的直接静态站点，不运行自建 RSS 解码器。Android 204 与 Apple Success 仅是既有连通性探针，按各自预期响应验收；429 冷却、每日额度和单轮上限继续生效。

## 执行边界与恢复

- 仅维护宿主机自身出口。来源必须能在宿主网络上下文绑定；NAT 公网地址填预期出口。当前不进入 Guest，不使用已分配给容器的整 IP，也不切换 WARP、VPN Gate 或其他代理。
- 每一跳都校验并固定同地址族的公网解析结果，拒绝私网、带凭据 URL 和环境代理。控制面 token 与养护 Cookie 使用独立客户端。
- 每响应最多 16 MiB，解压同样受限；每轮最多 32 MiB、20 动作、60 分钟。请求发出前先持久扣量，超额下载仍记录，时钟回拨不补额度。
- `last_started_at`、`next_scheduled_at`、`cooldown_until` 分开持久化。修改周期、关闭再开启或重启不会缩短冷却。重启不补发未知动作。
- 状态位于 Agent 状态目录的 `ip-maintenance-v2/`，目录 0700、敏感文件 0600，并持有独占文件锁。不会自动接管旧实验实现的 `ip-maintenance/` 或改写其数据。
- 执行器出现可恢复错误或 panic 时按上限 30 秒退避恢复。「执行器恢复中」只用于真实工作循环故障；Agent 升级或正常退出导致策略通道关闭时，活动轮次按中断处理，空闲执行器正常退出，不报告执行失败。恢复后的执行器发布实际等待或运行状态，不持续保留恢复提示；失败记录、每日计数和下一轮时间继续保留。缓存数据损坏可回退验证过的种子；预算检查点损坏会阻止养护并持续报错，不能删除检查点来自动获得新预算。
- 本地终态补报上限 64 条并受 1 MiB 检查点上限约束；缓冲或持久化不可用时暂停新请求。SIGTERM 与自更新退出均取消当前轮并保存边界，再交还主进程。

## 数据更新与保留

Console 有跨进程刷新租约。已配置、生命周期有效的机器会参与地区数据刷新；每次先冻结一个上游提交，然后从该提交下载 UA、关键词和地区站点。所有内容验证成功后在单个事务中发布；任意失败保留上次有效数据。Agent 验证摘要后落盘，执行中的轮次固定自身快照。

Console 只消费上游发布的数据，不执行其脚本，也不运行自建 Trends / RSS / UA 生成器。刷新采用 UTC 03:00 日界线，失败 15 分钟后再尝试。运行记录按机器保留最多 100 轮，默认 30 天；写入新轮次时裁剪，现有后台 retention 同时执行数量上限和 TTL，覆盖长期离线的机器。策略、控制幂等记录和审计不作为临时回执一起清除。

## API

管理读取遵循机器可见范围，已开放的无状态访客入口可以读取脱敏养护信息；管理写入仍要求系统管理员。Agent 请求使用本节点 token 和协议门槛。小策略和回执允许通过现有受限 RPC；数据包走鉴权 HTTP，不增加旧 Agent 不认识的 WakeDomain。

```text
GET / PUT  /nodes/{id}/ip-maintenance
POST       /nodes/{id}/ip-maintenance/run
POST       /nodes/{id}/ip-maintenance/stop
POST       /nodes/{id}/ip-maintenance/session-reset
GET        /nodes/{id}/ip-maintenance/runs?cursor=…
GET        /nodes/{id}/ip-maintenance/runs/{round_id}
GET        /ip-maintenance/regions
GET        /agent/v1/ip-maintenance/desired
GET        /agent/v1/ip-maintenance/data
POST       /agent/v1/ip-maintenance/report
```

控制请求包含 `expected_generation` 与调用方生成并在重试时复用的 `request_id`；停止另含 `round_id`。不同操作或参数不能复用同一个请求标识。策略保存和控制均返回 204 表示受理；实际确认以 `applied_control_sequence`、`applied_stop_sequence`、`applied_session_generation` 为准。回执含策略代次与轮次使用的代次，旧代次、旧控制或较小回执序号不能覆盖更新状态。

策略连接超过 120 秒没有成功刷新且未允许离线继续时，Agent 暂停养护并上报 `policy_lease_expired`。连接恢复后，协议 69 起立即恢复正确的等待/关闭状态，保留真实的中断历史，不重放已消费的手动请求。

### 请求跳过与执行记录

单页正文（含 gzip 解压后）上限为 16 MiB，超过后记录“页面过大，已跳过”并继续后续动作，不重复下载该超大页面。站点没有所选地址族的解析结果时，记录“无 IPv4/IPv6 解析，已跳过”，不重试、不回退另一地址族，也不计入 HTTP 请求额度；全部动作都被跳过时正常结束轮次。解析到非公网地址仍然拒绝访问，不能以跳过规则绕过地址校验。

普通连接、超时或 HTTP 错误每个请求失败后再重试 2 次（含首次共 3 次），覆盖出口检测、养护动作与地区取证；两次重试分别等待 1 秒、2 秒。动作请求最终失败后跳过；重试的请求与下载量照常计入预算。界面不评价轮次成功、部分成功或失败，只显示当前执行进度、空闲或下一轮时间；记录保留用时、HTTP 状态、跳过原因和请求明细。冷却、额度、出口不可用、离线和回执待确认等仍影响执行的状态继续显示。

遇到 429 限流时显示“限流暂停”；记录列表用它替换动作数量，不另占一行。

每日请求/流量预算、32 MiB 单轮下载预算、单轮时限、出口与来源校验、手动停止、策略失联保护继续生效；429 进入既有冷却，普通验证页跳过后继续后续动作。

### 双栈升级与回退

先更新 Console，再将 Agent 升级到协议 70；旧 Agent 继续单栈执行，双栈选项保持不可用，旧协议不会收到不认识的 `dual` 枚举。新增字段保存在既有 JSONB 中，无数据库迁移。启用双栈后不能直接回退到不认识该策略的旧 Console；应保留支持双栈的 Console，先关闭养护或切回单栈并等待两族停止、节点确认后，再回退 Agent。
