# 前端设计与实现标准

本标准适用于 `frontend/` 的视觉设计、交互、React/TypeScript 实现和相邻测试。现有实现是标准的事实基础：设计令牌位于 `frontend/src/styles.css`，共享组件位于 `frontend/src/ui/`，行为契约位于 `frontend/tests/`。

## 设计原则

- 界面首先表达层级、状态与操作关系，不用装饰替代信息结构。
- 同一种语义只使用一个视觉语言：操作色、数据色、状态色和分段装饰色不得互相借用。
- 桌面工作区、触屏文档流和拓扑画布可以采用不同布局机制，但导航、主题、反馈和组件语义必须连续。
- 高信息密度不能以可读性、键盘操作或触屏命中区域为代价。
- 新页面先组合现有结构和组件；只有现有抽象无法表达稳定的复用模式时才新增原语。

## 颜色与表面

颜色必须通过语义令牌表达，不在业务组件中发明局部色板。

- 表面层级：`--sunk`、`--ground`、`--surface`、`--sheet`、`--block`、`--band`。
- 文字层级：`--ink`、`--ink-2`、`--ink-3`、`--ink-4`。
- 交互角色：`--action-*` 用于导航、链接、焦点、主按钮和选择状态。
- 数据角色：`--data-*` 与 `--observe-*` 只用于图表和连续数据。
- 状态角色：`--ok`、`--gold`、`--err` 只表达成功、注意/变更和错误。
- 边框与装饰：`--line` 用于界面边界，`--grid-line` 只用于背景网格。

原始颜色值只应出现在令牌定义、无法解析 CSS 变量的绘图库适配层，或有明确注释的算法性色板中。暗色和亮色主题必须保持相同的层级方向与语义，不允许同一令牌在两种主题中表达相反的凸凹关系。

## 字体、尺寸与密度

- 正文和控件使用 `--sans`；数值、标识符、代码和诊断信息使用 `--mono`。
- `--serif` 是稀缺的品牌信号，当前只用于站点名，不扩散到页面标题。
- 卡片和控件圆角分别复用 `--r-card` 与 `--r-ctl`。
- 相同层级的标题、图标、按钮和状态标签应复用既有类，不通过页面级覆盖制造视觉例外。
- 中文回退字体可能改变行盒；需要严格对齐的紧凑标题应显式定义行高。
- 在移动端优先重排、换行或转为卡片，不依靠缩小字号塞入桌面布局。

## 组件与状态

- 先检查 `frontend/src/ui/` 和 `frontend/src/styles.css`；按钮、状态标签、空状态、对话框、复制、加载、图标、图表和向导不得在页面中重复实现。
- 服务端数据由既有 API/查询层管理；草稿数据走 `draft` / `forge` 流程。组件内不得建立第二份权威状态。
- 状态机值与用户文案分别保留。统一映射放在共享组件中，不能在不同页面各维护一份翻译。
- 页面必须覆盖加载、空、错误、成功和权限受限状态；错误不得静默转换成空数据。
- 路由首次加载遵循完整表面一次揭示策略：模块和必要数据就绪后再挂载完整页面。生产界面不展示可能被误认成真实数据的骨架；后续刷新保持既有表面并提供局部反馈。

## 交互规范

- 所有可操作元素必须支持键盘访问、可见焦点和准确的语义标签。
- 使用原生 `button`、`a`、表单控件和语义结构；只有原生语义不足时才补 ARIA。
- 图标按钮必须有可访问名称；纯装饰图标对辅助技术隐藏。
- 破坏性操作必须清楚说明对象和后果，并在真正改变状态前确认。确认不能掩盖缺少权限或前置条件。
- 异步操作开始后防止重复提交；完成、失败和可重试状态必须可见。
- 弹层和对话框必须管理焦点进入、关闭、Escape 和背景交互，复用 `ui/dialog.tsx`。
- 触屏命中区域、滚动容器和安全区必须在真实窄视口下验证；不要用固定全屏遮罩修复浏览器工具栏问题。

## 动效与数据可视化

- 动效用于解释状态变化和空间关系，不用于持续吸引注意。
- 统一使用现有 motion 工具，并遵守 `prefers-reduced-motion`。
- 图表颜色来自数据色板，不用红、金、绿装饰普通序列，以免与状态语义冲突。
- 图例、悬浮提示、坐标和摘要必须使用同一单位、范围与缺失值定义。
- “没有数据”“没有发出探测”和“探测失败”是不同状态，不得都显示为零。
- ECharts 折线与面积使用共享 `observe-series` 生成时间序列：显式空值和缺失的采样时段都要断开，不能只设置 `connectNulls: false` 后直接连接稀疏时间戳。有采样窗口时以窗口边界判断；只有时间点时按观测间隔识别明显断档，不把缺失时段算作探测丢包。

## 响应式与浏览器外观

- 普通触屏页面使用原生文档滚动；桌面和拓扑画布可以使用内部工作区滚动。
- 路由切换保存并恢复实际滚动主体的位置。
- `theme-color`、`color-scheme`、页面底色和调色盘必须同步，但不能假设浏览器一定采用指定的状态栏透明度或模糊。
- 背景网格属于装饰层，不能影响面板透明度、边框或图表刻度。
- 半透明材质（`--float` 一组）只用于菜单、弹出层、对话框、浮动窗口。亮色对话框底色（`--float-sheet`）取 96%：背后是压暗的页面，64% 会把白底染成中灰，输入框与按钮反而比弹窗亮。纸与面板不加 `backdrop-filter`：它们在切页时播放入场动画，每帧都要重算模糊，实测掉到 34–42fps；容器带模糊还会成为 backdrop root，使容器内吸顶页头、菜单的模糊失效。顶栏随内容滚走并保持实色。

## 实现规则

- TypeScript 保持 strict；未知边界用 `unknown` 并收窄，不使用 `any` 绕过模型。
- 使用函数组件和 Hooks；渲染保持纯函数，副作用具有完整依赖和清理逻辑。
- API 类型或交互语义改变时补行为测试，不用快照代替关键断言。
- 格式遵循 Prettier：单引号、分号、2 空格、120 列；ESLint 例外集中管理。

## 验证选择

- 纯 CSS/布局契约：相邻 `.test.mjs`，并运行对应 Node 测试。
- React 交互与可访问性：相邻 `.test.tsx`，使用 Vitest/Testing Library。
- 路由、滚动与导航连续性：运行 route checks 和相关导航测试。
- 主题与浏览器外观：运行 `npm run test:browser-appearance`；涉及 Safari 工具栏时仍需真机验收。
- 公共组件或全局令牌变化：至少运行 `npm run lint:strict`、`npm test`、`npm run build`。

具体命令和扩展验证见 `testing.md`。

## 评审清单

- 是否复用了正确的令牌和共享组件？
- 状态、层级和主次是否仅靠语义角色表达？
- 键盘、焦点、标签、触屏和缩减动效是否完整？
- 加载、空、错误、成功和缺失数据是否被区分？
- 明暗主题、窄视口和长中文文案是否都成立？
- 新行为是否有相邻的行为测试，而不是只靠人工截图？
