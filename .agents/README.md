# Brocade 工程知识库

`.agents/` 保存项目级工程约定、设计标准、运行手册、决策记录、执行计划和可复用 Agent 工作流。内容同时服务人类贡献者与编码 Agent；除工具入口外，不维护只对某一种模型有意义的平行文档。

## 目录职责

| 路径 | 职责 |
| --- | --- |
| `AGENTS.md` | 始终生效的项目边界、编码约定、验证与交付要求 |
| `architecture/` | 稳定的系统结构、数据流和跨层边界 |
| `standards/` | 按领域组织的设计、代码和测试标准 |
| `runbooks/` | 部署、发布、回滚和事故响应等可执行手册 |
| `adr/` | 已采纳的长期架构决策及其背景与后果 |
| `plans/` | 有状态、跨层或需要交接的实施计划 |
| `skills/` | 可重复的 Agent 工作流；每项由 `SKILL.md` 定义 |

根目录 `AGENTS.md` 是指向这里的发现入口；`.codex/skills` 是指向 `skills/` 的 Codex 兼容入口。正文只在 `.agents/` 维护。

## 维护规则

- 一个事实只保留一个权威来源。Skill 应引用标准或 Runbook，不复制其中的命令和不变量。
- Runbook 的命令必须可复制执行，并明确前置条件、成功判据、回滚边界和会改变外部状态的步骤。
- 文档不得包含真实凭据、生产地址、私钥、访问令牌或可识别用户的数据；示例使用明显的占位值。
- 行为、协议、配置、数据库或部署方式变化时，在同一改动中更新相关标准或 Runbook。
- 长期决策写 ADR；尚未完成的工作写 Plan。不要把临时讨论写成永久规则。
- 新增 Skill 前先确认它描述的是可重复工作流，而不是普通项目知识或一次性任务。

## 文档状态

本文档集从现有 `AGENTS.md`、`README.md`、CI 配置和前端实现提炼而来。发生冲突时，代码和 CI 只能说明“现在怎样”，不能自动覆盖明确写下的产品不变量；应先查明差异，再同步修改实现与文档。
